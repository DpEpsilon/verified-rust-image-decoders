## 0. Shared definitions

- `fmt_part(r)`, for a `try_*` result `r` that is not `OutOfMemory`, is the frozen-typed result: `Ok(v) ↦ Ok(v)`, `Err(Format(e)) ↦ Err(e)`. For the DIB policy pair, it applies to `r.0`.
- `Eq_f(x, r)` is entry point `f`'s result relation: the frozen executable-to-model predicate applied to `fmt_part(r)`, as tabulated in `SPEC.md` §2 ("Result relations"). Per core: DIB `decode_mp_eq`; DIB policy `decode_policy_mp_eq ∧ decode_policy_alpha_eq ∧ r.1 == recovered_policy`; TGA `decode_eq`; ICNS `parses_to`, `rle_result_eq`, `rgb_decoded_eq`, `mask_decoded_eq`, `combine_decoded_eq`; ICO `parse_eq`, `md_eq`. No clause in this document equates an executable result with a model value directly; executables return `Vec`/`Decoded`, models return `Seq`/tuples, and ICNS's parse model has its own error enum `MpError`.
- `L` is the final `view()` of the sealed `alloc_guard::AllocLog` that the `*_logged` entry point creates with `new_log()` and returns (`SPEC.md` §2). Each element is `(site, k, ok)`. `req(L)` is `L` with `ok` dropped. Only guard functions append to the log, one element per call, with `ok == (r is Ok)` for that call's result; ICO's `import_dib` (`SPEC.md` §3.1) is the one guard function that appends a whole imported DIB log. Code outside `alloc_guard` can neither construct an `OutOfMemory` nor edit the log. In every clause below, `o.site()` and `o.elements()` in spec position resolve to the closed same-`impl` counterparts `site_spec`/`elements_spec` (`SPEC.md` §1), whose bodies are visible only inside `alloc_guard`; a proof outside the guard reasons about them only through the guard's `ensures`.
- `G(f, Eq_f, Req)` holds for input `x`, result `r` and log `L` when all of the following hold:
  1. `r is Ok ∨ r is Err(Format(_))` ⇒ `Eq_f(x, r) ∧ req(L) == Req(x) ∧ ∀j: L[j].ok`.
  2. `r == Err(OutOfMemory(o))` ⇒ `L.len() ≥ 1 ∧ req(L).is_prefix_of(Req(x)) ∧ (∀j < L.len()−1: L[j].ok) ∧ ¬L.last().ok ∧ (L.last().site, L.last().k) == (o.site(), o.elements())`.
  3. Every `(s, k)` in `Req(x)` has `k` within the per-site maximum (`SPEC.md` §4), proved from checked values **before** the guard call.
- `log_tied(r, L)` is the log-only part of clauses 1–2 (drop `Eq_f` and `Req`). DIB exports it as `dib::dib::log_tied` for ICO's `import_dib`.
- `Prog(f, Eq_f, Req)`, the conditional progress theorem: `(∀j: L[j].ok) ⇒ r is not OutOfMemory ∧ Eq_f(x, r) ∧ req(L) == Req(x)`. It follows from `G` clauses 1–2; each core proves it by name so that a mutation weakening either clause leaves a failing target.
- `PreAlloc(x) ⇔ Req(x) == []`, with `Reach` its negation defined by code reachability (`SPEC.md` §2). Named corollary: `PreAlloc(x) ⇒ r is not OutOfMemory ∧ Eq_f(x, r) ∧ L == []`. Errors detected before the first reservation are never `OutOfMemory`; for ICNS `try_parse` that excludes the in-loop entry-header errors (A-ICNS-1).
- The public `try_*` function is the `*_logged` function with the log discarded. Its `ensures` carries `r is not OutOfMemory ⇒ Eq_f(x, r)`, and `r == Err(OutOfMemory(o)) ⇒ (o.site(), o.elements()) ∈ Req(x)`.
- **No wrapper inheritance.** A main crate has no frozen-named function, so each retired theorem is replaced by the `try_*` theorem alone: `Eq_f` on `fmt_part(r)` is exactly the frozen predicate the retired theorem stated (`decode_mp_eq` for DIB `decode`, `decode_eq` for TGA, `parses_to` for ICNS `parse`, `md_eq` for ICO `decode_entry`, and so on). The optional `<core>_abort_shim` crates carry an informal argument of the same shape (`SPEC.md` §1.3); it is documentation of an unverified crate and appears in no main crate's proof report.
- **Mutation kills depend on `Eq_f`.** Every verifier kill in §6 that cites clause 1, `Prog` or the `PreAlloc` corollary assumes `Eq_f` is the full frozen predicate. If a conjunct is weakened, those kill claims are void until the mutations are re-run.

## 5. Runtime checks (falsification gates for A-STD and the guard binding)

These tests are regression checks of A-STD-1/2/3 and of the guard body's `Err` binding on the pinned toolchain and allocator (`SPEC.md` §3). They do not prove anything. They run per core over every frozen vector and the corpus, in a test binary whose `#[global_allocator]` wraps `System` and records events within one `try_*` call.

- **Logical versus physical trace.** Let `L⁺` be `L` restricted to entries with `k ≥ 1`. The recorded `alloc`/`alloc_zeroed` events must correspond one-to-one and in order with `L⁺`. For each pair, the event's `Layout` has `align == align_of::<T_site>()` and `size ≥ k·size_of::<T_site>()`. Equality is expected on the pinned std and recorded per run; a larger size is allowed rounding; a smaller size fails. After a successful reservation, `capacity() ≥ k` (A-STD-1). There must be **no `realloc`** events (A-STD-2). Entries with `k == 0` must produce no event. Inputs with `PreAlloc` must produce no event.
- **Fault injection by nonzero reservation.** For each `j` in `1..=|L⁺|`, the allocator returns null on the `j`-th `alloc` event of the call. The result must be `Err(OutOfMemory)` with `(site, elements)` equal to `L⁺[j]`, the process must survive, and live bytes must return to the pre-call value after the result is dropped (no leak). A second mode fails every request of at least T bytes, for T ∈ {1, 4096, 65,536, 64 MiB}. An `Err` from the guard with no corresponding null-returning event fails the test, since under the size precondition it would mean capacity overflow (A-STD-3) or a guard that fabricates `Err`.
- **ICO through DIB.** Fault injection on the DIB reservation inside `try_decode_entry` must return ICO `OutOfMemory` with site `Dib(Output)` and DIB's element count, and the returned ICO log (in a test build that exposes `try_decode_entry_logged`) must end with that failed entry.
- **ICNS peak live bytes.** The counting allocator records the maximum live bytes per `try_combine` call and checks it against `SPEC.md` §4's three phases, including a mismatched-sides input (16×16 colour, 128×128 mask: 17,152 bytes before `TypeMismatch`).
- **Expected sizes per target.** The `size_of::<Entry>()` values used in these checks come from the per-target layout declaration (gate F2, through `lemma_entry_layout` and its exec counterpart), not from constants in the test. On x86_64 the gate measured 28 B (ICNS) and 44 B (ICO), alignment 4, on prototype struct shapes; each core's step re-declares the layout of its real `Entry`, and rustc re-checks it. i686's std is installed, but i686 has no declaration yet.
- **Abort shim crates (only if built).** These tests belong to the shim crate, not to the main crate's gates. In a child process, a shim function under fault injection must terminate. On the pinned std and target with the default alloc-error hook and without `-Zoom=panic`, the check is stricter: exit by SIGABRT, and stderr contains `memory allocation of <k·size_of::<T_site>()> bytes failed`. Elsewhere only termination without a normal return is checked.

## 7. Cost and order

DIB and TGA each have **one** guard call site. TGA is cheaper than DIB: one public function, no policy record, no step counter, no near-rlimit body. DIB has three call paths (`decode_tracked:7767`, `decode_policy_tracked:8600`, `decode_partial_metadata:8268`), three public functions plus the logged export, and the private witnesses. `decode_policy_tracked` runs close to its rlimit (comment at `dib.rs:8504`), so widening its return type and threading the log may need a split. Main risks:

- rlimit pressure in `decode_policy_tracked`.
- A-STD drifting with the toolchain. The counting test catches that drift on the pinned toolchain; no proof does.
- The call-graph audit's allowlist for precompiled std leaves is reviewed by hand; an item misclassified as non-allocating is a hole only the falsification gates can expose. The named reviewer, the recorded hash and the re-review rule on any toolchain change bound this risk without removing it. On DIB x86_64 release the allowlist has 21 entries, and 19 panic edges over 18 functions each need a T1/`Safe'` citation (`SPEC.md` §6).
- Path-insensitive authorisation. Monomorphised instances are shared between the guard and any other caller, so an audit that checks one path per instance can authorise an unapproved caller through the guard's path. The first F1 prototype had this defect. The fixed prototype judges every simple path and fails the same-instance control; the production tool must keep that check, and the control stays in its test suite. Judging every path is useless if the judgement of each path is loose: the seventh-revision prototype admitted a caller whose def-path merely ended with an admitted one. The fixed prototype matches printed def-path strings by equality, allowing only one trailing generic-argument group, consults every (item, `allow`) entry, and fails the collision controls `n12`/`n13` and the third-caller control `n14`. That is sound only within one crate: the prototype keys nodes by printed path, which drops the crate prefix of local items, so an external crate's `guard::try_zeroed` merges with the local one and is admitted. The production tool keys by `Instance`/`DefId`, rejects ambiguous allowlist names, and adds the control `x1_extern_namesake` (`SPEC.md` §6, *Caller and item identity*). An entry without generic arguments covers every instantiation reached from its admitted caller, so its contract must hold for each.
- The audit's blind spots (`SPEC.md` §6): const-eval and static-initialiser allocations; panic-path allocation, which rests on the human T1/`Safe'` citation, not on the tool; precompiled std bodies without MIR, a toolchain-determined set pinned only by the commit hash; indirect-call candidate sets, which fail closed but are not proved complete; allocator identity, which A-STD and the proof report carry; the path-enumeration bound (20,000 paths per root, depth 80), past which the audit fails closed rather than passing; the `source_hash`, which covers the source-map text of the audited crate's own files only and binds no `include_bytes!`/`include_str!` payload, environment or build input, `build.rs` or proc-macro output, or dependency (a `path` dependency is covered only by its own audit), so the proof report must list each with a content hash and match that list against an independently captured inventory (rustc dep-info covers only rustc-tracked dependencies; build-script and proc-macro reads through ordinary I/O must be traced or denied, controls `x9`/`x10`), or no report is issued; the audit tool's build-input detection, which sees presence and never content and does not detect `env!`/`option_env!`, features or `RUSTFLAGS` (in the prototype it is also heuristic: it sees a build script only through `OUT_DIR`, admits any crate named `verus*`, accepts `item = "*"` declarations, and finds `include_*!` sites by a text scan that cuts at a `//` inside a string literal and misses renamed imports and foreign macros expanding to an include; the production tool must replace each heuristic); the vstd version, which the prototype reads from `Cargo.lock` (a version string, not vstd's content) or an unchecked override, and which the production tool must bind to the linked artifact with the override refused; and the authorisation scope, which constrains the audited crate's callers only, not std's internal callers of the same instance.
- `rustc_driver` internals change between compiler releases, so the audit tool is tied to rustc 1.99.1 and must be ported with any Verus toolchain bump.
- i686 is installable, not yet audited: its std is installed, but it has no reviewed allowlist and no checked `Entry` layout (`SPEC.md` §6, §8).
- no_std drift: a consumer that depends on vstd with default features re-enables vstd's `std` in its build graph (cargo feature unification); a `Vec` import needed only by ghost code is invisible to `cargo build`. The `cargo tree` check and the verifier run catch these respectively (`SPEC.md` §9).

## 8. no_std

The main crates are `#![no_std]` with `extern crate alloc` and vstd `default-features = false, features = ["alloc"]` (`SPEC.md` §9). This adds no theorem and changes none: the conversion edits imports, paths, the Cargo feature and `cfg(test)` scaffolding, and the obligations above are unchanged. Measured: TGA 947 verified and ICNS 315 verified, 0 errors each, identical to the pre-conversion baselines. DIB and ICO convert in their own steps, and each step's verifier result must equal its pre-conversion count. The production guard is verified in a `no_std` crate. The crate-origin audit rule (no reachable instance outside `core`, `alloc`, `vstd`, `verus_builtin`, `compiler_builtins`, `SPEC.md` §9) is a production audit requirement, not a theorem, and is not yet implemented.

README paragraph, per converted core (TGA and ICNS today; DIB and ICO once converted):

> **no_std.** `<crate>` is `#![no_std]` and uses only `core` and `alloc`. Its one dependency is `vstd`, built with `default-features = false, features = ["alloc"]`; the procedural-macro crates behind it run inside the compiler and are not linked. If your build depends on `vstd` elsewhere, set `default-features = false` there too, or cargo re-enables `vstd`'s `std` feature for the whole build. Tests and examples use `std` and are not part of this claim.
