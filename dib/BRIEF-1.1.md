# Brief: DIB core update to DIB-CORE-SPEC 1.1 (Verus)

The shipped core (this directory, 1,367 verified obligations, 214 vectors) implements the frozen DIB-CORE-SPEC 1.0. Spec 1.1 (frozen, `spec-1.1-frozen/`, hashes in its FREEZE.txt) adds ONE mode, `IcoEntryDibSlack`: identical to `IcoEntryDib` except bytes after a complete AND mask are ignored instead of `TrailingBytes`. The three old modes are unchanged; the 214 old vectors are the first 214 of the 302 in `spec-1.1-frozen/VECTORS.json`. The authoritative manifest is `THEOREMS.md` (1.0) as amended by `spec-1.1-frozen/THEOREMS-DELTA.md`: READ THE DELTA FIRST, it lists exactly what changes (models, theorems, the 32 `dib.rs` / 16 `model.rs` mode sites, `model_vectors.rs`, public `Mode` break, new mutations, `decode_with_steps` export).

Binding rules (all earlier DIB/TGA/ICNS lessons apply; see BRIEF.md): every verifier run through ./verify.sh "<what>" (VERIFY_CRATE=<dir inside dib/> for copies; delete target/ and caches after: 500,000-inode volume cap); never call cargo verus verify directly; no scratch crates elsewhere; never delete or rename run logs; never edit spec-frozen/, spec-1.1-frozen/ or THEOREMS.md; no assume/admit/external_body/trusted/unsafe/todo/requires(false); no #[verifier::rlimit] or other solver-budget attribute (STUCK.md instead); state every theorem at the manifest's full quantification; witness lemmas with projection hypotheses must be discharged from and used by the public proof; implementation mutations change ONLY dib_verus/src/dib.rs, are faithful to the delta's named mutants and fail on a verifier diagnostic (not a rustc compile/type error); old-mode behaviour must stay byte-identical (the 214 old vectors, the corpus test and all shipped proofs keep verifying). Work is on git branch `dib-1.1`; do not commit unless asked (the coordinator commits). The corpus (84 Pillow test files, local only) and tests/corpus_expected.json are in dib/corpus (gitignored).
