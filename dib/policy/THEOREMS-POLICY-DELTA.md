# DIB policy theorem delta (frozen)

This is a proposed extension of `/home/ws/projects/verified-decoders/dib/THEOREMS.md` and frozen 1.1's `THEOREMS-DELTA.md`, **not a completed proof**. Do not weaken 1.1's resources or reinterpret the shipped `decode(bytes, mode)`.

## Model and executable boundary

Define the 22 retained fields as internal typed enums, not a public record constructor. Expose `#[non_exhaustive]` named profile selectors `Strict`, `GdkCompat-2.42.12`, `ImageCrateCompat-0.25.10`, `Recommended`, with `Default=Strict`. Custom record construction exists **only behind `#[cfg(test)]`** and must not compile into release artifacts; the Python oracle's `EXPERIMENTAL_OPTIONS` switch controls reference-model tests, not a Rust release feature. Every retained internal combination still obeys universal safety/resource obligations. New API: `decode_with_policy(bytes: &[u8], mode: BmpMode, profile: Profile) -> Result<ProfiledDecoded, Error>` where `BmpMode` has only `BmpFile` and `BareDib`, and `ProfiledDecoded` contains output dimensions, RGBA8 bytes and `recovered: bool`. Retain the old `decode(bytes,mode)` and `decode_with_steps(bytes,mode)` unchanged for all four modes. No public ICO policy entry point, implicit Strict fallback or overloaded arity exists. The oracle follows this division with `decode` and `decode_with_policy`.

Define `MH(b,bmp_mode,profile)` to derive a small **effective header record** after R1–R7 validation. The record contains pixel start, metadata end, declared palette count, masks, fill pixel, palette-index mode, short-pixel mode, scaling mode, image-size mode, 16-bit BITFIELDS alpha mode, clip mode, and the three **separate** RLE EOL, delta and EOB modes. It also carries `recovered_so_far` from data-affecting header recovery (invalid pixel offset repaired, `bitfield_offset=MetadataEnd` selecting a location other than valid `bfOffBits`, incomplete declared header, mask fallback or initialized Blank); tolerated `bfSize`/reserved/planes declarations alone do not set it. `MH` tags complete header, partial metadata or exact first error. For Blank results the tagged partial variant carries validated `N` and allocation size, so `MP` produces initialized output in the sole capped allocation. `MP`, `MR` and `Conv` take the required derived fields rather than the full 22-option record; `MR` additionally takes its coordinate/output state. `MH` handles `ParsedFields` with an end beyond EOF: an empty table requires no availability check but preserves the mathematical palette end for offsets. A nonempty table needs its full guarded span; internal masks at H>=52 retain their own guarded read. `MP` handles image-size checks, the closed-list recovered flag and BareDib suffix. The policy-free ICO branch retains the frozen `MA` model without `MH`'s partial variant; no `effective_policy` function or ICO fallback is required.

## Theorem inventory

| Claim | Required policy change |
|---|---|
| T1 safety | For either public API and every internally retained option combination, prove bounded reads and writes. New offsets and masks remain checked. |
| T2 exact header | `MH` equals the policy-indexed R1–R7 model as complete/partial derived record or exact first error. `ParsedFields` may put the declared end past EOF; every actually read field stays guarded, and a zero-length table needs no read. |
| T3 allocation | Universal `0<=allocation_calls<=1` and exactly one `4N<=64 MiB` allocation on *every successful path*, including initialized-blank recovery; none on header-error paths; no extra palette/scratch allocation. Pixel and RLE fill are writes into that allocation. |
| T4 conversion | Policy-indexed `conv=Conv` proves GDK's bounded popcount shifts, image-rs's >8-bit truncation, overlapping independent masks, default masks and 16-bit GDK opaque alpha. |
| T5 row arithmetic | Existing mathematical stride/orientation lemmas hold for all p, but statements involving pixel writes must account for short-row fill and clipped RLE. `T5`'s end-to-end helper use is policy-quantified. |
| T6 raw | Exact byte/cursor match to the policy raw transition, including 2-bpp high-first samples, a short row leaving initialized pixels rather than reading a partially present source row, and GDK's BITFIELDS metadata-end cursor. Model cursor may move logically past `|b|` after a short row or a ParsedFields header, but every **read** must remain bounded; use an explicit remaining-row count instead of asserting `cursor<=|b|` on those paths. |
| T7 RLE | Policy-quantified command/coordinate/paint equivalence for `MR`. Existing `painted<=N` remains universal with Clip; command progress `>=2` remains universal on entered complete commands. AtInputEnd can terminate with zero/one remaining byte without entering a command; no implicit partially consumed packet may read beyond input. |
| T8 ICO AND | Policy-free ICO `decode` uses the frozen model and retains exact XOR/AND-mask and suffix distinctions; there is no profiled ICO result to quantify. |
| T9/T10 result/errors | For named BMP profiles, `decode_with_policy=MP` on every RGBA byte, the `recovered` flag and exact first error. Native errors/crashes are not modeled. |
| T11 termination | Universal for every retained option value. RLE remains bounded by remaining input; an AtInputEnd terminal branch does not retry. |
| T12 linear work | Universal `steps <= 16*(|b|+N)` with the original charged counter and N definition. ZeroFill/Blank/RLE initialization charges bytes written. Clip computes `painted=min(quantity,max(0,width-x))` once and loops only over those painted pixels: **clipped positions cost zero loop iterations**, not 255 per command. A command still costs constant work and consumes at least two input bytes. Bound raw at 6N plus linear input scans and RLE at 9N plus command work (at most one command per two input bytes); retain the 16 multiplier. Verify the same executable call used by the public API. |
| T13 success/resource | Policy-quantified equality and initialized `4N` pixels; strict BareDib suffix remains exact, BMP ignores suffix. A policy-specific short-row success has only initialized black in unfilled cells. |

Resource obligations T1/T3/T11/T12 are **never conditional on a named profile or success**: every retained internal option combination still has the same caps, allocation bound, totality and linear work. Functional claims T2/T4–T7/T9/T10/T13 use a policy-indexed model only for named BMP/BareDib profiles; experimental records receive a functional proof only if promoted. Implement the old `decode` as the Strict instance of the same mathematical function, defining `MH_1_1 := MH(Strict)` and `MP_1_1 := MP(Strict)` rather than proving equality between independently written decoders. The spec-level lemma states equal first errors, RGBA bytes and dimensions for **all inputs in all four modes**; ICO dispatch remains unchanged. The frozen 302 vectors are a regression gate, not the proof. Compare `STRICT-VECTORS.json` byte-for-byte with the frozen source and run unchanged crate conformance tests.

## Proof staging, effort and risks

1. Add named typed profiles, unchanged Strict wrappers and the spec-level strict bridge; verify full 1.1 obligations before leniency. No public mode-variant or old-function arity change.
2. Add metadata-only options (`file_size`, `image_size`, `planes`, reserved, header selection) one at a time; each needs exact first-error witnesses in T2/T10.
3. Add palette/mask/colour options, then short-row fill and RLE. Keep `MR` separate from executable RLE code. Each new recovered path proves that its flag is true and that its output uses the one capped allocation.
4. Gate speculative fields independently: disable a field's experimental implementation if its proof stalls without altering a frozen named profile; do not freeze a profile until all its required fields are proved. Test coupled state (header end plus table size, offset plus BITFIELDS, terminal EOL plus delta, truncated row plus image size), not just single fields.
5. Add proof-gate witnesses for previously surviving meaningful mutations, compare against native BMP libraries, and audit allocation/loop costs. Keep the old strict witness file single; do not expand 64 MiB repeated vectors into verifier terms.

The original DIB proof contains 1,557 verified obligations and a large `model_vectors.rs` witness file. Metadata-only gates should cost a fraction of the original implementation; palette, recovery, and RLE branches could approach the original RLE/integration proof effort because they change cursor and first-error invariants. Budget at least **one additional substantial verification campaign**, not a one-branch change. Specific hazards: a fill pass exceeding the 16 multiplier, a policy field inadvertently changing ICO, `cursor<=|b|` invariants invalid after logical short-row advancement, multiplication of witness fuel by four profiles/custom combinations, a `model_vectors.rs` source-size/fuel explosion if every old vector is duplicated four times, and an extra allocating call introduced by a convenience palette fallback. Keep the old strict witness file single; use small policy-specific gates and runtime-generated fixtures for the rest.
