# Sources and evidence boundary — DIB 1.1 draft (historical 1.0 draft evidence below)

The paragraphs and fixture counts retained below document the **older 1.0 drafting stage**, not the current 1.1 vectors. This amendment adds exactly one source-level policy: permit surplus bytes after a complete ICO-entry AND mask. **READ baseline** `/home/ws/projects/spec/gdk-pixbuf/gdk-pixbuf/io-ico.c:289–298,334–375` ignores `data_size` for the selected DIB, but this does not establish normative format semantics. **READ frozen contract** `/home/ws/projects/verified-decoders/dib/spec-frozen/SPEC.md:R12,R14–R18`; its 1.0 files remain unchanged. The new mode and exact restriction to surplus bytes are **DECISION**, not a claim from a primary Microsoft specification. The 1.1 local oracle passes 302 vectors (214 original records unchanged, 88 additions). The independent reviewer derived a separate slack oracle and agreed on all 272 earlier vectors; the 30 subsequent shape-specific additions still need independent recheck. No 1.1 Verus proof has run.


`READ` means a complete local file or the relevant source code was actually inspected. `RECALLED` means a format assertion was **not** established by reading a primary specification. `DECISION` marks this decoder's policy. Both local gdk-pixbuf baselines were read in full: `/__modal/volumes/vo-Iyh3VLkOB7cEHrIp2RkTs7/projects/spec/gdk-pixbuf/gdk-pixbuf/io-bmp.c` and `io-ico.c`. They are implementation evidence, not normative authorities. Attempts to fetch the Microsoft pages below with WebFetch returned `ECONNRESET`; search snippets supplied some content, but no full primary-format document was read. Accordingly **no Microsoft claim is labelled READ**. These links identify the primary documents for a later evidence pass, not verified primary-source support for this draft.
