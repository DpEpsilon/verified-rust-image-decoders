# DIB theorem delta — version 1.1 (frozen)

This document amends `/home/ws/projects/verified-decoders/dib/THEOREMS.md` only for a fourth typed mode `IcoEntryDibSlack`. It **does not** change that frozen manifest or the shipped crate. No 1.1 proof has been run. The 214 original vectors are identical and remain obligatory for the old modes; 88 appended vectors (302 total) exercise the new branch, including every slack length from zero through nine, the exact 64 MiB input boundary, 32-bpp BI_RGB and BITFIELDS alpha, indexed palettes, and forbidden RLE. The intended implementation is a new mode-discriminant branch at the final trailing-byte check, not a second decoder.

- **Models `MH`, `MP`, `MA`, `MR`, `Conv`:** extend the typed `Mode` enum and the `is_ico` predicate to include `IcoEntryDibSlack`. `MH` and its successful record must retain the **exact fourth mode**, not collapse it to the old mode: header checks and metadata still match `IcoEntryDib`. `MR`/raw conversion/`MA` share the old ICO rules. `MP` skips only the final `cursor==|b|` test when its mode is `IcoEntryDibSlack`; old-mode `MP` is definitionally unchanged. Derive a bridge for every `b`: `MP(b,Slack)` and `MP(b,IcoEntryDib)` differ **only** when the latter returns `TrailingBytes`, then the former returns the completed decoded image; no weaker error changes. This bridge may use the exact mask-phase ghost cursor.
- **T1 safety, T2 exact header, T4 conversion, T5 row arithmetic, T6 raw, T7 RLE, T8 AND:** quantify over the new mode and prove that all ICO-mode branches recognize it, including positive even height, RLE rejection, non-BMP alpha, AND requirement, image-size set and palette policy. T8's final phase requires an explicit suffix branch; this is the substantive pixel-model update. These are adaptations of shared lemmas, not new image decoding algorithms.
- **T3 allocation:** same one `4N` request for new-mode success, same cap, same audit caveat. A return without a trailing check does not create another allocation.
- **T9 integrated `decode=MP`, T10 exact errors:** add the new mode to universal quantification. A new-mode suffix returns pixels where the old mode returned `TrailingBytes`; short mask and invalid `biSizeImage` retain their previous priority. Witnesses `slack-1-new/old`, `image-size-9-slack`, `mask-short-3-new`, and `invalid-size-and-short-new` prevent a vacuous last-stage proof.
- **T11 termination, T12 linear work:** no loop added; the same `steps<=16*(|b|+N)` proof applies, but ensure the returned branch carries the final ghost counter. The shipped `dib.rs` already has private `t12_linear_work` (near line 5388), whose body calls `decode_tracked` and ensures both `decode_mp_eq` and the step bound. Export that same body as `pub fn decode_with_steps` (with its ghost step result and proved postconditions), and have the ICO crate call **`decode_with_steps` instead of `decode`** on the exact selected slice. Erasure of the ghost return leaves the same executable decode path. Exporting a theorem without changing the ICO call would not connect the counter to ICO's invocation. This public export is additional proof-interface work, not required for functional composition or the ICO-only bound; audit uncharged library loops separately.
- **T13 success and resource:** `BareDib` and old ICO success still require `cursor=|b|`; new-mode success requires `cursor<=|b|` with the exact AND end before the ignored suffix. Output dimensions and bytes remain the old model's completed image. The old blanket ICO-success cursor claim needs a mode case split.
- **Named lemmas:** `stride_roundup_safe`, `row_last_sample_within_stride`, `product_width_height_bound`, `pixel_byte_offset_bound`, `vertical_flip_bijection`, `bit_mask_contiguous_extract`, `scale_round_bounds`, `palette_stride_bounds`, `rle_monotone_position`, `rle_painted_at_most_N`, and `and_bit_offset_bound` retain the same arithmetic statements; only their use sites may need the broadened ICO-mode guard. Add `slack_mode_same_prefix` (same header/pixel/mask transitions), `slack_mode_suffix_result` (exact final-stage difference), and `old_modes_unchanged` (all 214 old vector/model results).
- **Mutation deltas:** implementation-side mutate (1) treat new mode like `BareDib` at final cursor check (`slack-1-new`, T9/T10); (2) apply slack policy to old ICO (`slack-1-old`, T9/T10); (3) skip AND availability when suffix exists (`mask-short-3-new`, T1/T8/T9); (4) accept arbitrary nonzero `biSizeImage` in slack mode (`image-size-9-slack`, `image-size-includes-slack-new`, T8/T10); (5) omit doubled-height (`odd-height-new`) or ignore BI_RGB alpha/AND fallback (`alpha32-7f-mask80-new`, `alpha32-00-mask00-new`, T2/T8/T9); (6) allow RLE8/RLE4 in slack mode (`rle8-forbidden-new`, `rle4-forbidden-new`, T2/T7); (7) change the cap from `>` to `>=` (`max-input-slack-IcoEntryDibSlack`, T1); (8) rescan suffix before returning (long-suffix new mode, T12 **only when the actual loop is charged**, otherwise source audit). Do not mutate the model with the executable. The previously documented allocation mutant remains **audit-only** if an allocation call is added without a ghost charge.
