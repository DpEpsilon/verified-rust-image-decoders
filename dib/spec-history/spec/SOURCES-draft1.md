# Sources and evidence boundary

`READ` means the named source was inspected during this draft. `RECALLED` means not established from a primary specification. `DECISION` means this core's policy, not a purported BMP requirement. The two C baselines below were read **in full**; their progressive loader and file saver are implementation evidence, not authorities. Paths refer to `/__modal/volumes/vo-Iyh3VLkOB7cEHrIp2RkTs7/projects/spec/gdk-pixbuf/gdk-pixbuf/`.

| Format claim | Evidence and boundary |
| --- | --- |
| BITMAPFILEHEADER's BM, file-size, reserved fields, pixel offset | **READ** [Microsoft BITMAPFILEHEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapfileheader); `io-bmp.c:269–286,535–566`. Exact full-slice equality/offset precedence are **DECISION**. |
| CORE 12, INFO 40, V4 108, V5 124; signed height, planes, depth | **READ** [Microsoft header types](https://learn.microsoft.com/en-us/windows/win32/gdi/bitmap-header-types), [BITMAPCOREHEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapcoreheader), [BITMAPINFOHEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader), [BITMAPV4HEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapv4header), [BITMAPV5HEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapv5header); `io-bmp.c:292–342`. 52/56/64 acceptance comes from `io-bmp.c:305–323`; IBM normative treatment of 64 was **not read**. |
| 16-byte OS/2 2.x truncated header with 32-bit width/height | **RECALLED** / cross-checked against Pillow `pal8os2v2-16.bmp` bytes and [third-party Rust decoder documentation](https://docs.rs/oxideav-bmp/latest/oxideav_bmp/types/index.html); no IBM primary header document read. Distinguish it from the 12-byte CORE header. |
| Palette `biClrUsed=0`, RGBTRIPLE/RGBQUAD and word-aligned rows | **READ** [Microsoft BITMAPINFOHEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader), [header types](https://learn.microsoft.com/en-us/windows/win32/gdi/bitmap-header-types), [bitmap storage](https://learn.microsoft.com/en-us/windows/win32/gdi/bitmap-storage); `io-bmp.c:355–375,442–445,583–631`; short palettes are a documented field meaning. Strictly rejecting optional high-depth optimal palettes is **DECISION**, and [MS-WMF BitmapInfoHeader](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-wmf/567172fa-b8a2-4d79-86a2-5e21d6659ef3) permits them. |
| RGB 5:5:5 at 16 bpp; masks for 16/32; alpha mask in V4/V5 | **READ** [Microsoft BITMAPINFOHEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapinfoheader), [BITMAPV4HEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapv4header), [BITMAPV5HEADER](https://learn.microsoft.com/en-us/windows/win32/api/wingdi/ns-wingdi-bitmapv5header), [previous BITMAPINFOHEADER remarks on contiguous masks](https://learn.microsoft.com/en-us/previous-versions/dd183376%28v%3Dvs.85%29); `io-bmp.c:649–736,829–893,918–979`. | RLE8 and RLE4 encoded/absolute, escapes, delta, word padding | **READ** [Microsoft Bitmap Compression](https://learn.microsoft.com/en-us/windows/win32/gdi/bitmap-compression), independently [MS-WMF 4-bpp encoding](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-wmf/73b57f24-6d78-4eeb-9c06-8f892d88f1ab); `io-bmp.c:1105–1268`. Mandatory EOB, bounded runs/deltas, palette-zero initialization and exact suffix are **DECISION**. |
| ICO stored doubled height, XOR followed by 1-bpp AND, AND MSB-first | **READ** [Microsoft Resource File Formats](https://learn.microsoft.com/en-us/windows/win32/menurc/resource-file-formats) confirms DIB image bits followed by a monochrome AND mask, and [CreateIcon](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-createicon) documents AND/XOR masks; `io-ico.c:399–410,817–890,1235–1254` independently shows the doubled DIB height and MSB-first bit position. The **specific file-entry doubled-height field interpretation is RECALLED**, not verified from a primary ICO file-format specification. The loader ignores AND at 32 bpp (`:823–825`); our core deliberately applies it. |
| Directory selection and container PNG | **READ** `io-ico.c:214–394` selects a ranked DIB and excludes compressed entries; those operations are outside this API. A PNG-only entry is out of scope, not a `IcoEntryDib` acceptance claim. |
| Caps, exact error ordering, allocation/work bounds and fixture encoding | **DECISION**, modeled after **READ** `/__modal/volumes/vo-Iyh3VLkOB7cEHrIp2RkTs7/projects/tga/spec/SPEC.md`, `THEOREMS.md`, `REVIEW.md`, `REVIEW2.md`; reviewer mutation blind spots drove explicit palette/mask/precedence cases. No verified BMP implementation exists yet. |

The 186 fixtures were built by a separate scratch generator with manually specified expected runs/errors; `check_vectors.py` independently parses the bytes rather than importing the generator. `python3 -I check_vectors.py` passes 186/186. This is one oracle, not independent reviewer validation; no claim of mutation testing or freeze is made. One maximum-output fixture expands to 266,286 input bytes and 67,108,864 output bytes; the two full-input cases use symbolic expanded-length checks. The fixture generator is not a normative source.

Local corpus: [Pillow GitHub repository](https://github.com/python-pillow/Pillow), commit `aa60851e1f0f00a82560a553cbad4429d9233b86`, `Tests/images` sparse shallow clone, 84 regular `.bmp/.ico/.cur` files each at most 1 MiB, 1,365,291 bytes copied. Its `LICENSE` states MIT-CMU terms and copyright attribution; individual third-party fixtures may carry their own rights. The corpus stays local and **must not be redistributed**. `tools/run_corpus.py` reads the corpus and passes first DIB ICO/CUR entry to this oracle; this selection is solely a diagnostic shim, not the future container contract.
