# GIF owner decisions: changelog

The owner decided `policy-draft/QUESTIONS.md` Q1–Q18 on 2026-11-14; this file records how each decision was applied to the drafts, which became GIF-CORE-SPEC draft 0.2 and policy draft 0.2. Nothing is frozen. A later refinement of Q6 (size 1 only for a one-pixel frame, same day) is recorded in the Q6 entry and moved the vector count to 373. Results after applying them: 360 vectors (340 Strict, 20 profile records; 312 before: 49 added, `screen-8193` renamed, 13 with changed expectations) all agree with the oracles; 33 closed errors, 32 exercised by Strict vectors (`PixelBudgetExceeded` is left to a lemma); Strict bridge 355/355 inputs; obligation R: 163 still-accepted inputs, 114 accepted streams, 131,270 Strict frames, 0 violations; compatibility agreement unchanged (below).

## Decisions and their effect

- **Naming.** The provisional recommended profile is `RecommendedBeta` in every file under `gif/` (profiles: Strict, RecommendedBeta, GdkCompat-2.42.12, ImageCrateCompat-0.25.10). Files: `BRIEF.md`, `PLAN.md`, `spec-draft/DESIGN-NOTES.md`, `policy-draft/{OPTIONS.md,QUESTIONS.md,policy_oracle.py,validate.py,necessity.py}`, vector names in `spec-draft/gen_vectors.py`.

Files: `policy-draft/{OPTIONS.md,QUESTIONS.md}`, `gen_vectors.py`.
- **Q2 (a), API.** `decode_still` plus a frame iterator returning a view of the whole canvas borrowed from the decoder (one canvas, no per-frame allocation, no `Iterator` trait: `while let Some(f) = dec.next_frame()`), fused after its first error. Model change: `decode_frames` now returns `{error}` for errors before the first image descriptor, which changed the expectations of the nine truncation records `cut-25` to `cut-33` (cuts inside the Graphic Control or exactly at the first image separator now fail in the constructor). Files: `spec-draft/{SPEC.md (G1, G15, G18),gif_oracle.py,gen_vectors.py}`, `policy-draft/policy_oracle.py`, `BRIEF.md` (API block), `PLAN.md` (`MP`, T-ITER base case).

"Strict-accepted" is defined separately for the still entry point and the whole stream, with obligation R for each and a frame-prefix form; `validate.py` checks all three. Files: `SPEC.md` (G14, G15), `DESIGN-NOTES.md` (N15), `OPTIONS.md`, `validate.py`, `BRIEF.md`.
- **Q4.** Truncated and short frames and invalid LZW codes stay errors in RecommendedBeta; partial frames only in GdkCompat. No code change. Files: `OPTIONS.md` (D3), `QUESTIONS.md`, `BRIEF.md`.
- **Q5.** Out-of-range non-transparent colour index rejected in RecommendedBeta; compatibility profiles keep their library's rule; a transparent index beyond the table stays legal. - **Q6 (b), minimum code sizes.** Settled from `../leniency/corpora/gif-LZWMIN-ANALYSIS.md`. Strict keeps 2–8. RecommendedBeta takes the new third value `lzw_min=Range1to11Checked`: sizes 1–11 (size 1 refined below), and a literal code in 256..2^m−1 returns `ColorIndexOutOfRange` when read. Evidence: 15 non-fuzzer corpus files have a size outside 2–8; 5 are decodable images (size 1 in two files sharing one 42-byte 1×1 GIF and in image-gif `set_hsts.gif`; size 10 in libnsgif `lzw-code-three-subblocks.gif`; size 11 in gdk-pixbuf `max-codes.gif` and Pillow `issue_2811.gif`) that gdk-pixbuf (both paths) and image 0.25.10/gif 0.14.2 accept with identical first frames, while all three reject the other ten; checked and mod-256 decoders differ on 0 of 99 examined files, and all three incumbents wrap a size-9 literal above 255; widening flips exactly those five of 1,407 files; none of the 303 incidental assets uses such a size. Caveat: test-suite corpus, 23% fuzzer-derived. Obligation R unaffected. Vectors: `lzw-min-code-1-1x1`, `lzw-min-code-9`, `lzw-min-code-10`, `lzw-min-code-11` (decode), `lzw-min-code-9-literal-300` (rejected), `lzw-min-code-12` (rejected), all `@RecommendedBeta`. The generator's LZW encoder was fixed for `m > 8`. Files: `policy_oracle.py`, `gen_vectors.py`, `SPEC.md` (G9), `OPTIONS.md`, `QUESTIONS.md`, `BRIEF.md`, `PLAN.md` (M2).
  **Refinement (owner, 2026-11-14): size 1 only for a one-pixel frame.** `Range1to11Checked` accepts `m = 1` only when the descriptor gives `w·h = 1` (the declared frame size: not the clipped visible part, not the screen); any larger frame with `m = 1` returns `InvalidLzwMinCodeSize` at the minimum code size byte, before the sub-blocks are read. Sizes 10 and 11 stay accepted with checked literals, Strict stays at 2–8, compatibility profiles keep their library's rule. Evidence (`policy-draft/LZW-SIZE1-WIDENING.md`, 496 generated streams through gdk-pixbuf, `image` and the oracle, plus the sources of gdk-pixbuf 2.42.12, weezl 0.1.12 and giflib): at `m = 1` the table starts with 4 = 2^2 entries, so gdk-pixbuf and the oracle never widen the code width, weezl widens after the first new entry (the third code is 3 bits) and giflib, like Appendix F, one entry later (the second code is 3 bits); from five pixels up none of the three decodes an Appendix F stream correctly (0 of 40) and gdk-pixbuf returns wrong pixels without an error on 13 of 72 short ones. On a one-pixel frame the loop reads Clear codes and at most one 2-bit literal and stops, so no table entry is added and the three rules coincide. Both size-1 corpus files are 1×1 and stay accepted; the `lzw_min` flips stay at five of 1,407. Corpus re-check, run on the seven files whose walk reaches an `m = 1` image-data call (no other file can change; the full pass's oracle phase takes 13 to 15 minutes): the accept/reject outcome of all 1,407 files is unchanged and the five `lzw_min` flips are the same, but the first error of five rejected fuzzer-derived files, all libnsgif `ns-afl-gif` mutants with frames of 1,024 or 8,224 pixels that all three incumbents reject, becomes `InvalidLzwMinCodeSize` (four were `TruncatedImageData`, one `TooFewPixels`). Vectors added, all `@RecommendedBeta`: `lzw-min-code-1-2x1`, `-1x2`, `-1x1-interlaced`, `-1x1-frame-in-4x3-screen`, `-2x1-frame-clipped-to-1x1-screen` (still and `/frames` each), `-second-frame-2x1` (still and `/frames`), and `lzw-min-code-1-1x1/frames`; `lzw-min-code-1-1x1` is unchanged. Results: 373 vectors (340 Strict, 33 profile records) agree with the oracles; Strict bridge 360/360 inputs (5 new distinct inputs); obligation R unchanged (163 stills, 114 streams, 131,270 frames, 0 violations); compatibility agreement unchanged for Strict, GdkCompat and ImageCrateCompat; RecommendedBeta versus the incumbents 311 → 310 (image) and 269 → 268 (GDK loader), the one input being `vec:lzw-min-code-1`, a 2×1 size-1 stream that both decode and RecommendedBeta now rejects; of the 89 inputs Strict rejects and an incumbent accepts, RecommendedBeta accepts 41 (was 42); `necessity.py` finds `lzw_min` still needed by the size 9–11 inputs (breaks 10 inputs when reverted, was 12). Files: `policy_oracle.py` (`read_image_data` takes the frame area), `gen_vectors.py`, `SPEC.md` (G9), `OPTIONS.md`, `QUESTIONS.md`, `LZW-SIZE1-WIDENING.md`, `BRIEF.md`, `PLAN.md` (M2, vector count), `../leniency/corpora/gif_lzwmin.py` (census wrapper takes the extra argument).

## Tooling changes

- `check_vectors.py`: runs records with a `profile` through `policy_oracle.py` (expectations add `recovered`), supports `entry: plays`, and counts error coverage over Strict records only.
- `validate.py`: obligation R in three forms (still, stream, frame prefix) with counts; profile renamed.
- `necessity.py`: RecommendedBeta's fields are now measured against `image` and the GDK loader (before, it had no runner and every field reported 0).

## Measured effect

Compatibility agreement on the 329 probe, vector and witness inputs is unchanged: ImageCrateCompat 327/329 with image and with glycin, GdkCompat 327/329 with the GDK loader and 326/329 with gdk-anim. Both profiles already used `gce_consumers=ImageOnly`; reverting it to Strict's new `Reject` breaks the same number of inputs as reverting to the old `Spec` did (GdkCompat 7, ImageCrateCompat 2), so no field had to be adjusted. Fields whose reversion breaks no measured input: ImageCrateCompat's `gce_orphan`, `missing_trailer`, `trailing` (as before; the iterator comparison cannot see them) and its new `loop_scan` (no runner exposes the loop count); RecommendedBeta's `missing_trailer=AtEof` (gdk-pixbuf rejects, image cannot show it). Strict versus the incumbents: image 261 → 263 (Strict now rejects the two inputs with a Graphic Control before an unknown graphic label, as image does), GDK loader 218 → 217 (Strict now rejects `probe:gce-before-plaintext`, which GDK accepts). RecommendedBeta versus the incumbents: image 303 → 311 and GDK loader 260 → 269 (Graphic Control target and minimum code size inputs). Of the 89 inputs whose still Strict rejects and image or the GDK loader accepts, RecommendedBeta accepts 42 (the draft-0.1 field set: 33 of 86). `probes/results.json` was not re-run (the runners live in a reset `/tmp`); its `oracle` summaries predate draft 0.2, and `validate.py` does not read them.
