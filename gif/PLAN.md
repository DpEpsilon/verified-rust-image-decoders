# GIF proof phase: work breakdown

Conclusion first: one crate (`gif_verus`), `no_std + alloc` and `try_*`-only from the first line, proved in six core milestones (M0–M5) and two policy milestones (P1–P2). Estimated size, calibrated on the earlier cores: 1,600–2,400 verified obligations for the core plus Strict/RecommendedBeta, and 40–60% more for the two compatibility profiles (the owner's decisions of 2026-11-14 leave this range unchanged; see "Effect of the decisions" below); 1,200–2,000 `verify.sh` runs; 14–18 dispatches. The three obstacles most likely to cost runs are the LZW table representation, the bit reader over sub-blocks and the multi-frame iterator invariant.

Calibration: DIB reached 1,557 obligations over 1,560 logged runs (core 1.0, the 1.1 mode, policy P1–P2 and allocation work); TGA 947 obligations over 720 runs; ICNS 315 over 258; ICO 303 over 174. GIF's header and block parser are about TGA's size; its LZW decoder is harder than any RLE so far (a dictionary with a representation invariant); the compositor and the stateful iterator have no precedent in these cores.

## Structure

- `gif_verus/src/model.rs`: the frozen model, transcribed from `spec-draft/SPEC.md` independently of the executable: `MH` (G2–G4), `MB` (the block walk G5–G9 without pixels, returning the per-frame records and the concatenated image data `D` as a ghost `Seq<u8>`), `MP(b)` (the constructor's prefix walk of G15: `MB` up to the first `0x2C`, fixing `loop_count`), `ML(m, D, A)` (G10, the index sequence or first error), `IR(r, h)` (G11), `MC(canvas, frame, gce, prev)` (G12), `MS(b)`/`MF(b)` (G14/G15) and `plays` (G20). Policy-indexed versions take the record (P1). All caps appear only as the named constants of G1's limits table.
- `gif_verus/src/lzw.rs`, `parse.rs`, `compose.rs`, `policy.rs`, `gif.rs` (entry points, iterator, `plays`), `alloc_guard/{mod.rs,sites.rs}` (the hash-pinned guard of `../alloc-delta/SPEC.md` §3, sites `Canvas`, `LzwTable`, `Saved`). One crate with these as separate modules, each with its own model, proved in the stages below (Q10).
- Tests: `tests/conformance.rs` over `spec-draft/VECTORS.json` (all 373: 340 Strict, 33 profile records), the probe inputs, and a stress test (below).

The guard and `no_std` are adopted from the start (alloc-delta §1.2 removes non-`try` names; retrofitting cost DIB and TGA separate campaigns).

The task as planned: Run `policy_oracle.py` with RecommendedBeta end to end (still and whole stream) on the 1,407 files pinned by `../leniency/corpora/manifests/gif.MANIFEST.tsv` (manifest SHA-256 `122e6ecacdbe081c7bf32209ede195833d2fcda4553381dd39695631b39ccf23` on 2026-11-14) and record, per file, the outcome and which of RecommendedBeta's ten fields fired (the error each one replaced); summarise per field and compare with the GDK and image runners on the same files. **M1 — plain implementation.** Ordinary Rust outside `verus!`, with the guard already in place. Done when all 373 vectors pass (the 65,536-frame records and the 256 MiB padding records as runtime tests), every probe input matches `gif_oracle.py` on accept/reject and pixels, and the leniency harness gains a `verified` GIF runner agreeing with Strict.

**M2 — LZW core (T-LZW).** For all `m ∈ [2,8]` (and `m ∈ [2,11]` with checked literals for RecommendedBeta's `Range1to11Checked`, Q6), all `D`, all `A ≥ 1`; and, for `m = 1` under `Range1to11Checked`, all `D` and `A = 1` (the descriptor's `w·h`; any other `A` is `InvalidLzwMinCodeSize` before the sub-blocks, checked in the parser, so the LZW core never sees it): the executable decoder emits exactly `ML(m, D, A)`'s index sequence or its first error, with the bit position at the error; table indices stay below 4096; every chain walk stays inside the table and writes only positions below `A`; termination by the variant `8·|D| − pos`. Literal codes (below `clear = 2^m`) are decided by rule, with no per-frame initialisation of literal entries; the table holds entries only for codes `≥ clear+2`, in the one 20,480-byte `try_zeroed(LzwTable, 20480)` region (prefix, suffix and length views, G18; `THEOREMS.md` D20, L-TABLE-VIEW). Proof plan: two length functions, kept apart (`THEOREMS.md` R11): the raw storage accessor `stored_length(t, c)` (the LE16 pair at `12288 + 2c`, defined for every `c < 4096`, unspecified for literal codes, whose bytes are never written by the frame and read zero or stale) and the code-level `code_length(t, m, c) = if c < 2^m then 1 else stored_length(t, c)`, with `code_suffix` and `code_first` split the same way (a literal's suffix and first index are the code value, not table bytes). L-TABLE-VIEW's region separation is proved on the raw accessors (`prefix`, `suffix`, `stored_length`); everything below uses the code-level functions. The table invariant `∀c ∈ [clear+2, next): prefix(t, c) < c ∧ prefix(t, c) ∉ {clear, clear+1} ∧ stored_length(t, c) = code_length(t, m, prefix(t, c)) + 1 ≤ 4096`, with `code_length = 1` and `chain(c) = [c]` for `c < clear` by rule, plus the representation lemma `chain(t, m, c) = model_table[c]` with `|model_table[c]| = code_length(t, m, c)`; the chain walk's bound is `code_length(t, m, c) ≤ 4096` steps (the model holds strings; the executable holds prefix links, suffixes and lengths, and walks a code's chain last index first, writing each index at its pixel position, so no string stack is needed); the width lemma `next < 2^width ∨ width = 12` (for `m ≥ 2`; at `m = 1` it fails from the start, `next = 4 = 2^width`, which is why size 1 is limited to one pixel); the size-1 lemma: for `m = 1` and `A = 1`, `prev` is `none` when the first literal is read, so no table entry is added, `next` stays 4 and `width` stays 2 until the loop returns at the raster after at most one literal (under `lzw_tail=StopAtRaster`, RecommendedBeta's value; every code read is a 2-bit Clear or literal), which is the width all three incumbents' rules give on that frame (`policy-draft/LZW-SIZE1-WIDENING.md`); the KwKwK case where the new entry's string is needed before it is materialised. The models for `m ∈ [9, 11]` are judged against `policy-draft/policy_oracle.py` only: the Strict oracle `spec-draft/gif_oracle.py` rejects `m > 8` at G9 and its `lzw_decode` builds the literal table with `bytes([i])` for `i < 2^m`, which cannot represent a literal above 255, so the `lzw-min-code-9`, `-9-literal-300`, `-10`, `-10/frames`, `-11` and `-11/frames` records `@RecommendedBeta` are checked through `policy_oracle.py` (whose `lzw_decode` stores `i & 255` and rejects literal codes `≥ 256` when read). Witness gate: about 12 small streams (Clear, EOI, KwKwK, width change at 7→8 entries for m=2, each error; `THEOREMS.md` lists them). The size limit below is on the record's expanded input `b` (the bound under which `THEOREMS.md` checks records by concrete computation); the image-data payload `D` is smaller. No record whose input is at most 4,096 bytes reaches width 12 or `next = 4096`: the widest is `lzw-m2-reaches-12-bits` (1,268 input bytes, a 1,225-byte payload, 4,096 pixels), which reaches width 11 and `next = 1076`. Width 12 and `next = 4096` are reached by three larger records: `lzw-table-full-clear` (128×64 = 8,192 pixels, 12,001 input bytes, an 11,163-byte payload), `lzw-table-full-deferred-clear` (8,192 pixels, 12,300 bytes, an 11,461-byte payload) and `screen-32768x100` (3,276,800 pixels, 10,700 bytes, a 10,620-byte payload). In `lzw-table-full-clear` and `screen-32768x100` the only code read at `next = 4096` is a Clear; only `lzw-table-full-deferred-clear` reads non-Clear codes at a full table (4,035 of them), the deferred clear of L-FULL (measured with an instrumented `gif_oracle.py`, Sol review round 2). Those three are runtime tests, so width 12, the full table and the deferred clear are proved through the symbolic lemma L-FULL, and the gate adds a runtime stress test: a generated stream of at least 8 MiB that reaches width 12 and a full table, with and without a Clear at the full table, built at test time by `spec-draft/gen_vectors.py`'s encoder, checked against `gif_oracle.py`, and not stored.

**M3 — header and block parser (T1–T3, T10 prefix).** `MH`, `MP` and `MB` equality with exact first error for every input: header, both colour tables, extensions (GCE size and terminator, duplicates, undefined disposal, Application and Plain Text sizes, unknown labels, and the new label check that returns `UnsupportedGraphicControlTarget` when a pending GCE meets a label ≤ 0x7F, Q7), descriptors and caps (comparisons on unnarrowed sums up to 131,070), the two-phase image-data scan, the NETSCAPE2.0 scan of every sub-block (rule A, Q15). The bit reader over sub-blocks: prove that reading `width` bits at reader state `s` (sub-block index, offset, bit buffer) equals reading `D` at model position `pos(s)`, where `D` is the ghost concatenation built by the structural scan and `pos(s)` counts the code bits consumed so far: after a successful read it is the position after the code, and a read refused because fewer than `width` bits remain leaves it unchanged (SPEC G10.2: a step-1 error carries the position before the failed read, every later error of an iteration the position after its code). Allocation: `Canvas` and `LzwTable` reserved exactly when `MH` succeeds (A-…-1/2 shape: G, Prog, the `PreAlloc` corollary).

**M4 — interlace and compositor.** M4a: `interlace_row` is a bijection on `[0, h)` for all `1 ≤ h ≤ MAX_DIMENSION` (65,535) (pass sizes `⌈(h−s)/k⌉`; nonlinear facts as explicit lemmas); every pixel write lands inside `4·W·H`; under Strict the frame rectangle is inside the screen, so `4·((top+r)·W + left+c) + 3 < 4N`. M4b: disposal 2 and 3 on rectangles, the `Saved` buffer (reserved once, in the call that draws the first disposal-3 frame, after its G8–G9 checks and before its first LZW code; the decoder is fused after an `OutOfMemory` there) and its row layout, the canvas equality `canvas_k = MC(canvas_{k−1}, …)` as a whole `Seq`, stated per position (inside the rectangle and drawn, or unchanged).

**M5 — integration (T9–T13, T-ITER, T-PLAYS).** In the alloc-delta shape (`G ∧ Prog`, `PreAlloc`; A-GIF-1, A-GIF-2): `try_decode_still(b) = Ok(s)` implies `MS(b) = Ok(s')` with `s` and `s'` equal in every RGBA byte, unconditionally; and whenever the result is not `OutOfMemory`, `fmt_part(try_decode_still(b))` equals `MS(b)` exactly, including every RGBA byte and the first error. Whenever `Frames::try_new(b)` does not return `OutOfMemory`, it fails exactly when `MH` or `MP` fails, with that error, and otherwise `info()` equals `MF(b).info` (including `loop_count`); an `OutOfMemory` occurs only after `MH` succeeds and names an element of `Req_new(b)`. A valid input may return `OutOfMemory` (a failed `Canvas` or `LzwTable` reservation), so no theorem states an unconditional equivalence with the model; for the iterator, T-ITER: for every input and every `k`, the `k`-th `next_frame` returns the `k`-th element of `MF(b)` (frame record and borrowed canvas, then `Some(Err)` once if `end` is an error, then `None` forever), stated over arbitrary reachable decoder states and all finite call sequences, as DIB's T7 was. T-PLAYS: `plays` equals G20 for all 65,537 inputs and `total_plays` never overflows `u32` (a short case split; the Python check is `spec-draft/check_plays.py`). Work bound T12: `steps ≤ C_WORK·(|b| + N + P) + C_FIXED` for the still call and summed over any finite sequence of iterator calls (G18: a step is a loop iteration or a filled or copied element, so a fused call costs 0; `C_FIXED = 41,984` pays once per decoder for the LZW table's 20,480-byte zero fill and other fixed work); every code costs at least 3 bits of input (2 bits under `m = 1`), every emitted index is charged to `P` whether written or clipped, disposal and restore of a (clipped) rectangle are charged to that frame's `w·h`, the `Saved` zero fill of `4·N` bytes to the `N` term of the call that reserves it, and the chain walk of one code to the indices it emits; the indices discarded under `StopAtRaster` after the raster is complete number at most `A − 1` and are charged to that frame's `w·h` (`THEOREMS.md`, L-DISCARD), not to a per-frame constant. Stress and performance test candidate: a synthetic 60×60 stream with 37,239 frames (the shape of a real full-film GIF, which fits every cap: 12.5% of `MAX_TOTAL_PIXELS`, 57% of `MAX_FRAMES`, 49,280 bytes of working memory); generate it, do not fetch or store a real film. Witnesses (`model_vectors.rs`, about 20 small gates), runtime conformance, and an implementation-side mutation campaign (below).

**P1 — Strict/RecommendedBeta.** Typed `#[non_exhaustive]` `Profile`; the 22-field record plus `loop_scan` internal and `#[cfg(test)]`-constructible; the spec-level Strict bridge `M*(Strict) = M*` for every input; RecommendedBeta's ten fields (Q1's eight, `gce_consumers=ImageOnly`, `lzw_min=Range1to11Checked`) with obligation E (E1, E4 are the only events reachable in RecommendedBeta) and obligation R in its two forms (still-accepted and stream-accepted, plus the frame-prefix form), proved as a simulation over the synchronisation points of `policy-draft/OPTIONS.md` (lemma L-CONS: nine inertness lemmas for the pure values and, for `lzw_tail=StopAtRaster`, the post-raster tail lemma L-TAIL; `THEOREMS.md` R10); T1/T3/T11/T12 universal over every record. Profile records already in `VECTORS.json` (33: 31 RecommendedBeta, 2 ImageCrateCompat-0.25.10; expected values from intent, checked through `policy_oracle.py`); extend them in the same style.

**P2 — compatibility profiles.** GdkCompat-2.42.12 (sticky Graphic Control, `GdkTable` state, `KeepCanvas`, `StopFrame`, `SkipByte`, `restore_outside=Keep`, size-0 minimum code surrogate; `loop_source=GdkAnywhere` stays a residual) and ImageCrateCompat-0.25.10 (`Streaming`, `empty_first_subblock`, unknown-extension rejection, `Transparent` indices, `loop_scan=FirstSubBlockOnly`). Opt-in, versioned, never glycin's default; frozen only after the held-out corpus comparison (Q17). ## Hardest verification obstacles

1. **LZW table and termination.** The prefix chain must be acyclic (`prefix[c] < c`) and bounded (`len ≤ 4096`) for the chain walk to terminate and its pixel writes to stay in bounds; the KwKwK entry; the deferred clear at width 12 (no entry added, width unchanged, `next = 4096` never readable as a code); the model–executable bridge from `Seq<Seq<u8>>` to three regions (prefix, suffix, length) of one 20,480-byte reservation (G18, L-TABLE-VIEW).
2. **Bit reader across sub-block boundaries.** Codes straddle sub-blocks; the reader's local state must be related to a single ghost bit position in the concatenated payload, and the structural scan that defines that concatenation runs before decoding (G9).
3. **Interlace row mapping.** A bijection over four arithmetic progressions with empty passes for small `h`; it feeds every pixel-address proof.
4. **Compositing arithmetic.** `u32` sums of `u16` coordinates (up to 131,070; the descriptor check already needs them, and `Clip` writes nothing at or beyond the edge, Q18), clipped rectangles for disposal and restore, `Saved` row strides, and a canvas-equality invariant over every position after every frame.
5. **The iterator invariant.** Decoder state (cursor, pending Graphic Control, previous frame's disposal and rectangle, `Saved`, frame and pixel counters) must equal the model's state after `k` frames for every `k`, with the fused error state; the base case is the state after the constructor's prefix walk `MP`, not after the header.
6. **Linear work with long LZW strings.** One code can emit up to 4,095 indices; the bound charges them to `P`, and `MAX_TOTAL_PIXELS` keeps `P` at most 2^30.

## Mutation candidates (implementation-side, for M5)

Widen one code early (TIFF style) or late; drop the KwKwK case; read codes MSB-first; swap interlace passes 2 and 3; skip the empty-pass adjustment for `h < 5`; fill disposal 2 with the background colour; restore the whole canvas for disposal 3; let the Graphic Control persist to the next frame; accept a duplicate Graphic Control; let a Plain Text block clear the pending Graphic Control instead of returning `UnsupportedGraphicControlTarget`; take only the first NETSCAPE2.0 sub-block in Strict; compute `total_plays` in `u16`; skip a zero first image-data sub-block and keep scanning (`empty_first_subblock=Skip` in Strict); check the colour index before the transparent index; accept `m = 9`; accept `m = 1` for a frame of two or more pixels, or test the screen's instead of the frame's `w·h`; omit `DataAfterEndOfInformation`; reserve `Saved` per frame (T3 must kill it); rescan the remaining input per code (T12 must kill it).

## Compositor in the same crate?

Yes (QUESTIONS.md Q10, decided (a)). A streaming callback interface (indices handed to a caller-supplied sink) could allow a split later without an index buffer; not planned for 0.1. Indices are written straight to the canvas through the interlace map, so the compositor and the LZW emitter share the pixel-address lemmas; three of the 22 policy fields (`frame_bounds`, `index_range`, `short_frame`) act inside the emit loop; and a split would need an index buffer of up to 16.7 megapixels and a cross-crate allocation log (as ICO needed for DIB). Keep it a separate module with its own model function (`MC`) so its proofs run after M2–M3 without reopening them.

## Effect of the decisions on the estimate

The range stays 1,600–2,400 core obligations, because the decisions add and remove work of similar size. Added: the constructor's prefix walk `MP` and its equality with the first part of `MB` (the T-ITER base case moves; perhaps 30–60 obligations); the `UnsupportedGraphicControlTarget` label check (under 10); `plays` (under 20); checked literals and sizes 2–11 in the LZW proof (a wider `m` range in T-LZW), plus the one small size-1 lemma (a one-pixel frame adds no table entry, the code width stays 2); perhaps 20–40 together. Removed or simpler: Strict no longer models Plain Text and unknown labels consuming a Graphic Control, so `gce_consumers` is a reject check rather than a second scope rule; `version` has one value; the per-side cap disappears from G3's proof, while the coordinate sums up to 131,070 were already needed for `Clip`. Partial frames (Q4) and index substitution (Q5) stay out of RecommendedBeta, so its proof keeps to error-site relaxations. The Q9 corpus pass costs runs of the oracle, not verifier runs.
