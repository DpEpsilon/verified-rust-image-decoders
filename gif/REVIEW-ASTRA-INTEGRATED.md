# Independent adversarial review of the integrated GIF proof (checkpoint 606)

Reviewer: GPT-6 Astra (read-only), 2026-11-16, on `gif/gif_verus` at run 606 (700 verified, 0 errors). Saved by the coordinator; the reviewer may not write files. Condensed by the coordinator: the findings and verdict are reproduced as reported, the long coverage list is shortened.

## Verdict

**Do not sign off on the full frozen manifest at checkpoint 606.** The reviewer found no demonstrated public-output mismatch, no reachable contradictory precondition, and no project-level `assume`/`admit`/`external_body`/`unsafe`/axiom. It found one explicit frozen storage clause that the implementation contradicts, an LZW model that does not use the independent string-table representation the manifest promises, and incomplete mandatory witness, mutation and production-allocation-audit gates. The severities concern proof sign-off, not exploitable decoder vulnerabilities. The reviewer inspected `runs/606.log` (`700 verified, 0 errors`) but did not replay Verus or bind the log to the current tree.

## Findings

1. **High: the LZW model lacks the frozen string-table representation proof** (`THEOREMS.md:71` requires an independently evolving table of strings and a representation lemma from each executable prefix chain to `model_table[c]`). `lzw_model.rs:134–147` stores prefix/suffix arrays; `:184–207` derives strings with the shared `chain::str_of`/`root_of`; `refinement.rs:23–40` relates prefix/suffix representations. The standalone `lzw_proof/src/model.rs:10–22` says the same (no string-to-arrays bridge). Concrete obligation: for `m=2` after literals 1 and 2, the abstract dictionary must independently acquire `[1,2]` and executable code 6 must denote it. Not evidence of wrong LZW semantics; the independent dictionary-semantic check is unestablished. Fix: supply the representation proof or amend the manifest.
2. **High: mandatory independent witnesses and the proof-sensitivity campaign are incomplete.** `model_vectors.rs` has six witness pairs (all still decoding). Outstanding: 356 small-record proofs, 11 large-record symbolic instantiations, iterator witnesses (for example `anim-dispose-previous-middle`), the integrated at-least-8-MiB LZW stress adapter, 26 implementation mutations (for example mutation 7: disposal 3 restores the whole canvas; mutation 20: Saved reserved for every disposal-3 frame) and the alloc-delta mutation artifacts. The six existing witnesses are meaningful (expected bytes from the frozen records, real public calls).
3. **High: the production allocation audit's trusted evidence is not established.** `tools/audit_alloc.sh:29–30` states the production call-graph audit has no GIF configuration. The signed allowlist and build-input inventory (`THEOREMS.md:190`, A-GIF-5 at `:99`) are missing. No actual extra allocation was found; the evidence for an expressly trusted boundary is missing.
4. **Medium: Saved uses screen stride, contrary to T8's rectangle stride** (`THEOREMS.md:59`: Saved rows with stride `4*w`, `w` the frame rectangle width). Save and restore (`gif.rs:1716`, `:1672`) use the full-canvas `copy_rect` (`compose_new.rs:954–965`, `:1055–1097`); `frame_model.rs:115–119` models the same layout. Counterexample: 3×2 screen, disposal-3 rectangle `(1,0,1,2)`: saved pixels at byte offsets 4 and 16 (row starts 12 bytes apart), T8 requires 4. Save and restore agree, so no visible disposal bug. Fix: change implementation and model, or approve an erratum.
5. **Medium: the encoded T-LZW entry contract is narrower than the manifest's universal domain** (`THEOREMS.md:57`). `lzw.rs:2355–2366` takes `u32` lengths and area, requires `area <= MAX_TOTAL_PIXELS`, and a fresh structurally scanned reader (`reader_ready`, `:2205–2216`). Example excluded: `m=2`, empty payload, `A = MAX_TOTAL_PIXELS+1`. Actual GIF calls establish the preconditions through G8–G9, so no hole in the public path; the integrated theorem is a reachable-domain theorem and should not be reported as the unrestricted T-LZW without a bridge or an explicit scope amendment.
6. **Medium: duplicated cap numerals defeat the frozen symbolic-cap requirement** (`THEOREMS.md:9`: cap values only in `limits.rs`, a lint rejecting copies, unchanged proofs after permitted cap changes). `model.rs:979–984` asserts `MAX_INPUT == 268435456` and uses the numeral; other proof sections hard-code current resource values. Lowering `MAX_INPUT` would make that equality false.
