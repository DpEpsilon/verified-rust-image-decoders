# GIF core theorem manifest (frozen with GIF-CORE-SPEC 1.0, 2026-11-16)

This manifest states what the GIF proof phase must prove against GIF-CORE-SPEC draft 0.2 (`spec-draft/SPEC.md`, G1–G20), which is copied unchanged to `spec-frozen/` at the M0 freeze, and, for the P rows, against policy draft 0.2 (`policy-draft/OPTIONS.md`). It has the shape of `../dib/THEOREMS.md`, `../tga/THEOREMS.md` and `../icns/THEOREMS.md`, with the fallible-allocation shape of `../alloc-delta/THEOREMS-ALLOC-DELTA.md` built in from the first line: there is no infallible entry point, so there is no retired theorem and no wrapper. One crate, `gif_verus`, `#![no_std]` with `alloc`, modules `model`, `lzw`, `parse`, `compose`, `policy`, `gif`, `alloc_guard` (`PLAN.md`, Structure). Section "Discrepancies found" at the end lists the conflicts found between the drafts, each marked Resolved (with how) or Open; the rows that depend on one name it.

No executable code, Python oracle or incumbent library may be imported into the models. The proofs hold for 32-bit and 64-bit Rust slice domains (`|b| ≤ isize::MAX` on each target). No `assume`, `admit`, `external_body`, trusted FFI, `unsafe`, false precondition, new `assume_specification` or ghost claim disconnected from a concrete call establishes any obligation. Each proof report states the verifier, vstd, rustc and Verus versions. Allocation failure is **inside** the guarantee: it is the result `Err(OutOfMemory(o))`, related to the sealed log by `G` (below); only allocator behaviour itself, the trusted items of the last section, and compiler or verifier unsoundness are outside it.

## Constants

Every resource cap is written by its G1 name and by no numeral: `MAX_INPUT`, `MAX_DIMENSION`, `MAX_OUTPUT`, `MAX_FRAMES`, `MAX_TOTAL_PIXELS`. Their values live only in G1's limits table and, in the crate, only in `limits.rs`; a source lint (M1) fails on any of the five values written elsewhere in `src/`. A cap change is one edit to G1 and one to `limits.rs`, and every theorem below is unchanged by it, provided the new values keep the derived facts G1 lists (`MAX_DIMENSION ≤` the LE16 wire limit, `MAX_OUTPUT ≤` the guard's `MAX_BYTES` (67,108,864 today, so `MAX_OUTPUT` is held at 64 MiB; the owner intends to raise both later as a strict widening, via an alloc-delta erratum with re-verification of every core, the audit and new guard hashes, 2026-11-16; see `../RELEASE-GATES.md`), `4·N ≤ MAX_OUTPUT` fitting `u32` once checked, and the unchecked quantities `4·MAX_DIMENSION²` and `MAX_TOTAL_PIXELS + MAX_DIMENSION²` fitting `u64`; lemma `area_cap_u64`).

Two format constants of Appendix F are not caps and are named here: `LZW_CODES` (the table size of G10.2 steps 6–7, 4096) and `LZW_MAX_WIDTH` (12). G18 names two more: `LZW_TABLE_BYTES = 4096·(2 + 1 + 2) = 20,480`, the one `LzwTable` request, and `C_FIXED = 2·LZW_TABLE_BYTES + 1,024 = 41,984`, the once-per-decoder additive work constant (D5). Two work constants are fixed by this manifest, as G18 delegates: `C_CALL = 32` and `C_WORK = 2·C_CALL = 64` (T12; adequate for every `m`, RecommendedBeta's `m` up to 11 included, because the LZW core decides literal codes by rule and does no per-frame table initialisation, D20).

Notation: `N = W·H` when `MH(b)` succeeds and 0 otherwise; for the frame with index `k` (zero-based, in stream order) `A_k = w_k·h_k` from its descriptor; `P` is the sum of `A_k` over the frames whose walk reaches G10 (G18). `STRICT` is the record whose 22 fields and `loop_scan` take the bold values of `OPTIONS.md`; `RB` is RecommendedBeta's record.

## Total mathematical models

Each model is the named spec section transcribed in `model.rs` independently of the executable; this manifest does not restate the sections. Every model is total over finite byte sequences and natural numbers; on arguments outside a reachable domain it returns the internal marker `OutsideDomain`, which is not a 34th error. Model errors are exactly G16's 33 names. Arithmetic is on mathematical integers; every guarded read checks availability first (Conventions).

**Step accounting** (G18, Work; D7). Every concrete loop body increments a ghost `steps: nat` by one per iteration, and each library or guard call that fills or copies `k` elements adds `k`; straight-line code adds nothing, so a call on a fused decoder, which runs no loop, adds 0. For iterator call number `n` (`n = 0` is the first `next_frame`), `cur_n` is the model walk cursor after the call (`|b|` if the call ends in an error), `cur_{−1}` is the constructor's final cursor, and `Δ_n = cur_n − cur_{n−1}`.

## Allocation shape (alloc-delta §0, unchanged definitions)

`fmt_part`, `L`, `req(L)`, `G(f, Eq_f, Req)` (clauses 1–3), `log_tied`, `Prog` and `PreAlloc` are exactly as in `THEOREMS-ALLOC-DELTA.md` §0. `AllocSite = Canvas | LzwTable | Saved`. Every request is a byte-counted `try_zeroed(site, n)` of the hash-pinned guard, so no guard text or admitted audit type changes. Per-site maxima (clause 3): `Canvas` and `Saved` at most `MAX_OUTPUT` bytes, `LzwTable` exactly `LZW_TABLE_BYTES`. `ReqLzw = [(LzwTable, LZW_TABLE_BYTES)]` = `[(LzwTable, 20,480)]` (G18, D4): one reservation, which the decoder views as prefix codes (LE16 pairs, bytes `[0, 8192)`), suffix bytes (`[8192, 12288)`) and string lengths (LE16 pairs, `[12288, 20480)`), 4,096 each.

- `Req_still(b) = Req_new(b) = if MH(b) is Ok then [(Canvas, 4·N)] ++ ReqLzw else []`, for every record `p` (`MH_p = MH`, lemma L-MHP).
- `Req_next_p(b, n) = [(Saved, 4·N)]` if `SavedAt_p(b) = Some(n)`, else `[]`.
- `Eq_still(b, r)`: `fmt_part(r)` equals `MS(b)` byte for byte (`still_eq`). `Eq_still_p(b, r)`: equals `MS_p(b)` including `recovered`. `Eq_new_p(b, r)`: `fmt_part(r)` is `Err(e)` iff `MP_p(b) = Err(e)`, and otherwise the decoder satisfies `wf_p(b, −1)` with `info() = MF_p(b).info`.
- Iterator log. `Frames::try_new_logged` and `Frames::try_new_with_policy_logged` create the log with `new_log()` and, on success, move it into the decoder as a `Tracked<AllocLog>` field; `dec.log_view()` is a closed spec function. This is an extension of alloc-delta's shape, which returns the log from a single call (D9; `REVIEW-BRIEF.md` makes its strength a review focus).

### T-LZW sub-obligations (M2)

- Code-level functions (R11). The table invariants are stated over functions of the code, defined from L-TABLE-VIEW's raw storage accessors `prefix`, `suffix` and `stored_length` and from `m`, never over a raw accessor applied to a literal code. With `clear = 2^m`: `code_length(t, m, c) = if c < clear then 1 else stored_length(t, c)`; `code_suffix(t, m, c) = if c < clear then c else suffix(t, c)`; `code_first(t, m, c) = if c < clear then c else code_first(t, m, prefix(t, c))` (well founded by the invariant `prefix(t, c) < c`); `chain(t, m, c) = if c < clear then [c] else chain(t, m, prefix(t, c)) ++ [suffix(t, c)]`. They are used only for `c < clear` and `c ∈ [clear + 2, next)`. A literal code's facts come from the code value by rule: the executable reads no table byte for it, and its stored bytes are unspecified (zero after `try_zeroed`, stale once an earlier frame with a smaller `m` wrote an entry there; the same holds for the entries at or above `next`, left from before a Clear or from an earlier frame), so `stored_length(t, c)` of a literal code is not 1 in general. Example: in an `m = 2` frame whose first two codes are the literals 1 and 2, code 6 gets the string `[1, 2]` with prefix 1, so `stored_length(t, 6)` must be `code_length(t, 2, 1) + 1 = 2`, whereas `stored_length(t, 1) + 1 = 1` from the zero-filled storage.
- Table invariant, for every code `c ∈ [clear+2, next)`: `prefix(t, c) < c` and `prefix(t, c) ∉ {clear, clear + 1}`; `stored_length(t, c) = code_length(t, m, prefix(t, c)) + 1 ≤ LZW_CODES`, so `code_length(t, m, c) = code_length(t, m, prefix(t, c)) + 1`; code `c < clear` denotes the literal string `[c]` by rule, the table holds entries only for codes `≥ clear + 2`, and a chain walk ends at the first code below `clear` (D20; there is no per-frame initialisation of literal entries, and the table storage is the one `try_zeroed(LzwTable, LZW_TABLE_BYTES)` region). Under `RB` with `m ≥ 9`, every literal reached by a chain walk is below 256, because a literal code `≥ 256` is `ColorIndexOutOfRange` when read (T4) and so never becomes `prev` or a prefix; hence `code_suffix` and `code_first` are byte values for every `m`. Representation lemma: for every code `c` in the union domain `c < clear ∨ clear + 2 ≤ c < next` (literal codes and valid dictionary entries; the two sets are disjoint, and codes `clear` and `clear + 1` are not in the domain), `chain(t, m, c) = model_table[c]`, `|model_table[c]| = code_length(t, m, c)` and `model_table[c][0] = code_first(t, m, c)` (the model holds strings; the executable holds prefix links, suffixes and stored lengths, and walks a code's chain last index first, placing each index at its pixel position, so `code_first` is the end of the chain).
- Index bounds: every table index is `< LZW_CODES`; every byte offset into the table reservation is `< LZW_TABLE_BYTES`; a chain walk takes `code_length(t, m, c) ≤ LZW_CODES` steps and every position it writes is `< A` (positions `≥ A` give `TooManyPixels` or, under `StopAtRaster`, are discarded, in G10.2's forward order); `next = LZW_CODES` is never readable as a code (G10.2 step 6).
- Width lemma: `next < 2^width ∨ width = LZW_MAX_WIDTH` for `m ≥ 2`; widening exactly at `next = 2^width ∧ width < LZW_MAX_WIDTH`.
- KwKwK: `code = next ∧ prev ≠ none ∧ next < LZW_CODES` yields `prev + first(prev)` before the entry is materialised.
- L-FULL (deferred clear): from any reachable state with `next = LZW_CODES`, a non-Clear, non-EOI code `< LZW_CODES` adds no entry and leaves `width = LZW_MAX_WIDTH` until a Clear.
- Size-1 lemma (`RB`, `m = 1`, `A = 1`): `prev = none` when the first literal is read, so no entry is added, `next` stays `2^(m+1)`, `width` stays 2, and the loop returns at the raster after at most one literal (`lzw_tail=StopAtRaster`).
- Termination by `8·|D| − pos` (T11).
- Policy forms (P1): `ML_p` for `lzw_tail ∈ {Strict, StopAtRaster}`, `lzw_min ∈ {Spec, Range1to11Checked}`, with the E4 event exactly when the raster-completing code carries indices past `A`; and lemma L-TAIL (below), which P-R needs for `lzw_tail=StopAtRaster`.

### T-ITER (M5; P1 for every record)

Fix `b`, a record `p`, and `F = MF_p(b)` with `n_F = |F.frames|`. `wf_p(b, n)` is the decoder invariant relating the concrete state (cursor, pending Graphic Control, previous frame's disposal and rectangle, `Saved`, `k`, `T`, canvas, fused flag, log) to the model state after `n + 1` calls (`n = −1` after the constructor). `next_frame` requires only `wf_p(b, n)` for some `n` and ensures `wf_p(b, n + 1)` and the result below; `info()` is pure. Therefore, for every reachable decoder state and every finite call sequence, with no earlier call having returned `OutOfMemory`, call `n` returns:

### Named lemmas

- L-MHP: `MH_p(b) = MH(b)` for every record (`version` has the one value `Known`).
- L-INTERLEAVE (G10.2 last paragraph, G12.2): with `(idx, out, pos) = ML(m, D, A)`, the frame's draw outcome is `Err(ColorIndexOutOfRange)` if some `idx[j]` is non-transparent and `≥ C`, and otherwise `out`; the first such `j` is where drawing stops.
- L-PREFIX (G14, D3): if `MS(b) = Ok(s)`, `t` is the cursor after the first image's block terminator, and `b'` agrees with `b` on `[0, t)` with `|b'| ≤ MAX_INPUT`, then `MS(b') = Ok(s)`. (The premise `MS(b) = Ok` is needed: a stream with no image gives `NoImage` alone and `TrailingBytes` with bytes appended, and an error that depends on `|b|` changes with the length.)
- L-CODE: each code read consumes at least `min(3, m + 1)` bits of `D`, so codes per frame `≤ 8·|D|/2`.
- L-CHAIN: the chain walk of a code costs at most the length of its string, which is at most `q + 1` for `q` indices already emitted in the frame.
- L-TABLE-VIEW (G18, D4, R11): the raw storage accessors `prefix(t, c) = t[2c] + 256·t[2c+1]`, `suffix(t, c) = t[8192 + c]` and `stored_length(t, c) = t[12288 + 2c] + 256·t[12288 + 2c + 1]` over the 20,480-byte reservation `t`, for every `c < LZW_CODES` (literal codes included, whose stored bytes are unspecified); each exec setter changes only its own region and only its own code's bytes, so the other two accessors are unchanged for every code and the same accessor is unchanged for every other code. Proved once over the raw accessors. The T-LZW invariants are stated over the code-level functions `code_length`, `code_suffix`, `code_first` and `chain` (T-LZW sub-obligations), which read these accessors only for codes `≥ clear + 2`.
- L-TAIL (G10.2, R10): the post-raster tail of a frame is the sequence of G10.2 iterations from the first one that begins with `q = A` to the end of the loop. If Strict's tail ends without error, its codes are `Clear^j` then `eoi` for some `j ≥ 0` (step 4 rejects any other code at `q = A`, step 1 rejects running out of bits, and step 5 rejects a whole byte after the `eoi`, so only padding bits of the `eoi`'s last byte follow); a Clear iteration changes only `pos`, `next`, `width` and `prev` (step 3), the `eoi` iteration only `pos`; no iteration reaches step 8, so the tail emits no index, writes no canvas cell, makes no colour check (G12.2) and raises no event. Hence the frame's canvas, record and walk state at S3 are those at raster completion, whatever the tail. `lzw_tail=StopAtRaster` returns at the tail's first iteration without reading a code.
- L-DISCARD: under `StopAtRaster`, the indices discarded by the raster-completing code number at most `A − 1` (from L-CHAIN: length `≤ q + 1` with `q ≤ A − 1`), so their cost is inside `A`.
- L-BUDGET: from every reachable walk state with `T + w·h > MAX_TOTAL_PIXELS` whose earlier G8 checks pass, `MB` returns `PixelBudgetExceeded` (no vector; G17).
- Arithmetic lemmas, stated as explicit facts: `area_cap_u64` (symbolic in the caps: for `W, H, w, h ≤ MAX_DIMENSION` and `T ≤ MAX_TOTAL_PIXELS`, `4·W·H ≤ 4·MAX_DIMENSION² < 2^64` and `T + w·h ≤ MAX_TOTAL_PIXELS + MAX_DIMENSION² < 2^64`, so the `u64` products and sums that the `OutputTooLarge` and `PixelBudgetExceeded` checks compare equal the mathematical values; no `u32` intermediate occurs before either check, since `4·MAX_DIMENSION²` exceeds `u32::MAX`), `product_dimension_bound` (`W·H ≤ MAX_OUTPUT/4`, after the check), `canvas_offset_bound`, `rect_sum_unnarrowed` (`left + w ≤ 2·MAX_DIMENSION`), `interlace_pass_sizes` (`⌈(h − s)/k⌉`), `interlace_bijection`, `saved_row_offset_bound`, `lzw_width_bound`, `pixel_budget_monotone` (`T ≤ MAX_TOTAL_PIXELS` invariant), `total_plays_u32`.

- **R10** (high) Resolved. RecommendedBeta did not satisfy the definition of a conservative record it was declared under.
