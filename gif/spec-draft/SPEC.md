# GIF decoder core

GIF-CORE-SPEC draft 0.2 (not frozen). Draft 0.2 applies the owner's decisions on `../policy-draft/QUESTIONS.md` (cited Q*n*; changelog in `../DECISIONS.md`). Source text: GIF89a, CompuServe, 31 July 1990, copy in `sources/spec-gif89a.txt` (cited as §*n* of that document; this spec's own sections are G*n*). Reference model: `gif_oracle.py`; every function there names the G section it implements. Vectors: `VECTORS.json` (G17), generated by `gen_vectors.py`, checked by `check_vectors.py`.

Scope. This core (the Strict profile) specifies **the supported GIF subset, not complete GIF89a**. Where GIF89a defines a construct the core does not implement, the core returns a named error for it rather than guess: a Graphic Control Extension aimed at a Plain Text or unknown graphic-rendering block (G7, `UnsupportedGraphicControlTarget`) is the one such construct. Such an error marks an unsupported file, not a malformed one.

Conventions. Offsets are zero-based; ranges half-open. LE16 is an unsigned little-endian 16-bit word. All arithmetic is on mathematical integers before any checked narrowing. "Require *n* bytes at *p*, else E" means: if `p+n > |b|`, return error E without reading. RGBA8 output is tightly packed, non-premultiplied, left to right, top row first; every alpha value is 0 or 255.

## G1. Entry points, records and limits

**Limits.** Every resource cap is one named constant in this table and nowhere else; the theorems (`../PLAN.md`) are stated over these names, so a cap changes by editing one line (Q8).

| Constant | Value | Bounds |
|---|---|---|
| `MAX_INPUT` | 67,108,864 (64 MiB) | input bytes (G2) |
| `MAX_DIMENSION` | 65,535 | screen width and height (G3); equal to the LE16 wire limit, so it adds no separate per-side cap |
| `MAX_OUTPUT` | 67,108,864 (64 MiB) | `4·W·H`, bytes of one RGBA8 canvas (16,777,216 pixels) |
| `MAX_FRAMES` | 65,536 | image descriptors per stream (G8) |
| `MAX_TOTAL_PIXELS` | 2^30 | sum of `w·h` over the image descriptors processed (G8) |

Derived bounds used by the proofs: every coordinate and size field is at most 65,535, so `left + w` and `top + h` are at most 131,070 and are computed without narrowing (G8, and the clipped rectangles of `../policy-draft`); a canvas offset `4·(y·W + x)` with `x < W`, `y < H` is below `MAX_OUTPUT`. All arithmetic on these fields is specified for the full range 0–65,535, not only for values below a smaller cap.

Two entry points share one stream walk (G5–G12):

- `decode_still(b)` returns `Ok(Still{width, height, rgba})` or `Err(e)`. `rgba` is the logical screen after the first image is drawn (G14).
- `decode_frames(b)` returns `Err(e)` for an error in G2–G4 or in the block walk before the first image descriptor, otherwise `Frames{info, frames, end}`: `frames` is the sequence of frame records in stream order and `end` is `Trailer` or `Err(e)`, the first error after the last returned frame (G15). The executable form (Q2) is a constructor that performs that prefix walk, so that `info` already holds the loop count found before the first image, and a frame method whose *k*-th call returns `frames[k]` as a view borrowed from the decoder (the whole canvas plus the frame's fields; one canvas is reused, no per-frame allocation), then `Err(e)` once if `end` is an error, then nothing on every later call (fused).
- `plays(loop_count)` interprets `Info.loop_count` (G20).

`Info = {width, height, version: "87a"|"89a", background_index: u8, aspect: u8, loop_count: Option<u16>}`. `loop_count` is the raw NETSCAPE2.0 value found before the first image descriptor (G6.3) and is the normative field; `plays` (G20) is its documented meaning. A frame record is `{rgba (4·W·H bytes, the whole canvas after drawing), rect: (left, top, width, height), delay_cs: u16, disposal: 0..3, user_input: bool, transparent: Option<u8>, interlaced: bool}`. `delay_cs` is the raw Graphic Control value in hundredths of a second; mapping 0 or small delays to a display delay is a presentation policy outside this core (`../policy-draft/OPTIONS.md`, `delay_map`).

## G2. Header

Test `|b| > MAX_INPUT` first: `FileTooLarge`. Require 13 bytes at 0 (Header plus Logical Screen Descriptor), else `TruncatedHeader`. Bytes `[0:3]` must be `GIF`, else `BadSignature`. Bytes `[3:6]` must be `87a` or `89a` (case-sensitive), else `UnsupportedVersion` (§17; §17.d.ii's advice to attempt unknown versions is not followed in any profile, Q12). The version does not gate any later rule: a GIF87a stream's Graphic Control Extension applies exactly as in 89a (DESIGN-NOTES N3).

## G3. Logical Screen Descriptor (§18)

`W = LE16(6)`, `H = LE16(8)`, packed byte `F = b[10]`, `background_index = b[11]`, `aspect = b[12]`. Require `1 ≤ W ≤ MAX_DIMENSION` and `1 ≤ H ≤ MAX_DIMENSION`, else `InvalidDimensions` (with `MAX_DIMENSION = 65,535` only zero fails); then `4·W·H ≤ MAX_OUTPUT`, else `OutputTooLarge`. Global table flag `F & 0x80`; table size field `F & 7`. Colour resolution (`F>>4 & 7`), sort flag (`F & 0x08`), background index and aspect ratio change no pixel and are not validated (N1, N2).

## G4. Global Color Table (§19)

If the flag is set, the table is `3·2^((F&7)+1)` bytes of R,G,B triples at 13: require them, else `TruncatedColorTable`. The cursor `p` is then 13 plus the table length. A stream without a global table is valid.

## G5. Block loop and data sub-blocks (§15, §16, §27, Appendix B)

State: pending Graphic Control `gce` (none), frames seen `k = 0`, pixel total `T = 0`, `loop_count` none. At cursor `p`:

1. `p = |b|`: `MissingTrailer`.
2. `b[p] = 0x3B` (Trailer): if `gce` is pending, `GraphicControlWithoutGraphic`; if `p+1 < |b|`, `TrailingBytes`; otherwise the stream ends with `Trailer`.
3. `b[p] = 0x21`: extension, G6.
4. `b[p] = 0x2C`: image, G8–G12.
5. Any other byte: `UnknownBlock`.

A *sub-block sequence* starting at `q` is read as: require 1 byte at `q` (size `n`); `n = 0` is the block terminator and ends the sequence; otherwise require `n` bytes after the size byte and continue at `q+1+n`. The caller supplies the error name for a missing byte. A size byte of 0 always terminates, including as the first sub-block of image data (N10).

## G6. Extensions (§23–§26)

Require 2 bytes at `p` (introducer and label), else `TruncatedExtension`. Let `L = b[p+1]`, `q = p+2`. If `L ≤ 0x7F` and a `gce` is pending: `UnsupportedGraphicControlTarget` (G7). This check precedes every other check of the extension.

**G6.1 Graphic Control (L = 0xF9).** If `gce` is pending: `DuplicateGraphicControl` (§23.a: at most one per graphic). Require 1 byte at `q`, else `TruncatedExtension`; it must be 4, else `InvalidGraphicControl`. Require 6 bytes at `q`, else `TruncatedExtension`; `b[q+5]` must be 0 (the extension has exactly one data sub-block), else `InvalidGraphicControl`. Packed `G = b[q+1]`: disposal `(G>>2) & 7`, which must be at most 3, else `UndefinedDisposal` (§23.c.iv: 4–7 "to be defined"); user input `G & 2`; transparency flag `G & 1`; reserved bits `G>>5` ignored (N1). `delay_cs = LE16(q+2)`; transparent index `b[q+4]` if the flag is set, else none (the byte is then ignored). The record becomes the pending `gce`; continue at `q+6`.

**G6.2 Plain Text (L = 0x01).** Require 1 byte at `q`; it must be 12, else `InvalidPlainText`. Require 13 bytes at `q`, then read the sub-block sequence at `q+13` (errors `TruncatedExtension`). Reached only with no `gce` pending (G6, G7). It is not rendered (N4, Q7), and its grid and colour indices are not validated.

**G6.3 Application (L = 0xFF).** Require 1 byte at `q`; it must be 11, else `InvalidApplicationExtension`. Require 12 bytes at `q`; the identifier and authentication code are `b[q+1:q+12]`. Read the sub-block sequence at `q+12`. If the 11 bytes equal `NETSCAPE2.0` and no image descriptor has been seen (`k = 0`), every data sub-block of the extension is examined, and each one of exactly 3 bytes whose first byte is 1 sets `loop_count = LE16` of its last two bytes (the last such sub-block wins; Q15 rule A, N11). Other sub-blocks (for example the 5-byte buffering sub-block with first byte 2) and every other application, including `ANIMEXTS1.0`, `XMP DataXMP` and `ICCRGBG1012`, are skipped (Q14, Q15).

**G6.4 Comment (L = 0xFE) and unknown labels.** Read the sub-block sequence at `q`. A Comment is skipped (§24: "may be ignored by the decoder"). An unknown label is skipped (§12, Appendix D). An unknown label `≤ 0x7F` falls in the graphic-rendering range of §12; it is skipped when no `gce` is pending and otherwise rejected before it is read (G6, G7, N5).

## G7. Scope of the Graphic Control Extension (§12, §23.d)

§23.d applies a Graphic Control Extension to the next graphic-rendering block, which may be an image, a Plain Text Extension or an unknown block with label `0x00–0x7F`. This core supports only the first: a pending `gce` applies to the next image descriptor (G8). If, before that descriptor, the walk meets a Plain Text Extension or an unknown extension with label `≤ 0x7F`, the stream is outside the supported subset and the walk returns `UnsupportedGraphicControlTarget` at that block's label (G6; Q7, N16). Comment and Application extensions and unknown labels `0x80–0xF8` do not affect a pending `gce`; Plain Text and unknown labels `0x00–0x7F` with no `gce` pending are skipped. An image without a pending `gce` uses delay 0, disposal 0, no user input, no transparent index.

## G8. Image Descriptor and Local Color Table (§20, §21)

If `k = MAX_FRAMES`: `TooManyFrames`. Require 10 bytes at `p` (separator plus nine bytes), else `TruncatedImageDescriptor`. `left = LE16(p+1)`, `top = LE16(p+3)`, `w = LE16(p+5)`, `h = LE16(p+7)`, packed `I = b[p+9]`. Then, in order:

- `w = 0` or `h = 0`: `InvalidFrameDimensions`.
- `left + w > W` or `top + h > H` (sums up to 131,070, compared without narrowing): `FrameOutsideScreen` (§20.a: "Each image must fit within the boundaries of the Logical Screen").
- `T + w·h > MAX_TOTAL_PIXELS`: `PixelBudgetExceeded`.
- Local table flag `I & 0x80`: the table is `3·2^((I&7)+1)` bytes at `p+10` (§21; §20.c.ix's "raise 2 to the value of the field" omits the `+1` and is not followed, N6); require them, else `TruncatedColorTable`. The active table is the local table if present, else the global table; if neither exists, `NoColorTable` (§11 permits a decoder-chosen table; this core does not invent colours, Q11).

Interlace flag `I & 0x40`; sort flag `I & 0x20` and reserved bits `I & 0x18` are ignored. Let `A = w·h` and `C` the active table's entry count.

## G9. Image data structure (§22)

Require 1 byte (the LZW minimum code size `m`), else `TruncatedImageData`. Require `2 ≤ m ≤ 8`, else `InvalidLzwMinCodeSize` (Appendix F: indices are at most 8 bits and a one-bit image uses code size 2). Strict keeps this range; RecommendedBeta accepts 2–11 with literal codes above 255 rejected, and `m = 1` only when the frame descriptor's `w·h = 1`; a larger frame with `m = 1` is `InvalidLzwMinCodeSize`, decided here before the sub-blocks are read (Q6, `lzw_min` in `../policy-draft/OPTIONS.md`). Read the sub-block sequence after `m` (errors `TruncatedImageData`); `D` is the concatenation of its payloads. The whole sequence is read before any code is decoded, so a structural or truncation error inside the image data precedes every LZW and colour error of that image (N7). Record `gce` for this frame, clear the pending `gce`, set `k ← k+1` and `T ← T + A`.

## G10. Variable-length-code LZW (Appendix F)

Codes are read from `D` least-significant bit first: code *i* occupies the next `width` bits of the bit string in which bit *j* of byte *n* has position `8n+j`. `clear = 2^m`, `eoi = clear+1`.

**G10.1 State.** The table maps codes to index strings: codes `0..clear-1` are the single indices `[c]`; `clear` and `eoi` have no string. `next = clear+2`, `width = m+1`, `prev = none` (no previous string), pixel count `q = 0`. The stream may start without a Clear code (Appendix F says encoders *should* emit one; N8).

**G10.2 Loop.** Repeat:

1. If fewer than `width` bits remain in `D`: `TooFewPixels` if `q < A`, else `MissingEndOfInformation`.
2. Read `code` (`width` bits).
3. `code = clear`: reset `next = clear+2`, `width = m+1`, `prev = none`; continue.
4. If `q = A` and `code ≠ eoi`: `MissingEndOfInformation` (after the last pixel only Clear codes and then the End of Information code may follow).
5. `code = eoi`: if `q < A`, `TooFewPixels`. Otherwise let `e` be the bit position after this code; if `ceil(e/8) < |D|`, `DataAfterEndOfInformation` (whole bytes after the one holding the code's last bit; the padding bits of that byte are ignored). Otherwise the image data is complete.
6. Determine the string `s`: if `code < next` (and is not `clear`/`eoi`), `s` is the table entry; if `code = next`, `prev ≠ none` and `next < 4096`, `s = prev + first(prev)` (the KwKwK case); otherwise `InvalidLzwCode`. In particular the first code after a Clear (or at the start) must be a literal.
7. If `prev ≠ none` and `next < 4096`: add entry `next = prev + first(s)`, `next ← next+1`; then if `next = 2^width` and `width < 12`, `width ← width+1`. When `next = 4096` the table is full: no entry is added and `width` stays 12 until a Clear (the "deferred clear"; N9).
8. `prev ← s`. Emit each index of `s` in order at pixel positions `q, q+1, …` (G12.2); if a position reaches `A` while indices of `s` remain, `TooManyPixels`.

Errors are reported in this loop order, interleaved with the per-pixel colour check of G12.2. The loop terminates because every iteration consumes `width ≥ 3` bits of the finite `D` or returns.

## G11. Interlace (§20.c.vii, Appendix E)

For a non-interlaced image, stream row `r` (pixels `r·w … r·w+w-1`) is image row `r`. For an interlaced image the stream rows are, in order, the image rows `0, 8, 16, …`, then `4, 12, …`, then `2, 6, 10, …`, then `1, 3, 5, …`, each pass taking every row of its residue class below `h`; a pass is empty when its starting row is `≥ h`. `interlace_row(r, h)` is the image row of stream row `r`; it is a bijection on `[0, h)` for every `h ≥ 1`.

## G12. Compositing

**G12.1 Canvas.** Before the first frame the canvas is `W·H` pixels of `(0,0,0,0)`. The background colour index is not used (N2).

**G12.2 Drawing.** Before drawing frame *k*, apply the disposal of frame *k−1* (G12.3). If frame *k*'s disposal is 3, save the canvas pixels of its rectangle. Then for each emitted index `v` at pixel position `q`: if `v` equals the frame's transparent index, the canvas pixel is unchanged; otherwise require `v < C`, else `ColorIndexOutOfRange`, and set canvas pixel `(left + q mod w, top + interlace_row(⌊q/w⌋, h))` (or `top + ⌊q/w⌋` without interlace) to `(R, G, B, 255)` from entry `v`. A transparent index `≥ C` is permitted; such pixels are never looked up. The frame record's `rgba` is the canvas after its last pixel.

**G12.3 Disposal (§23.c.iv).** Disposal 0 and 1 leave the canvas. Disposal 2 sets every pixel of the frame's rectangle to `(0,0,0,0)` (N2). Disposal 3 restores the pixels saved in G12.2. The last frame's disposal is never applied.

**G12.4 Errors inside a frame.** An error in G8–G12 discards all of that frame's writes; no partially drawn frame is ever returned, and the canvas of the last returned frame is unchanged.

## G13. Metadata exposed

`Info` (G1) and the per-frame fields of G1. Comment text, Plain Text content, XMP and ICC application data are parsed for structure only and not exposed by release 0.1 of the crate (Q14). The RGBA output is untransformed: colour-table values copied as stored, with no colour management, gamma or ICC profile applied, and no premultiplication. Pixel aspect ratio is exposed raw and never applied.

## G14. `decode_still`

Run G2–G12 until the first image's sub-block terminator has been read and the frame drawn; return `Still{W, H, rgba of that frame}`. Bytes after that terminator are not examined (Q3): trailing garbage, a missing trailer and errors in later frames do not affect the result. If the walk reaches the Trailer before any image, return `NoImage`. Errors before the first image is complete are returned as found.

**Strict-accepted (still).** `b` is Strict-accepted for the still entry point iff `decode_still(b)` returns `Ok`. This depends only on the bytes up to the first image's block terminator. Obligation R for this entry point (`../policy-draft/OPTIONS.md`): every profile returns the identical `Still` with `recovered = false`.

## G15. `decode_frames`

Return `Err(e)` for the first error of G2–G4 or of the block walk G5–G7 before the cursor first reaches an image separator `0x2C` (the constructor's prefix walk; it fixes `loop_count`). Otherwise continue the walk; every image that completes G8–G12 appends a frame record; the first error after that (or `Trailer`) is `end`. An error inside the first image descriptor or its data is therefore `end` with zero frames, not a constructor error. A stream with no image and a valid Trailer returns zero frames and `end = Trailer` (§11 permits a stream that only loads a colour table).

**Strict-accepted (stream).** `b` is Strict-accepted as a whole stream iff `decode_frames(b)` returns `Frames` with `end = Trailer`. A stream-accepted input is still-accepted unless it has no image; the converse fails (a damaged second frame). Obligation R for this entry point: every profile returns the identical `Info`, the identical frame records with `recovered = false` on each, and `end = Trailer`. Its prefix form also holds: every frame Strict returns before an error is returned identically, with `recovered = false`.

## G16. Errors

The closed, case-sensitive error set (33 names): `FileTooLarge`, `TruncatedHeader`, `BadSignature`, `UnsupportedVersion`, `InvalidDimensions`, `OutputTooLarge`, `TruncatedColorTable`, `MissingTrailer`, `UnknownBlock`, `TruncatedExtension`, `DuplicateGraphicControl`, `InvalidGraphicControl`, `UndefinedDisposal`, `InvalidApplicationExtension`, `InvalidPlainText`, `GraphicControlWithoutGraphic`, `TooManyFrames`, `TruncatedImageDescriptor`, `InvalidFrameDimensions`, `FrameOutsideScreen`, `PixelBudgetExceeded`, `NoColorTable`, `TruncatedImageData`, `InvalidLzwMinCodeSize`, `InvalidLzwCode`, `TooManyPixels`, `TooFewPixels`, `MissingEndOfInformation`, `DataAfterEndOfInformation`, `ColorIndexOutOfRange`, `TrailingBytes`, `NoImage`, `UnsupportedGraphicControlTarget`. `NoImage` is returned only by `decode_still`. `UnsupportedGraphicControlTarget` names an unsupported construct, not a malformed stream (G7). Allocation failure is not in this set (G18).

Precedence is operational: the first check that fails in the order written in G2–G12, walking the stream once. Restated: `FileTooLarge`, `TruncatedHeader`, `BadSignature`, `UnsupportedVersion`, `InvalidDimensions`, `OutputTooLarge`, `TruncatedColorTable`; then per block in stream order. Within an extension: `TruncatedExtension` for the label, `UnsupportedGraphicControlTarget`, `DuplicateGraphicControl`, size-byte presence, size value, body presence, terminator value, `UndefinedDisposal`. Within an image: `TooManyFrames`, `TruncatedImageDescriptor`, `InvalidFrameDimensions`, `FrameOutsideScreen`, `PixelBudgetExceeded`, `TruncatedColorTable`, `NoColorTable`, `TruncatedImageData` (minimum code size byte), `InvalidLzwMinCodeSize`, `TruncatedImageData` (sub-blocks), then the G10.2/G12.2 loop errors in code and pixel order. At the Trailer: `GraphicControlWithoutGraphic`, then `TrailingBytes`. No partial result or second error is exposed by `decode_still`; `decode_frames` exposes the completed frames and one error.

## G17. Vectors

`VECTORS.json` is an array of `{name, entry, input_hex, expected}` with `entry ∈ {still, frames, plays}`, and an optional `profile` naming a policy profile (`../policy-draft/OPTIONS.md`); a record without `profile` is a Strict (core) record. Optional input expansion: `pad_to: n` appends zero bytes up to length `n`; `repeat_hex`, `repeat`, `suffix_hex` form `input_hex + repeat_hex×repeat + suffix_hex`. Expectations: `{error}`; a still success `{width, height, rgba_runs}`; a frames success `{width, height, loop_count, frames: [{rect, delay_cs, disposal, user_input, transparent, interlaced, rgba_runs}], end}` with `end` either `"trailer"` or `{error}`; or a summary `{summary: true, width, height, frame_count, last_rgba_runs, end}` for the 65,536-frame records; a `plays` record expects `{loop_count, plays, total_plays}` from `decode_frames` followed by G20 (`plays` is `"Once"`, `"Forever"` or `{"Repeats": n}`, `total_plays` an integer or null). Profile records add `recovered` to the still result and to each frame. `rgba_runs` are maximal runs `{count, hex}` of RGBA8 pixels in top-first order (eight lowercase hex digits). Expectations are written from the generator's intent (the index raster it encoded, a drawn canvas, or a named error), not computed by the oracle. 360 records (340 Strict, 20 profile); `check_vectors.py` reports agreement and which errors the Strict records exercise (32 of 33), and `check_plays.py` checks G20 exhaustively over its 65,537 inputs. The wire-maximum records (65,535×1, 1×65,535 interlaced, 32,768×100, a 131,070 coordinate sum) exercise the G1 arithmetic at 65,535. `PixelBudgetExceeded` has no vector (a witness needs about 10⁹ decoded pixels); it is left to a symbolic lemma, as DIB's 64 MiB boundaries were.

## G18. Resource and safety contract (for the implementation)

Input is borrowed. Before any reservation, G2–G4 hold and `4·W·H ≤ MAX_OUTPUT`. Reservations, all through the `alloc_guard` of `../../alloc-delta/SPEC.md` (no aborting allocation in the main crate):

| Site | Size | When |
|---|---|---|
| `Canvas` | `4·W·H` bytes, zero-filled | `decode_still` and the iterator constructor, after G2–G4 and before the constructor's prefix walk (G15), so `Req` does not depend on blocks after the header |
| `LzwTable` | one fixed record: 4096 prefix codes (`u16`), 4096 suffix bytes, 4096 first bytes, a 4096-byte string stack (20,480 bytes) | same call, after `Canvas` |
| `Saved` | `4·W·H` bytes | the first frame whose disposal is 3, once per decoder |

So `Req(still) = [(Canvas, 4N), (LzwTable, 1)]` iff G2–G4 pass, and the iterator's `Req` adds `(Saved, 4N)` once. No other input-dependent allocation: no index buffer (indices are written straight to the canvas), no per-frame copy (an error leaves the canvas unexposed, G12.4), no growing collection. No reads beyond the slice, no unchecked overflow or narrowing, no panic, no recursion. Work: with `N = W·H` (0 if G2–G4 fail) and `P` the sum of `w·h` over images reaching G10, `steps ≤ c·(|b| + N + P)` for one constant `c` fixed in the theorem manifest, for every input and every policy record; per iterator call, the same bound with `|b|` replaced by the bytes consumed in that call and `N` charged only to the constructor and to disposal/restore of rectangles. Pixel positions that a policy clips away are still produced by the LZW loop and count in `P`; the disposal and restore work of a frame is at most its rectangle's area clipped to the screen and is charged to that frame's `w·h`, so it too is inside `P`. `P ≤ MAX_TOTAL_PIXELS` makes the whole decode bounded independent of the LZW expansion ratio.

## G19. Not in this core

No rendering of Plain Text; no background fill; no colour management, gamma or ICC application; no premultiplication; no streaming input (the caller supplies the whole stream); no partially decoded frames (only `../policy-draft` options introduce them); no frame timing beyond the raw fields; no loop playback. The cores' `no_std + alloc` form and the fallible-allocation API follow `../../alloc-delta/SPEC.md` §1–§9 unchanged.

## G20. Play count

`plays(loop_count: Option<u16>) -> Plays`, with `Plays = Once | Forever | Repeats(u16)`, is a total pure function: `None ↦ Once`, `Some(0) ↦ Forever`, `Some(n) ↦ Repeats(n)` for `n ≥ 1`. `total_plays(Once) = 1`, `total_plays(Repeats(n)) = n + 1` computed in `u32` (at most 65,536, no overflow), and `Forever` has no total. This is the convention of 7 of 12 surveyed implementations, including the three browser engines (`../policy-draft/LOOP-COUNT-EXPLAINER.md`): the stored value counts repeats after the first play. It interprets only the raw field of G6.3; where a NETSCAPE2.0 block occurs after the first image or under another identifier (`ANIMEXTS1.0`), `loop_count` is `None` and `plays` is `Once` in Strict and RecommendedBeta (other sources: `loop_source`, GdkCompat only). Playback stays outside the core (G19). Checked exhaustively by `check_plays.py`; vectors `plays-*`.
