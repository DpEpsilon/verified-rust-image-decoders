# ICNS core theorem manifest

This manifest fixes the proof obligations for both projects against **ICNS-CORE-SPEC 1.1** (`/home/ws/projects/spec/SPEC.md`, R1–R18). It does not change that specification. The notation below describes mathematical values, not a particular verifier's syntax. A proof of a theorem about a weaker model, a different error order, or only successful inputs does not count.

## Total reference model

A byte sequence `b` has a mathematical nonnegative length `|b|`; concrete calls have `|b| ≤ usize::MAX` on the target (both 32-bit and 64-bit targets must respect their integer widths). `u8`, `u32` and `u64` denote the corresponding unsigned ranges; model calculations use unbounded natural numbers before checking a target-width conversion. `U32BE(b,p) = 2²⁴b[p]+2¹⁶b[p+1]+2⁸b[p+2]+b[p+3]`, called only after the model has checked that the four bytes exist. `hex4` produces exactly eight lowercase hexadecimal digits from four bytes. An entry is `(type_hex: string, payload: [u32,u32], opaque_candidate: bool, nominal_side: Option<u32>)`, with exact field equality, not just a count or range invariant. A successful pixel result is `(width: u32, height: u32, data: bytes)`; equality includes **every** output byte and the exact error variant when unsuccessful. `Result X = Ok(X) | Err(error)`; its errors are exactly the 19 names of R17. `OutsideDomain` below is a mathematical marker, **not** a twentieth API error.

Define `legacy(c)` by the exact eight code-to-side pairs in R8, including whether `c` is colour or mask. Define `modern(c)` by the fourteen exact code-to-`nominal_side` pairs in R9. Define `sig(p)` iff `p` begins with all eight PNG signature bytes or all twelve JP2 signature bytes from R9. `classify(c,p)` returns `nominal_side=modern(c)` if present, else `None`, and `opaque_candidate = (modern(c)≠None) ∨ (legacy(c)=None ∧ sig(p))`. All other codes, including `ic04`/`ic05`/`icsb` without matching signatures, remain ordinary. This definition must be implemented independently of the code under proof.

`MP(b): Result[list<Entry>]` executes this *ordered*, finite algorithm: if `|b|>67,108,864`, `FileTooLarge`; if `|b|<8`, `TruncatedHeader`; if `b[0:4]≠"icns"`, `BadMagic`; let `L=U32BE(b,4)`; if `L<8`, `InvalidFileLength`; if `L>|b|`, `TruncatedFile`; if `L<|b|`, `TrailingFileBytes`. Set `off=8`, `E=[]`. While `off<L`: if `L-off<8`, `TruncatedEntryHeader`; let `c=b[off:off+4]`, `q=U32BE(b,off+4)`; if `q<8`, `InvalidEntryLength`; if `q>L-off`, `EntryOutOfBounds`; if `|E|=4096`, `TooManyEntries`; let `start=off+8`, `end=off+q`; append `(hex4(c),[start,end],classify(c,b[start:end]))`; set `off=end`. On `off=L`, return `Ok(E)`. All earlier branches return immediately, so the 4,097th entry's malformed length wins over `TooManyEntries`, while a valid 4,097th entry wins over malformed subsequent bytes. Set `Accepted(b) ⇔ ∃E. MP(b)=Ok(E)`, and `P(b,E) ⇔ MP(b)=Ok(E)` with exact list equality and the **same immutable b**.

`MR(s,n): Result[(R,G,B)]` is total for every finite `s` and natural `n`; the required calls have `n∈{256,1024,2304,16384}`. Start `cursor=0`. For each channel R, G, B set `produced=0` and, while `produced<n`, check cursor before reading control (`RleTruncated` if absent); consume control; set `(count,literal)=(control+1,true)` for control <128 and `(control−125,false)` otherwise; if `count>n−produced`, `RleOverrun` **before** reading data; require `count` available bytes for a literal or one for a repeat (`RleTruncated` otherwise); append exactly that many channel bytes; advance cursor and produced. Once all three channels contain exactly `n` bytes, return `RleTrailingBytes` if `cursor≠|s|`, otherwise `Ok(R,G,B)`. Thus every error is the first encountered by this order. For `n=0`, the loops are empty and the trailing-byte test still applies; the decoder never calls it with zero.

`MC(b,E,i)`, `MA(b,E,i)`, and `MJ(b,E,ci,mi)` are **total mathematical functions** returning `OutsideDomain` if `¬P(b,E)`; this marker is never a concrete result or an assumed fact. On `P(b,E)`, `MC` first tests `i≥|E|` (`IndexOutOfRange`), then membership in the four colour types (`UnsupportedType`); let side `d`, `n=d²`, payload `b[E[i].payload[0]:E[i].payload[1]]`. For `it32` only, remove exactly its first four bytes iff they equal `00 00 00 00`. Call `MR(payload,n)` and propagate its error; on success return `Ok(d,d,out)` where `out[3k..3k+3]=[R[k],G[k],B[k]]` for `k=y·d+x`, increasing x then y. `MA` tests index then four mask types in the same order, then tests payload length exactly `d²` (`InvalidMaskLength` otherwise); return `Ok(d,d,payload)` verbatim. `MJ` tests `ci=None` (`MissingColor`), then `mi=None` (`MissingMask`); for present `u32` indices call `MC` first and propagate its error, then `MA` and propagate its error; compare sides (`TypeMismatch` if unequal); otherwise return `Ok(d,d,out)` with `out[4k..4k+4]=[rgb[3k],rgb[3k+1],rgb[3k+2],alpha[k]]`. No other error or implicit entry selection is possible. These definitions determine all 111 fixture outcomes and are executable in principle without calling either project implementation.

For the safety statements, `Safe(f,args)` means: provided each requested heap allocation succeeds and the operating system supplies the ordinary process stack, the call terminates, performs no panic, out-of-bounds read/write, integer overflow, division error or unchecked narrowing, and returns a normal `Result`. This conditional excludes external resource exhaustion, **not** a malformed-byte exception. Every index and intermediate size is checked against the concrete target's `usize` and the R1 widths. An M2 proof may not assume `P` or safe ranges as an axiom: it must prove its own success invariant for `parse` and discharge decoder call preconditions using a concrete successful call `parse(b)=Ok(E)` with unchanged `b` and `E`. M3 subsequently proves that this success relation is equivalent to `P(b,E)`; M4 uses that bridge. Public direct calls on forged entries or a changed byte slice lie outside the decoder API contract and need not be safe.

## Required theorems

A project's four exported functions and its actual RLE helper are the functions quantified below; `parse`, `rgb`, `mask`, `combine`, `rle` denote those concrete functions. No proof may restrict the quantified byte contents to vector examples.

This includes **every** length `0..67,108,864` and larger representable lengths (those must return safely without scanning). | Restricting inputs to valid ICNS, nonempty slices, or a fixed small maximum. |

| **T9 · M4 · R10–R12,R15,R17** | `∀s,n, |s|≤67,108,864 ∧ n∈{256,1024,2304,16384}: rle(s,n)=MR(s,n)` as the exact three-channel result or exact first RLE error; all packet values `0..255` and all channel boundaries are covered. | Assuming streams are well formed, proving only decoded length, or omitting the trailing-data branch. |
| **T10 · M4 · R1,R8,R10–R12,R15,R17** | `∀b,E,i:u32, P(b,E): rgb(b,E,i)=MC(b,E,i)` exactly, including optional zero-only `it32` prefix, each RGB byte and precedence of index/type/RLE errors. | Requiring the selected entry to be colour, the index in range or decoding to succeed. |

The safety bounds are on requested/returned buffers and records, not a promise that an allocator will supply memory. T1–T6 additionally require **termination arguments**: parser offset strictly increases by at least eight until return, each RLE packet increases produced by at least one, and per-pixel copy loops have finite `d²` iterations; errors short-circuit. If an implementation uses more scratch buffers, it must prove each requested buffer is within the same `67,108,864`-byte input cap and that no pixel output exceeds the bounds above; it must disclose that extra allocation in its proof report. No proof can satisfy T1–T6 by catching a panic and returning an error afterward.

## Non-vacuity and mutation protocol

Each project's **own mathematical model**, before comparison with executable Rust, must agree with all **111** frozen vectors; a production-decoder test is not evidence that the proof model agrees. For the **102 vectors** whose expanded `input_hex`/`input_repeat` is at most **4,096 bytes**, establish each model result by concrete computation **or proof** against the fixture's independent `expected` field. Do **not** expand the other nine inputs inside a verifier: prove the named symbolic lemmas below and instantiate them with each fixture's compact description. The following **40 named witnesses are all at most 4,096 bytes**, exist in `spec-frozen/VECTORS.json`, and must be reported individually; the nine large witnesses are reported with their lemma instantiations instead:

- Container errors and precedence: `short-header`, `bad-magic`, `empty-input`, `bad-magic-before-length`, `invalid-file-length`, `declared-longer`, `declared-shorter`, `truncated-entry-header`, `entry-size-seven`, `entry-length-one-too-long`, `trailing-after-entry`, `entry-size-zero`.
- Container successes and classification: `minimal-empty`, `entry-length-equals-remaining`, `unknown-type`, `duplicate-order`, `opaque-ic10`, `jp2-signature-unknown-type`, `png-signature-legacy-mask-stays-mask`.
- RLE and colour: `rgb-is32`, `rgb-it32`, `literal-128-boundary`, `literal-nonuniform-rgb`, `it32-eight-zero-prefix-then-literals`, `is32-four-zero-literals`, `rle-empty`, `repeat-overrun-before-missing-value`, `run-crosses-channel-boundary`, `rle-trailing-data`.
- Mask and composition: `mask-h8mk`, `mask-too-short`, `mask-index-equal-entry-count`, `unsupported-rgb-type`, `unsupported-mask-colour-type`, `mask-without-colour`, `colour-without-mask`, `combine-mask-before-colour`, `combine-nonuniform-alpha`, `mismatched-mask-dimensions`, `combine-colour-error-before-mask-error`.

The following are **required proved symbolic lemmas about the model**, not executable expansions or axioms. `BE32(x)` is the four-byte big-endian encoding of a `u32` value; `e = bytes("none") · BE32(8)` is an eight-byte empty entry; `e^k` repeats it `k` times; `H(k,s) = bytes("icns") · BE32(8+8k+|s|) · e^k · s`, defined when its length is at most 67,108,864. For `0≤j<k`, let `E_k[j]=(type_hex="6e6f6e65", payload=[16+8j,16+8j], opaque_candidate=false, nominal_side=None)`.

- **L1 — oversized input:** `∀b, |b|>67,108,864: MP(b)=Err(FileTooLarge)`. Instantiation: `file-too-large` (`00` repeated 67,108,865 times).
- **L2 — exact-limit bad magic:** `∀b, |b|=67,108,864 ∧ b[0:4]≠bytes("icns"): MP(b)=Err(BadMagic)`. Instantiation: `file-size-at-limit` (`00` repeated 67,108,864 times). Its expected error is **BadMagic**, not FileTooLarge.
- **L3 — large exact mask:** For every byte string `a` with `|a|=16,384`, let `b=bytes("icns")·BE32(16,400)·bytes("t8mk")·BE32(16,392)·a` and `E=[("74386d6b",[16,16,400],false,None)]`. Then `MP(b)=Ok(E) ∧ MA(b,E,0)=Ok(128,128,a)`. Instantiation: `mask-t8mk`, where `a` repeats `7f` 16,384 times; its expected alpha run has count 16,384.
- **L4 — repeated valid entries:** `∀k∈{0,…,4096}: MP(H(k,empty))=Ok(E_k)`. Instantiation: `entry-count-exactly-4096` at `k=4096` (32,776 bytes). The empty base case is non-vacuous.
- **L5 — 4,097th valid entry before a suffix:** `∀s, |s|≤67,108,864−32,784: MP(H(4097,s))=Err(TooManyEntries)`. Instantiations: `entry-count-limit` with `s=empty` (32,784 bytes), `count-limit-before-stray-suffix` with `s=bytes("BAD")` (32,787 bytes), and `entry-count-before-later-malformed-entry` with `s=bytes("none")·BE32(7)` (32,792 bytes). In each case the declared length includes `s`, and parsing stops at the valid 4,097th entry before examining it.
- **L6 — malformed 4,097th entry before count limit:** For `q:u32`, let `B(q)=bytes("icns")·BE32(32,784)·e^4096·bytes("none")·BE32(q)`. Prove `∀q<8: MP(B(q))=Err(InvalidEntryLength)` and `∀q>8: MP(B(q))=Err(EntryOutOfBounds)`. Instantiations: `invalid-4097th-entry-before-limit` with `q=7` and `entry-count-followed-by-overflowing-4097th` with `q=4,294,967,295`, both 32,784 bytes. The `q=8` case follows L5 and gives `TooManyEntries`.

All **nine** vectors longer than 4,096 bytes appear in L1–L6 exactly once as an instantiation (L5 covers three, L6 two); the other 102 remain concrete proof/computation obligations. A project may derive the instantiation from its general lemma by arithmetic on lengths and compact repeat counts, never by allocating a 64 MiB proof-level sequence.

Each project must run deliberate negative proofs **with all T1–T13 statements left enabled**, in a disposable copy, and retain the failed verifier diagnostics; a passing compile or runtime test is not enough. Required mutations (restore each one before the next):

1. Change `MP`'s acceptance check from `|b|>67,108,864` to `≥` while leaving **L2** (exact-limit BadMagic) and T7 unchanged; the symbolic L2/T7 proof must fail, **not** a 64 MiB concrete model-vector evaluation.
2. Change the entry bound check from `q>L−off` to `q>L−off−8` while leaving `entry-length-equals-remaining` unchanged; T7/model-vector obligation must fail.
3. Move `TooManyEntries` before the 4,097th entry length check while leaving **L6** and T7 unchanged; the symbolic `q=7` instantiation (`invalid-4097th-entry-before-limit`) must fail, **not** a 32 KiB concrete model-vector evaluation.
4. Delete the `legacy(c)=None` guard from signature classification; T7 must fail on `png-signature-legacy-mask-stays-mask`.
5. Delete or deliberately weaken the parser-success range/provenance postcondition while keeping the modular decoder-safety call-site obligations T3–T6 and T13 unchanged; their derivation must fail. If the verifier reconstructs the bound by unfolding code, instead assert the false claim `start>end` for the parsed entry in `entry-length-equals-remaining`: verification must fail, and report why the first mutation did not.
6. Change a repeat's `control−125` to `control−124`; T9/T10 must fail on `rgb-is32` or `repeat-overrun-before-missing-value`.
7. Swap RLE's overrun and payload-availability checks; T9 must fail on `repeat-overrun-before-missing-value`.
8. Strip eight zeros rather than exactly four for `it32`; T10 must fail on `it32-eight-zero-prefix-then-literals`.
9. Reverse missing-colour/missing-mask priority, or check mask before RGB, while leaving T12 unchanged; use `mask-without-colour` or `combine-colour-error-before-mask-error` to witness failure.
10. Remove the RGBA alpha-byte equality from a *modular* `combine` postcondition while keeping T12's full pixel equality and the dependent final assertion unchanged; T12 must fail, unless another proved lemma supplies the same equality—in that case replace a nonzero alpha with zero in the implementation and show T12 fails on `combine-nonuniform-alpha`.

A mutation that only breaks a test but still verifies all required proof obligations is not a successful proof sensitivity check. Conversely, a removed helper clause that remains derivable from other verified premises does not make the original proof vacuous; the specified fallback negative assertion is mandatory.

## Assurance boundary

The allowed **additional** trust assumptions are **none**: no `assume`, `admit`, trusted/external-body function, unchecked lemma, unverified FFI, unsafe operation, or test-only axiom may establish a theorem. The verifier's soundness, its standard-library contracts, and the compiler's faithful execution of verified code are the unavoidable trusted computing base; state their versions in each report. The proofs do **not** establish that PNG/JPEG 2000 bytes are valid or decoded, that macOS tools emit only accepted files, that byte-slice ownership remains unchanged across an external caller's separate operations, or that the chosen 64 MiB/4,096-entry policy suits every application. They do **not** guarantee successful heap allocation: out-of-memory aborts/allocator failures are excluded explicitly by `Safe` rather than silently treated as errors. They do **not** guarantee against operating-system stack exhaustion; instead T1–T6 prove that core call depth is bounded independently of input and that none of the specified loops recurses. External process termination, hardware failure, verifier/compiler defects and arbitrary fabricated entries are outside these claims. These exclusions cannot be used to suppress a deterministic panic or bounds error on a normally allocated, provenance-valid call.
