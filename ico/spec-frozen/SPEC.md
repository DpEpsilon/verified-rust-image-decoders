# ICO/CUR container core

**ICO-CORE-SPEC 1.0 (frozen).** This is a byte-slice core over a standalone `.ico`/`.cur`, not a resource-file `RT_GROUP_ICON` directory (its 14-byte resource-ID records are outside scope; RECALLED), ANI/RIFF, stream loader, image selector, PNG decoder or renderer. It depends on the proposed `/home/ws/projects/dib/spec-1.1/SPEC.md` DIB-CORE-SPEC 1.1 `IcoEntryDibSlack` mode; DIB 1.1 is frozen first (its oracle identity is pinned in `spec/dib_oracle_pin.py`); proving this core additionally requires DIB 1.1's reproved public model and tracked decoder. The frozen DIB 1.0 implementation must remain untouched until 1.1 is reviewed and reproved. Wire fields are unsigned little-endian; ranges `[start,end)` are zero-based. All intermediate model calculations use mathematical integers, and concrete arithmetic must be checked before narrowing to `usize` on either 32- or 64-bit targets. A caller retains the immutable byte slice while using returned records.

R1. Public API: `parse(bytes: &[u8]) -> Result<Vec<Entry>, Error>` and **total** `decode_entry(bytes: &[u8], entries: &[Entry], index: u32) -> Result<dib_verus::Decoded, Error>`. An `Entry` record has exactly `{width:u16,height:u16,color_count:u8,raw_offset:u32,raw_size:u32,planes:Option<u16>,bit_count:Option<u16>,hotspot_x:Option<u16>,hotspot_y:Option<u16>,status:EntryStatus}`. `EntryStatus` is either `Invalid(EntryDefect)` or `Valid{kind:Png|Dib,payload:[u32,u32]}`; `EntryDefect` is exactly `InvalidEntryReserved|EmptyEntry|EntryOverlapsDirectory|EntryOutOfBounds`. In JSON, `status` is `{"invalid":"Name"}` or `{"valid":{"kind":"Png|Dib","payload":[start,end]}}`. An invalid record retains its raw offset and size, but has **no** trusted payload range or kind. Parse returns all `count` records in wire order, including invalid records; a bad unselected record never aborts parsing or decoding another. `Decoded` is the DIB crate's exact RGBA object, with dimensions from the DIB header, not a directory-sized wrapper. No `Entry` is a borrow into payload bytes.

R2. Limits: `MAX_INPUT=67,108,864` bytes, `MAX_ENTRIES=1,024` records. Parse and decode first test input length `>MAX_INPUT` (`FileTooLarge`) before reading it. Exactly the limit passes this test. Both require at least six bytes (`TruncatedDirectory`). The count cap is policy, not a restriction implied by the u16 wire count (u16 permits 65,535); a complete maximum-size directory occupies 16,390 bytes. A parse implementation may make one bounded entry-list reservation after directory/count/table guards, and no PNG or DIB pixel request. `decode_entry` itself requests no allocation and calls DIB at most once; any physical allocation count/capacity claim requires source audit because ghost counters do not detect uncharged new calls. OOM and operating-system stack failure are outside byte errors.

R3. Shared directory guard `H(b)` checks in this exact order: `U16(b,0)=0` else `InvalidReserved`; `type=U16(b,2)∈{1,2}` else `UnsupportedType` (ICO=1, CUR=2); `count=U16(b,4)>0` else `EmptyDirectory`; `count<=MAX_ENTRIES` else `TooManyEntries`; `dir_end=6+16*count<=|b|` else `TruncatedEntries`. All six header bytes must exist before these reads. Thus an incomplete table wins over every entry defect; a count of 1,025 wins over incomplete table. Parse returns `Err` **only** for R2/R3 directory-wide errors. Complete entries never make the entire parse fail, even if all are invalid.

R4. For each `i=0..count-1` at `p=6+16*i`, read `(w0,h0,color_count,reserved,lo,hi,size,offset)` at byte offsets `(0,1,2,3,4..6,6..8,8..12,12..16)` of the record. Set `width=w0 or 256`, `height=h0 or 256`, `raw_size=size`, `raw_offset=offset`; each nominal dimension is 1..256. Determine status by **first matching defect**, in this order: `reserved!=0 → InvalidEntryReserved`; `size=0 → EmptyEntry`; `offset<dir_end → EntryOverlapsDirectory`; `offset>|b| OR size>|b|-offset → EntryOutOfBounds`. All checks use the **end of the entire directory**, not this record's end. No later test overrides an earlier defect; a defect on record `i` does not stop the iteration. Only if all checks pass set `payload=[offset,offset+size)` and classify per R6. The valid range satisfies `dir_end<=offset<offset+size<=|b|`; `offset=dir_end` and an end exactly EOF pass. `offset+size` must not wrap or narrow unchecked. Retain a byte reserved field only via status (it is not a public record field); revalidation rereads it from the file.

R5. For ICO, `planes=Some(lo)`, `bit_count=Some(hi)`, `hotspot_x/y=None`. For CUR, `planes/bit_count=None`, `hotspot_x=Some(lo)`, `hotspot_y=Some(hi)`. Preserve zero, large and inconsistent metadata; CUR hotspots are unsigned 16-bit coordinates and are **never** interpreted as planes/depth or clipped. A renderer may reject a hotspot outside the **decoded** dimensions. `color_count` is metadata, not a palette constraint. A zero byte in **either** nominal dimension means 256. Directory dimensions can disagree with the DIB header: do not reject, resize or use nominal dimensions for DIB pixels. For PNG, retain directory dimensions as nominal metadata only; the PNG decoder independently checks its real dimensions.

R6. For a **valid bounded range only**, classify `Png` iff `size>=8` and its **first eight bytes** equal `89 50 4e 47 0d 0a 1a 0a`; otherwise `Dib`. Never complete a seven-byte prefix with bytes beyond the declared range, and never search later in the payload. A full signature alone suffices; the core neither reads IHDR nor validates PNG chunks, CRCs or dimensions. No valid DIB begins with this signature: its first four bytes as little-endian header size would be `0x474e5089`, rejected by DIB R2. DIB payload structure is not checked in `parse`.

R7. Valid payload ranges may be identical, nested or straddle one another. There is no sort, deduplication, pairwise overlap check or alignment rule. File-level gaps and bytes after the last range are ignored; bytes **inside** a DIB range after its complete AND mask are accepted by the proposed `IcoEntryDibSlack` mode. This settled D11 choice keeps exact short-side delimitation: never extend an under-declared range to EOF or into a neighbour. Such a selected entry returns the DIB's exact truncation error. This is the settled D11 policy, not an implicit feature of 1.1 DIB. Count zero is `EmptyDirectory`, which the baseline also rejects.

R8. `decode_entry` is **total for all representable bytes, all typed `Entry` slices and all `u32` indices**, including forged/mutated records or a slice from another file. First run R2/R3 directory guards without allocating an entry list, propagating their errors. Then if `index>=count`, return `IndexOutOfRange` (even if `entries.len()!=count`); otherwise if `entries.len()!=count`, return `InvalidEntryRecord`. Reconstruct the **selected** entry from the wire by R4–R6; if `entries[index]` is not exactly equal field-for-field and status-for-status to that reconstruction, return `InvalidEntryRecord`. Only `entries.len()` and `entries[index]` may be inspected; no other supplied element is read or revalidated. If selected status is `Invalid(e)`, return its exact `e`. If selected valid kind is `Png`, return `PngDelegation` without invoking DIB. Otherwise take precisely `s=&bytes[payload.start..payload.end]`, call the DIB 1.1 public tracked decoder `dib_verus::decode_with_steps(s,IcoEntryDibSlack)` **once** (the ghost step return is erased), return the same success `Decoded` or `Dib(e)` with the exact DIB error. This selected-record reread is constant work; do not call allocating `parse` again. All slices are guarded before indexing, so forged records cause an error, not a panic. Equality of raw bytes across calls is **not** asserted by this total API.

R9. Closed case-sensitive `Error` set: directory errors `FileTooLarge`, `TruncatedDirectory`, `InvalidReserved`, `UnsupportedType`, `EmptyDirectory`, `TooManyEntries`, `TruncatedEntries`; entry defects `InvalidEntryReserved`, `EmptyEntry`, `EntryOverlapsDirectory`, `EntryOutOfBounds` (**decode-only** as returned errors; in parse they occur inside statuses); `IndexOutOfRange`, `InvalidEntryRecord`, `PngDelegation` (decode-only), and typed `Dib(dib_verus::Error)`. No `InvalidHotspot`, `DimensionMismatch`, `InvalidPng` or container `TrailingBytes`. In vectors, a DIB error is written `Dib(ErrorName)`; in Rust it carries the DIB 1.1 error enum, not a string. New DIB mode changes which selected slices return `TrailingBytes`; it changes no DIB error names.

R10. **Total precedence:** `parse`: R2 cap, six-byte availability, then R3 reserved/type/empty count/count cap/whole-table guard; after those checks, return the complete ordered list of R4 per-record statuses (each record has its own reserved/size/directory-overlap/out-of-file priority), without a global first-entry error. `decode_entry`: same R2/R3 guard; `index>=count`; list-length mismatch; selected record field/status mismatch; selected record's first defect; PNG delegation; exact DIB 1.1 error order on that declared slice. A malformed *unselected* record cannot win over the selected result. No partial list escapes a directory-wide error; invalid entries in a successful list are complete records, not partial results. Decode does not depend on whether a caller actually invoked parse first.

R11. Independent total mathematical models: `MC(b)` executes R2–R7 and returns either the directory-wide error or the **complete** list (including invalid statuses). `ME(b,i)` is the selected-record reconstruction after a successful directory guard. `MD(b,E,i)` is total for every `(b,E,i)`, executes R8 in R10 order, and for a selected valid DIB defines its result as the exact frozen-amendment model `map_result(Dib, MP_1.1(b.subrange(start,end),IcoEntryDibSlack))`. No `OutsideDomain` marker or provenance premise exists; the result for forged entries is the exact error specified by R8. The executable must equal `MC` and `MD` as whole results, including every record field, error, decoded dimension and RGBA byte. These models must not call the executable parser or Python oracle.

R12. `VECTORS.json` is an array of `{name,input_hex,operation,expected}` with `operation=parse|decode`; `index:u32` exists only for decode. A decode vector runs `parse` to **construct the ordinary supplied entries**, unless optional `entries_override` supplies a JSON array of typed `Entry` objects to test totality; `entries_override` is permitted **only** when `operation=decode`. If parse has a directory-wide error, the vector's expected result is that error and `decode_entry` itself must reproduce it even with an override. A successful parse expects `{entries:[Entry...]}` in R1 schema; decode success expects `{width,height,rgba_runs:[{count,hex}...]}` with maximal runs of adjacent four-byte pixels; an error is `{error:name}`. `input_hex` is lowercase contiguous hex. `input_repeat` (positive, default 1) repeats the whole seed; optional **paired** `repeat_from` and `input_suffix_hex` form `seed[:cut]+seed[cut:]^input_repeat+suffix`, with `0<=cut<len(seed)` in bytes. Compute length before allocating any over-cap fixture. These JSON fields are test fixtures, not wire data. There are **217** vectors (frozen with this spec).

R13. Work/resource contract: compute `dir_end` and range arithmetic in `u64`/checked `usize`. Parse visits at most 1,024 records and compares at most eight signature bytes per valid record. The decode wrapper revalidates **one** wire record in constant loops (at most eight signature iterations), then delegates once or not at all. Charge a ghost step for each **actual** ICO-controlled loop-body iteration and bulk-fill byte touched; establish `steps(parse)<=16*(|b|+1)` and `steps(wrapper)<=16*(|b|+1)` for every call. The chosen DIB 1.1 public `decode_with_steps` call has `steps_DIB<=16*(|slice|+N)` and `decode_mp_eq` as proposed postconditions; a combined bound becomes a theorem only after the DIB 1.1 implementation proves and exports that contract and ICO invokes the same function. The currently shipped DIB 1.0 crate has no such public call, so no cross-crate numerical total is yet proved. Source-audit any extra uncharged allocation or loop. The output-size and DIB work bounds remain the DIB dependency's own proof obligations; repeated caller-initiated decoding of 1,024 aliases is **not** one invocation and must charge each call.
