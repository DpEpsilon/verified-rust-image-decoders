# Remaining glycin formats: differential-harness plan

Inventory taken from the checked-out `glycin-loaders/*/*.conf` registrations and `glycin-image-rs/src/lib.rs` dispatch. This is a plan, not an implementation. The image-rs column means glycin's **in-tree** loader, not another independent vote for the same `image` decoder. The clone contains competing custom registrations for `image/bmp` (`glycin-dib`), `image/x-tga` (`glycin-tga`) and `image/x-icns` (`glycin-icns`); a deployed configuration's chosen loader depends on installed configuration and ordering. The existing harness invokes those implementations explicitly rather than assuming dispatch precedence.

## Completed adapters

| Format / registered MIME | Actual loader | Core | Independent comparisons and remaining gap |
| --- | --- | --- | --- |
| BMP `image/bmp` | `glycin-image-rs` → `image::BmpDecoder`; also `glycin-dib` → `dib_verus` | DIB 1.1 | Completed BMP harness: image-rs, GDK BMP, verified DIB; the two glycin registrations must remain distinct. |
| TGA `image/x-tga` | `glycin-image-rs` → `image::TgaDecoder`; also `glycin-tga` → `tga_verus` | TGA verified | Completed adapter: image-rs, GDK TGA forced/detected, `tinytga`, verified TGA. Future enhancement: add the custom `glycin-tga` glue as a separate column. |
| ICNS `image/x-icns` | `glycin-icns` → verified container/legacy core plus image-rs PNG | ICNS verified legacy/parser | Completed adapter: verified legacy and PNG-candidate selection, `icns` crate, GDK ICNS, glycin glue. PNG pixels themselves are **not** verified. |
| ICO `image/vnd.microsoft.icon`, CUR `image/x-win-bitmap` | `glycin-image-rs` → `image::IcoDecoder` for both | ICO planned, independent ICO 1.1 + DIB 1.1 Python oracles available | Completed adapter: per-entry oracle/`ico` crate, image-rs, glycin, GDK; the oracle deliberately delegates PNG. |

## Recommended next order

The comparison candidates are independent implementations where named; GDK modules listed here are **installed** in this environment. A candidate without an installed GDK module needs a separate executable or library and must be marked unavailable, not silently counted as a rejecting decoder.

| Order / format / every registered MIME | Glycin decoder and comparison candidates | Core; extension effort and normalization |
| --- | --- | --- |
| 1. PNM: `image/x-portable-bitmap`, `image/x-portable-graymap`, `image/x-portable-pixmap`, `image/x-portable-anymap` | `glycin-image-rs` → `image::PnmDecoder` (PBM/PGM/PPM/PAM); installed GDK PNM module, `pnm`/`netpbm` Rust crates or netpbm CLI if locally available. | No verified core. Low–medium: ASCII/binary modes, comments/whitespace, maxval boundaries, channel counts, 1/8/16-bit scaling; PBM bit polarity and PAM alpha require explicit RGBA normalization. |
| 2. QOI: `image/qoi` | `glycin-image-rs` → `image::QoiDecoder`; `qoi` crate and other pure-Rust QOI implementation. No installed GDK QOI module. | No core. Low: short header, chunk tags, run/index state, overrun and trailing bytes; byte-exact 8-bit RGBA. |
| 3. PNG: `image/png`; APNG: `image/apng` | `glycin-image-rs` → `image::PngDecoder`; `png` crate (image-rs itself uses it: **not** an independent vote), `spng`/libpng via native subprocess, GDK's built-in PNG loader; APNG compare independent APNG-capable library and first-frame policy. | No core. Medium for static PNG, high for APNG: CRC, chunk order, interlace, palette/tRNS, gamma/color metadata, 16→8-bit policy; APNG timing, compositing, disposal and frame selection. |
| 4. GIF: `image/gif` | `glycin-image-rs` → `image::GifDecoder`; installed GDK GIF module, independent `gif` crate (avoid counting image-rs's own `gif` dependency as independent). | No core. Medium–high: LZW, transparency index, multiple frames, logical screen offsets, disposal, frame duration, interlacing and palette expansion. |
| 5. XBM: `image/x-xbitmap`; XPM: `image/x-xpixmap` | `glycin-image-rs` → `image-extras::{xbm,xpm}` decoders; installed GDK XBM/XPM modules; independent `xpm`/`xbm` crates or parsers if worthwhile. | No core. Medium: XBM C-source syntax and bit order, XPM symbols/colors/transparency and text encoding; PNG-style byte signature tests do not apply. |
| 6. DDS: `image/vnd.ms-dds` | `glycin-image-rs` → `image::DdsDecoder`; independent `ddsfile` (container) plus `bcdec_rs` (BCn decompression), DirectXTex only if already installed. No installed GDK DDS module. | No core. Medium–high: mipmaps, cube/array surfaces, BC1–BC7, DX10 header; choose and record mip/face and whether format conversion changes colors or alpha. |
| 7. JPEG: `image/jpeg` | `glycin-image-rs` special path `loader::jpeg` → `zune-jpeg` and metadata glue; independent libjpeg-turbo subprocess, `jpeg-decoder` crate; GDK's built-in JPEG loader. | No core. Medium–high: progressive/restart/CMYK/YCbCr, EXIF orientation, ICC treatment; lossy IDCT rounding requires a per-pixel tolerance metric in addition to exact hashes. |
| 8. WebP: `image/webp` | `glycin-image-rs` → `image::WebPDecoder`; `libwebp` native subprocess, installed-GDK check (no WebP module here), independent Rust crate if available. | No core. High: lossy pixel tolerances, lossless bit-exactness, animation disposal/blend/timing, ICC and alpha premultiplication. |
| 9. TIFF: `image/tiff` | `glycin-image-rs` special `loader::tiff` → `tiff` crate; installed GDK TIFF module, libtiff CLI/bindings, another independent TIFF reader. | No core. High: multiple IFDs/pages, strips/tiles, compression variants, palette/CMYK, orientation, 16-bit/float channels and sample-layout conversion. |
| 10. Radiance HDR: `image/vnd.radiance`; OpenEXR: `image/x-exr` | `glycin-image-rs` → non-strict `image::HdrDecoder` for HDR; special `exr` crate path for EXR. High: RGBE exponent scaling, scanline RLE, linear-light 16/32-bit floating point, NaN/Inf and tone mapping. Compare canonical float samples before presentation-oriented RGBA8; do **not** call a tone-mapped hash a decoder disagreement. |
| 11. JPEG 2000: `image/jp2`, `image/x-jp2-codestream` | `glycin-image-rs` → `hayro_jpeg2000::integration::Jp2Decoder`; OpenJPEG or another independent library. No installed GDK JP2/JPC module. | No core. High: JP2 boxes versus bare codestream, 12/16-bit components, progression/resolution levels, color transforms, palette and ICC; normalize the selected resolution explicitly. |
| 12. JPEG XL: `image/jxl` | `glycin-image-rs` special `loader::jxl` → `jxl` crate; libjxl CLI/bindings and independent implementation where available. No installed GDK JXL module. | No core. | 13. HEIF/AVIF: `image/heif`, `image/avif` | `glycin-heif` → `libheif-rs`/libheif; `dav1d` + AV1 image wrapper or FFmpeg/libavif where available. No installed GDK HEIF/AVIF module. | No core. | 14. SVG/SVGZ: `image/svg+xml`, `image/svg+xml-compressed` | `glycin-svg` → `librsvg-rebind`/librsvg; resvg/usvg renderer as independent implementation; no installed GDK SVG module. | No core. High: gzip wrapping, XML references, fonts, viewport/dimensions, CSS and rasterization variability. Fix renderer viewport, resources/fonts and color space before RGBA comparison. |
| 15. RAW: `image/x-canon-cr2`, `image/x-adobe-dng`, `image/x-epson-erf`, `image/x-minolta-mrw`, `image/x-olympus-orf`, `image/x-panasonic-rw`, `image/x-panasonic-rw2`, `image/x-pentax-pef`, `image/x-sony-srf` | `glycin-raw` → `libopenraw`; compare LibRaw/dcraw or rawloader for supported camera models. No installed GDK RAW module. | No core. Very high: real camera corpus/licensing, preview versus raw sensor plane, CFA demosaic, white balance, black levels, orientation and 12/14/16-bit scaling; record selected image and pipeline settings before comparing. |

`glycin-test.conf` registers `image/x-glycin-test`: a synthetic test loader, not an image format; it needs protocol tests rather than a decoder-leniency matrix. The in-tree image-rs dispatch also recognizes `image/x-ff` (farbfeld), `image/x-qoi` and `image/x-targa` aliases, but no corresponding loader registration appears in these `.conf` files; note those entry points when calling the loader directly, without claiming the installed MIME dispatcher serves them. Editor stanzas (`jxl`, `webp`, and others) are not extra decoders.

For each new adapter, freeze license-safe synthetic fixtures, keep downloaded corpus bytes and all corpus-derived witnesses under `/tmp/claude-0`, isolate each decoder process, preserve `crash`/`timeout` rather than collapsing it to rejection, and emit a public frozen-only summary separately from the full local matrix. Any future verified core needs a dedicated section **“where our core's choices disagree with ALL or MOST other decoders”**; independent implementations, not multiple wrappers of image-rs, determine that comparison. No source decoder repository needs modification.
