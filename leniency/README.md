# Decoder leniency harness

The engine in `engine.py` runs one file's **identical bytes** through independent subprocesses, captures a one-line JSON result, and classifies acceptance and normalized RGBA8 SHA-256 hashes. Format adapters define runners, input generators, and provenance; `bmp/harness.py` is the first adapter. No corpus file is copied into this repository. Generated input files, manifest and per-input results live under `/tmp/claude-0/leniency-bmp/`; summarized findings and minimized witnesses live in `bmp/`.

## Run

```sh
cd ~/projects/leniency/bmp
./build.sh && python3 harness.py --inputs 10000 --seed 731 --jobs 6
```

The `--inputs` ceiling includes 260 frozen/corpus inputs and targets 10,000 total inputs. To inspect a sample, add `--inputs 500`. Run `PYTHONDONTWRITEBYTECODE=1 python3 -I tests/test_engine.py` for deterministic generator and classification tests. `python3 reproduce.py PATH_FROM_MATRIX` runs one existing witness through every decoder (inspect `LENIENCY.md` for current paths). The adapter writes a summary to `bmp/summary.json`, detailed per-input results to `/tmp/claude-0/leniency-bmp/results.jsonl`, and provenance, source name, length and hash to `/tmp/claude-0/leniency-bmp/manifest.jsonl`. Original corpus paths appear in provenance but their bytes remain in the source directories; generated BMPs live in the temporary directory. Do not publish the corpus or anomaly bytes.

The Rust binary has four selectors: the verified `dib_verus::decode(Mode::BmpFile)`, pinned `image =0.25.10` (explicit BMP and guessed format), and the glycin clone's **in-tree `glycin-image-rs::ImgLoader`** through `LoaderImplementation::load` / `specific_frame`. Glycin currently maps `image/bmp` to `glycin-image-rs`; the separate verified `glycin-dib` loader is *not* the glycin selector. The native GDK binary calls `gdk_pixbuf_new_from_file`, `gdk_pixbuf_new_from_stream`, and `GdkPixbufLoader` with whole-buffer, single-byte and 4096-byte writes. The installed 2.42.12 module list contains the dynamically loaded BMP module (`libpixbufloader-bmp.so`). `image-explicit`, `image-guess`, and glycin's image-rs path share code internally; do not count them as independent votes.

Every runner returns one JSON line with status, error class/message on error, or dimensions, source color type, alpha flag and RGBA SHA-256 on success. Optional third argument writes raw top-first, non-premultiplied RGBA8. `alpha_present` currently means at least one decoded alpha value is nonopaque, not merely that a source header has an alpha channel. `orig_color_type` for the image crate comes from its decoder's `color_type()` before conversion; glycin and GDK expose their pre-normalization output format; verified core only exposes RGBA8 output. Subprocess limits: 10 seconds, 768 MiB virtual address space, no core dumps and a 64 MiB output-file cap. GDK's path-based error message includes the generated file path, so cluster by status rather than message. `all-reject` means every decoder rejected, *not* that their error classifications agree; compare the raw per-input error classes. Distinct pixels are resolved by rerunning the representative witnesses with RGBA dumps to identify alpha-only, red/blue swaps, orientation, size or other color/layout differences.

Mutations start from frozen vectors (41 BMP-file cases and 138 wrapped bare DIBs), 71 local corpus BMPs, glycin's checked-out BMP and nine GDK BMPs. Other ICO-entry vectors cannot be interpreted as standalone BMPs and are excluded. The wrapper computes `bfOffBits` from DIB header, mask and palette fields, preserving the original DIB; ambiguous invalid DIBs need manual interpretation. Seed tuples (header size, depth, compression) drive systematic header boundary values, inconsistent size pairs, truncations, trailing bytes and seeded random bit flips. Each generated mutation has a rule, field, old/new value and seed source in the manifest. Mask mutations edit mask words in 40-byte bitfield headers and extended headers; RLE escape mutations edit escape words at the pixel start and near the end. Palette lengths receive boundary values through `biClrUsed` plus truncation. These are targeted probes, not an exhaustive RLE grammar or palette enumerator; unobserved variants remain a coverage gap.

`LENIENCY.md` contains representative matrix cells, class counts, GDK path disagreement counts, verified-core divergence examples and anomaly IDs. A mutation enters a provenance cluster only if it changes the **acceptance and cross-decoder pixel-equality pattern** relative to its unmutated seed; a change that merely changes the same pixels in every decoder does not count as a newly exposed leniency. A row records the most frequent outcome pattern among changed inputs with that provenance; `patterns` counts distinct outcomes within the row. Frozen vectors and local corpus images stand alone without a seed comparison. A bounded byte-range delta debugger saves a witness preserving *every runner's* acceptance, dimensions and RGBA hash; it does not guarantee global minimality. Per-input outcomes remain in the JSONL.

## Add a format

1. Add `format/runners/` binaries that accept selector, input path and optional RGBA-dump path, returning the same JSON contract. Record original pixel formats and convert to top-first straight RGBA8 before hashing.
2. Add a format adapter based on `bmp/harness.py`: register selector/executable pairs, write a deterministic generator yielding `(bytes, provenance)` and supply any format-specific behavior rules. Import `engine.invoke`, `engine.classify` and `engine.compact`; the subprocess sandbox and classification logic stay unchanged.
3. Add formats' actual glycin and upstream library entry points instead of treating a wrapper around one implementation as an independent decoder. For ICNS, compare representation selection by requested size; for TGA, include image origin and palette/RLE variants; for ICO/CUR, preserve entry, DIB/PNG and AND-mask provenance. Enumerate MIME types from the checked-out `glycin-loaders/*/*.conf` registrations, then add adapters for image-rs formats (PNG/JPEG/GIF/WebP/TIFF and others), dedicated HEIF/AVIF, SVG and RAW loaders, and any later additions. Document transformations that change bytes (such as the bare-DIB-to-BMP wrapper).

Pillow was not available in the installed Python environment and PyPI is outside the allowed network; no independent extra Rust BMP decoder was integrated in this first matrix. Inputs in `/tmp/claude-0/leniency-bmp/anomalies/` are retained for local diagnosis only. Original corpus files and any minimized witnesses derived from them remain under `/tmp/claude-0/leniency-bmp/`, never in this repository. Do not attempt exploitation or report upstream without the coordinator's decision.

## TGA, ICNS, and ICO/CUR

The adapters `tga/`, `icns/`, and `ico/` use `format_harness.py`, `shared/src/main.rs`, and `shared/gdk.c`. The shared engine additionally exposes status/pixel-relation signatures, exact outcome signatures (including selected entries), and compact JSON records retaining selection metadata; BMP's existing interface remains unchanged. Run `./run.sh --inputs 10000 --seed 731 --jobs 8` in any adapter directory; each script builds Rust/C runners under `/tmp/claude-0/` and then generates and compares that format's inputs. No builds or corpus copies enter the source decoder repositories. Each runner returns one JSON line with `ok|error|crash|timeout`, error class/message, original output format, dimensions, transparent-alpha flag, RGBA8 SHA-256, and selected entry when applicable. The optional last argument writes straight top-first RGBA8. Run each `tests/test_*.py` with `PYTHONDONTWRITEBYTECODE=1 python3 -I` after building; use `python3 reproduce.py FILE` for any witness (`ico/reproduce.py FILE --entries` also compares each directory entry). `tga/` includes the independent `tinytga` crate; GDK's TGA module is tested both by filename/auto detection and by forced type with whole/one-byte/4096-byte writes. The ICNS legacy core selects a largest colour+mask pair; its PNG column delegates pixels to image-rs, while the glycin-ICNS glue chooses and falls back across candidates. ICO/CUR use the independent Python ICO+DIB oracles, which report `PngDelegation` rather than pretending to decode PNG; the image-rs, `ico` crate and GDK columns decode PNG where supported. Entry-selection disagreements and pixel-only disagreements each have their own minimized-witness rows, even when a rule's most frequent outcome is accept-vs-reject.

Each adapter's **local** `summary.json` and `LENIENCY.md` include all outcomes, including corpus-provenance rows. Its `summary-public.json` and `LENIENCY-PUBLIC.md` recount only frozen vectors and mutations descended from frozen vectors; only those results and frozen-derived witnesses are eligible for the public repository. Every original input, per-input result, manifest, corpus-derived witness, crash and timeout input lives under `/tmp/claude-0/leniency-{tga,icns,ico}/`; do not sync any of those directories. The anomalies are retained separately and were not investigated for exploitation or reported upstream. `GLYCIN-FORMATS.md` inventories the remaining registered MIME types; `SYNC-TO-REPO.md` is the explicit public-copy manifest.
