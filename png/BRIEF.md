# Brief: verified PNG decoder (Verus) — scope

Status: specification phase, draft 0.2; the theorem manifest (`THEOREMS.md`, M0) and its review brief (`REVIEW-BRIEF.md`) are drafted, not reviewed. The draft spec is `spec-draft/` (PNG-CORE-SPEC 0.2: SPEC.md P1–P21, a 62-name closed error list, the Strict oracle `png_oracle.py` with a hand-written inflate, 796 vectors (598 Strict, 198 profile) exercising all 62 errors), the leniency catalogue is `policy-draft/` (30-field record, four profiles, closed `recovered` events R1–R5, 16 owner questions), and the proof plan is `PLAN.md`. The owner decided PNG-Q1–Q15 on 2026-11-16 (`policy-draft/DECISIONS.md`; Q16 is not relevant yet). Nothing is frozen and no Rust exists yet. Freeze order (PNG-Q7): Strict's decode rules (`spec-draft/`) may freeze first, once the corpus pass is not needed for them (the surplus-output and Adam7 defects are repaired in 0.2); RecommendedBeta and the cap values freeze only after a pass over a pinned real PNG corpus. Each freeze writes a `FREEZE.txt` with hashes, and this brief then gains the binding rules of `../dib/BRIEF.md`, `../dib/BRIEF-POLICY.md` and `../alloc-delta/SPEC.md` unchanged.

## Goal

A feature-complete PNG decoder with the guarantees the DIB/BMP, TGA and (planned) GIF cores have: safety (T1) for every input and every policy record; exact equality with the frozen model (T2 and the integrated entry-point theorems), including the first error, for every result that is not `OutOfMemory` (an `Ok` result implies model success unconditionally; GIF erratum lesson, `THEOREMS.md` T13); allocation bounds (T3) through the sealed `alloc_guard` with `try_*` entry points, `OutOfMemory` outside the format error set, and the G/Prog/PreAlloc theorem shape of `../alloc-delta/THEOREMS-ALLOC-DELTA.md`; termination; a linear work bound; and the policy machinery: a closed `recovered` event list (R1–R5), the Strict bridge (`policy(Strict) = core model` for every input), obligation E (`recovered` iff an event occurred) and obligation R (RecommendedBeta returns identical RGBA with `recovered=false` on every Strict-accepted input). Both crates are `no_std + alloc`; the inflate crate needs no `alloc` at all.

## Features in scope

- **Datastream.** Signature, chunk layout, CRC-32 on every chunk, chunk-type letters, critical vs ancillary (unknown critical rejected, unknown ancillary skipped, reserved bit treated as unknown), the third edition's ordering table including the APNG chunks, duplicates, IEND, trailing bytes.
- **IHDR.** All fifteen colour-type/bit-depth pairs: greyscale 1, 2, 4, 8, 16; truecolour 8, 16; indexed 1, 2, 4, 8; greyscale+alpha 8, 16; RGBA 8, 16. Compression and filter method 0, interlace 0 or 1.
- **PLTE and tRNS.** Palette length and entry count rules; suggested palettes in truecolour images (validated, not applied); tRNS for colour types 0, 2 and 3 with exact key comparison at native depth and masking of unused high bits; tRNS forbidden for types 4 and 6.
- **zlib/DEFLATE.** RFC 1950 header (CM = 8, CINFO ≤ 7, FCHECK, FDICT rejected), stored, fixed and dynamic blocks, canonical Huffman construction with zlib's completeness rule, length/distance decoding with the declared window, Adler-32, nothing after the Adler-32, the image data as one stream over any number of IDAT (or fdAT) chunks of any size including zero, output size exactly `R(w,h)` (too little: `TruncatedImageData`; one byte more: `ExcessImageData`).
- **Scanlines.** The five filter types (None, Sub, Up, Average, Paeth), filter byte distance `max(1, bits/8)`, Adam7 with empty passes contributing no bytes, sub-byte packing.
- **Conversion.** RGBA8 (exact scaling for depths 1, 2, 4; rounding for 16, PNG-Q3) and RGBA16 (exact scaling from every depth).
- **Ancillary chunks.** Validated and exposed raw: gAMA, cHRM, sRGB, iCCP (name and method; profile through `icc_profile`), sBIT, cICP, mDCV, cLLI, bKGD, hIST, pHYs, sPLT, eXIf (byte range), tIME; tEXt, zTXt, iTXt validated structurally (keyword rules, separators, method bytes) and never inflated. None of them changes a pixel except tRNS (PNG-Q4: no gamma or colour management in the core, as in every measured incumbent).
- **APNG.** acTL, fcTL, fdAT with the shared sequence counter, frame rectangles inside the canvas, dispose ops NONE, BACKGROUND, PREVIOUS (PREVIOUS on the first frame acts as BACKGROUND), blend ops SOURCE and OVER (exact integer OVER, PNG-Q8), the default image as frame 0 or outside the animation, frame-count check, raw `num_plays` and `delay_num/delay_den`. Strict rejects APNG structural errors in the constructor; RecommendedBeta's constructor instead falls back to the default image as a single frame with R4 when its upfront walk finds a structural error before any frame is exposed, and every other failure (allocation, resource, critical-chunk, later inflate) still surfaces as an error, the default image having to decode itself (PNG-Q11; a design choice, no measured APNG decoder does it).

## API

```rust
pub fn try_decode_still(b: &[u8]) -> Result<Still, TryError>;            // default image, RGBA8 (P15)
pub fn try_decode_still16(b: &[u8]) -> Result<Still16, TryError>;        // RGBA16, any source depth
pub fn try_decode_still_with_policy(b: &[u8], p: Profile) -> Result<(Still, bool), TryError>;
pub fn try_decode_still16_with_policy(b: &[u8], p: Profile) -> Result<(Still16, bool), TryError>;   // PNG-Q13 (i)
pub struct Frames<'a> { /* borrowed input, canvas, Raw buffer, Saved, walk cursor */ }
impl<'a> Frames<'a> {
    pub fn try_new(b: &'a [u8]) -> Result<Frames<'a>, TryError>;                // Strict: walk + default image
    pub fn try_new_with_policy(b: &'a [u8], p: Profile) -> Result<Frames<'a>, TryError>;   // named profile
    pub fn info(&self) -> &Info;                                               // IHDR, colour chunks, num_plays
    pub fn try_next(&mut self) -> Result<Option<FrameView<'_>>, TryError>;     // fused after Err
}
pub struct FrameView<'f> { pub rgba: &'f [u8], pub rect: (u32, u32, u32, u32), pub delay: Option<(u16, u16)>,
                           pub dispose: u8, pub blend: u8, pub recovered: bool }
pub fn try_icc_profile(b: &[u8]) -> Result<Option<Vec<u8>>, TryError>;   // P17, Strict
pub fn try_icc_profile_with_policy(b: &[u8], p: Profile) -> Result<Icc, TryError>;  // Icc = Absent | Discarded | Failed(Error) | Present(Vec<u8>) (PNG-Q4); P1, after MI_p (D14)
pub fn chunks(b: &[u8], p: Profile) -> ChunkIter<'_>;                    // borrowed (type, data, status) after a walk; text for glue (PNG-Q13 (ii)); P1, after MChunks_p (D15); signature open
pub enum ChunkStatus { Accepted, Discarded(DiscardReason) }              // DiscardReason: BadCrc | Misplaced | Duplicate | InvalidValue
```

The 16-bit policy entry point and the chunk status are owner additions of 2026-11-16 (PNG-Q13); `policy_oracle.py` has no API-level model for them. `chunks` yields every chunk whose framing is valid, in file order, with a status, so glue cannot reinstate a chunk the profile discarded: only `Accepted` chunks have a verified CRC and a place the profile allows (under Strict every chunk is `Accepted` or the walk failed). Metadata access is three-valued (absent, discarded by the profile, present; the ICC profile also failed-to-decode), and a malformed ICC payload never blocks pixel decoding. `Info` carries the IHDR fields, palette entry count, tRNS presence, raw gAMA, cHRM, sRGB, cICP, mDCV, cLLI, sBIT, bKGD, pHYs and tIME values, the iCCP profile name and the eXIf byte range. `TryError` is `Format(Error) | OutOfMemory(OutOfMemory)` with the 62 error names of P18. Delay mapping (image: `den = 0 → 100`, milliseconds; glycin additionally `0 ms → 100 ms`) and loop translation belong to the glue.

Representation and status, as the council ruled on the M1b questions (M1BQ, 2026-11-20; `png_verus/QUESTIONS.md` Q4, Q5):

- **`Still16`.** `rgba16: Vec<u8>` holds `8·W·H` bytes in pixel order: four samples per pixel in R, G, B, A order, each 16-bit sample two bytes, most significant first (big-endian), on every host. Consumer glue converts when its destination requires another layout; on a little-endian host, reinterpreting the bytes as native `u16` is not a conversion. The bytes keep the shared, hash-pinned `alloc_guard` byte-identical across cores (no `u16` allocation site); T13's model sample `i` is `256·bytes[2i] + bytes[2i+1]` (ERRATA E3).
- **`Frames` constructors.** `Frames::try_new(b)` constructs Strict decoding and `Frames::try_new_with_policy(b, p)` takes a named profile, as D1 and PNG's still entries, GIF, DIB and TGA name them. Both use the same constructor implementation: `try_new(b)` is defined as `try_new_with_policy(b, Profile::Strict)`, with identical errors and guard requests. `Frames` does not implement `Iterator`: each returned frame view borrows the decoder's reusable canvas. `THEOREMS.md` writes `Frames::try_new(b, p)` for `try_new_with_policy(b, p)` and `Frames::try_new(b, Strict)` for `try_new(b)` (ERRATA notation entry, proposed); `MWF_p`, allocation order and frame semantics are unchanged.
- **`Info` byte ranges.** `Info::iccp_name` and `Info::exif` are `(offset, length)` byte coordinates into the exact input slice passed to the entry point that returned the `Info`. They neither own nor retain that input and copy no metadata bytes, so `Info`, `Still` and `Still16` carry no input lifetime. The caller must retain the original input to resolve a pair; a pair applied to any other slice, even an in-bounds one, has no specified metadata meaning. That each returned pair is in bounds and denotes the model's range is the M3 gate L-INFO-RANGE (`PLAN.md`).
- **Deferred to P1.** `chunks` and `try_icc_profile_with_policy` are absent from the crate (no stub, no `unimplemented!`) and are not cancelled; each is implemented at P1 after its model is in `policy-draft/policy_oracle.py` (`MChunks_p` and T-CHUNKS under D15; `MI_p` under D14). Until then PNG-Q4 and PNG-Q13 are delivered only in part: `Info`'s three-valued `Meta` and the Strict `try_icc_profile` exist; text chunks, per-chunk status and `Icc::Discarded | Failed` do not, and integration must claim none of them.
- **`try_decode_still16_with_policy`.** A provisional implementation of D16 (`policy-draft/DECISIONS.md`): available, but covered by no conformance record, differential probe or M1b claim until P1's independent oracle and checks exist. Availability does not imply policy support.

How the output model meets the consumers:

- **gdk-pixbuf** wants RGB8 or RGBA8 (`io-png.c` strips 16-bit samples to their high byte and expands everything else) plus the options `icc-profile` (base64), `x-dpi`/`y-dpi` from pHYs and `tEXt::key` from text chunks. The glue copies `Still` into a pixbuf (dropping alpha when the source has none and no tRNS), base64-encodes `try_icc_profile`, converts pHYs and reads text through `chunks`. gdk-pixbuf has no APNG support (the loader shows the default image); a module could wrap `Frames` in a `GdkPixbufAnimation` as the GIF loader does.
- **image 0.25.10 / png 0.18.1** returns native depth (`L8 … Rgba16`) with `EXPAND`; `into_rgba8` rounds 16-bit samples exactly as P13.2 does. Its APNG decoder yields full-canvas RGBA8 frames, as `Frames` does.
- **glycin** passes 16-bit formats through (`R16g16b16a16` etc.) and needs the ICC profile, cICP, Exif and XMP. It would use `try_decode_still16` for 16-bit sources, `Info.cicp`, `try_icc_profile`, the eXIf range and the XMP iTXt through `chunks`; its animation path maps to `Frames`.

## Resource caps and allocation

Caps are the constants of SPEC P1 (one section; theorems are stated over the names, PNG-Q5): input 2^30 bytes (1 GiB; raised from 256 MiB on 2026-11-17 by the coordinator, pending owner objection); width and height ≤ 2^31 − 1 (the PNG wire limit); `4·W·H ≤ 256 MiB` (2^26 pixels); at most 65,536 frames and 2^30 frame pixels; ICC profile ≤ 16 MiB. These numbers are the owner's decision of 2026-11-17 (PNG-Q5; before: 16,384 per side and 64 MiB, a provisional baseline from 2026-11-16) and stay held out of the freeze until the PNG corpus pass (PNG-Q7) is re-run under them; the pass of 2026-11-16 ran under the old caps with a raised-cap side run and is the evidence for the raise (five valid files rejected at 16,384; largest real image 60.9 megapixels, 244 MiB). **The caps depend on the shared allocation guard `MAX_BYTES` (per reservation, copied byte-identically into every core) being raised from 67,108,864 to 2^30 by a separate change (alloc-delta erratum E16):** a 67-megapixel RGBA16 output is 512 MiB and `Raw` about the same, each one reservation. The input cap was 256 MiB until 2026-11-17, when a stored (uncompressed) 8192 × 8192 RGBA8 PNG (about 268 MB) exceeded it; at 2^30 every still image within the output caps fits a stored encoding, and only a stored APNG whose frame data together exceed the cap remains `FileTooLarge` (`policy-draft/DECISIONS.md` "Input-cap update"). The input is borrowed, so the raise changes no reservation; the proofs use 64-bit bit positions (`8·MAX_INPUT` does not fit `u32`, GIF erratum E3). Chunk lengths are bounded by `2^31 − 1` and the input; text chunk sizes need no cap because the core never inflates them; inflate output never exceeds the declared size `R(w,h)` (the decompression-bomb bound: work and memory are linear in the output the header already promised, whatever the compression ratio). Allocation (P20), all through the guard, none before the structural walk succeeds:

| Site | Bytes | Reserved |
|---|---|---|
| `Raw` | `R(W,H) ≤ 8·W·H + S(H) ≤ 8·W·H + 2H + 2` (filtered data; inflate's output and its own window; `S(H)` is the scanline count, more than `H` when interlaced) | once per decoder |
| `Output` | `4·W·H` (`8·W·H` for `try_decode_still16`), zero-filled | once per decoder |
| `Saved` | `4·W·H` | at the first frame (k > 0) whose disposal is PREVIOUS, once |
| `IccWindow`, `Icc` | 32,768, then the measured profile length | `try_icc_profile` only |

Peak live heap per entry point, with `N = W·H` (SPEC P20; figures at `N = 2^26`, `4N` = 256 MiB): `try_decode_still` `R + 4N` (8-bit RGBA twice the output, 512 MiB; 16-bit RGBA three times, 768 MiB); `try_decode_still16` `R + 8N` (768 MiB and 1 GiB; the RGBA16 output alone is 512 MiB); `Frames` `R + 4N`, plus `4N` once PREVIOUS disposal is used (512 MiB to 1 GiB); the Adam7 scanline term of a one-pixel-wide image adds up to 128 MiB; `try_icc_profile` at most 32 KiB + 16 MiB. Resolved (PNG-Q5, 2026-11-17): `Raw` for 16-bit RGBA and the RGBA16 output were single reservations above the old `MAX_BYTES`; with the guard at 2^30 each is below one reservation (SPEC P20). The walk keeps a fixed-size record (no chunk list, no frame list: data chunks are re-walked by offset), the Huffman tables are fixed arrays in the decoder state, inflate allocates nothing. `PreAlloc` holds exactly when the walk fails. `OutOfMemory` from `Saved` can displace a later format error of that frame (accepted for ICNS, alloc-delta D5). The `try_*` API, the sealed log, the removed non-`try` names and the `no_std + alloc` certification follow `../alloc-delta/SPEC.md` §1–§9 unchanged; A-STD-1/2 are the only trusted items.

## Decomposition (PNG-Q12)

Two crates: `inflate_verus` (zlib + DEFLATE; `no_std`, no `alloc`; API `inflate_zlib_into(src, out, options)` and `inflate_zlib_measure(src, ring, limit, options)`, each returning a status (`Done`, `Full`, `Err(e)`) and the bytes produced on every outcome (`THEOREMS.md` T-INFL, D6; this replaces the earlier single `inflate_zlib(src, out) -> Result<usize, InflateError>`, which could neither measure nor report the written prefix on an error); frozen interface `Inflate(Z, L, options)` = output prefix of length ≤ L or the first error, with five policy fields acting inside inflate (`adler`, `stream_end`, `zlib_tail`, `window`, `single_code`), the first-error order, and the distinction between output exactly full and another output byte existing; its documentation states that strict mode enforces the declared window, which stock zlib does not (PNG-Q15), so a non-PNG caller that needs zlib's behaviour passes `window=Ignore`; `Segments` abstracts IDAT/fdAT payload runs with a spec function `concat()`) and `png_verus` (chunks, filters, Adam7, conversion, APNG compositor, policy, guard). The split costs no speed (generic, inlined), no memory (output-as-window, zero allocation, so no cross-crate allocation log as ICO needed for DIB) and no PNG-side proof complexity (one frozen model function); it gives ICO, ICNS (both embed PNG), TIFF Deflate, zTXt/iCCP and any later format a verified inflate. The split is the owner's decision (PNG-Q12, 2026-11-16) and is consistent with the owner's GIF Q10 verdict, whose three costs do not arise here. The APNG compositor stays in `png_verus` (owner preference), as its own module and model.

## Guard-limit update — 2026-11-17

The owner approved alloc-delta erratum E16: `MAX_BYTES` is now 1,073,741,824
bytes (1 GiB), not 67,108,864 bytes (64 MiB). This supersedes the earlier plan
to choose the shared guard limit after the PNG corpus pass. DIB, TGA, ICNS,
ICO and GIF keep their existing 64 MiB output caps; a core may raise its cap
separately through its own erratum. PNG's owner-decided caps are now the PNG wire-limit dimensions and 256 MiB
RGBA8 output; freezing those values remains corpus-gated. The 1 GiB per-reservation guard accommodates the
512 MiB RGBA16 output for an 8192 × 8192 image and its filtered raw buffer;
the earlier statements that those proposed PNG reservations exceed the guard
limit describe the pre-E16 guard, not the current limit. Verification and
audit evidence, including pending DIB verification, is in
`alloc-delta/ERRATA.md` E16 and `RELEASE-GATES.md` item 1.
