# PNG proof phase: work breakdown

Conclusion first: two crates (`inflate_verus`, then `png_verus`), both `no_std` and `try_*`-only from the first line, proved in the order inflate first: the inflate crate's plain implementation (M1a) and proofs (M2) start as soon as Strict's decode rules are frozen (Stage 1), because they depend neither on the cap values nor on RecommendedBeta; `png_verus` follows in M1b and M3–M6, and the policy milestones P1–P2 come last. Estimated size, calibrated on the earlier cores: 2,300–3,400 verified obligations for both crates with Strict and RecommendedBeta (inflate 700–1,000 of them), and 40–60% more for the two compatibility profiles; 1,900–3,200 `verify.sh` runs; 18–24 dispatches. The obstacles most likely to cost runs are canonical Huffman table construction and its completeness check, the bit reader over segmented input, in-place filter reconstruction with Paeth, and the APNG iterator invariant. The theorem manifest is `THEOREMS.md` (M0 draft); the review brief and the staged freeze commands are `REVIEW-BRIEF.md`.

Calibration: DIB reached 1,557 obligations over 1,560 logged runs (core 1.0, the 1.1 mode, policy P1–P2, allocation work); TGA 947 obligations over 720 runs; ICNS 315 over 258; ICO 303 over 174; the GIF plan estimated 1,600–2,400 obligations and 1,200–2,000 runs for a comparable feature set without a separate decompressor (`gif_verus` stands at 729 verified obligations after its errata). PNG's chunk walk has about three times TGA's header rules (25 chunk types, an ordering table, per-chunk value rules); its inflate is harder than GIF's LZW (two code tables rebuilt per block, a completeness check, overlapping copies); filters, Adam7 and fifteen sample formats have no precedent in these cores; the APNG compositor is GIF's with blending added. Runs per obligation have been 0.6–1.0; the estimate uses 0.8–0.95 because inflate's bit-level proofs resemble GIF's LZW, the costliest part of that plan.

## Structure

- `inflate_verus/src/model.rs`: the frozen model `Inflate(Z, L, o)` (P9–P10: header, blocks, codes, Adler-32, tail; `o` the five policy fields `adler`, `stream_end`, `zlib_tail`, `window`, `single_code`) as total spec functions over `Seq<u8>`, transcribed from SPEC.md independently of the executable: the output is a sequence built by appending, a match is defined on that sequence, a code by its canonical codewords (`THEOREMS.md` models table, D17). `huffman.rs` (canonical codes: counts, first codes, symbol table; decode), `bits.rs` (LSB-first reader over `Segments`; a byte offset and at most 63 buffered bits, no `u32` bit counter), `inflate.rs` (blocks, LZ77 copy into the caller's slice, and the measuring variant with a `WINDOW_MAX`-byte ring), `adler.rs`. Entry points `inflate_zlib_into` and `inflate_zlib_measure` (`THEOREMS.md` D6). No allocation; no guard; no `alloc` dependency.
- `png_verus/src/model.rs`: `MW(b)` (the walk P2–P8, P14.1: a document record and ghost data ranges per image), `MWF_p(b)` (the constructor's walk with the R4 fallback), `R(w, h)` and `MPass` (P11, P12), `MF(raw, …)` (unfiltering, P11), `MC8`/`MC16` (conversion, P13), `MD` (one image's decode, P11–P13), `MOver` and `MK(canvas, …)` (P14.3–P14.4), `MS(b)`/`MS16(b)`/`MFr(b)`/`MI(b)` (P15–P17). The models call `inflate_verus::model::Inflate` by path; there is no second inflate model. Policy-indexed versions take the record (P1). `limits.rs` (the six caps and `caps_ok`), `walk.rs`, `filter.rs`, `adam7.rs`, `convert.rs`, `compose.rs`, `png.rs` (entry points, iterator), `alloc_guard/{mod.rs,sites.rs}` (the hash-pinned guard of `../alloc-delta/SPEC.md` §3 with `MAX_BYTES` of erratum E16; sites `Raw`, `Output`, `Saved`, `IccWindow`, `Icc`; no palette-expansion, row, chunk-list or frame-list buffer, `THEOREMS.md` "Allocation shape").
- Tests: `tests/conformance.rs` over all 810 records of the three files of the pre-freeze split (done 2026-11-17: `spec-draft/VECTORS.json`, 599, frozen at Stage 1 as `spec-frozen/VECTORS.json`; `limits-draft/VECTORS-CAPS.json`, 13; `policy-draft/VECTORS-POLICY.json`, 198; the `MAX_INPUT + 1` and `MAX_INPUT` `pad_to` records, the `MAX_TOTAL_PIXELS` pixel-budget records and the two `MAX_ICC` profiles as runtime tests), the probe inputs, and the zlib cross-check of `check_vectors.py` re-run against the Rust inflate.

Every limit from SPEC P1 is a `pub const` in `limits.rs`, and every theorem mentions the constants by name (`R ≤ 2·MAX_OUTPUT + MAX_OUTPUT/2 + 2`, from `R ≤ 8·W·H + S(H)`, `S(H) ≤ 2H + 2` and `H ≤ MAX_OUTPUT/4`; `4·W·H ≤ MAX_OUTPUT`; `P ≤ MAX_TOTAL_PIXELS`), never their values; arithmetic-overflow lemmas take the constants' ranges as preconditions, collected in one lemma `caps_ok` (`THEOREMS.md` Constants: `MAX_DIMENSION ≤ 2^31 − 1`, with `W·H` and `4·W·H` in `u64`, exact since `4·(2^31 − 1)^2 < 2^64`; `5·MAX_OUTPUT/2 + 2 ≤ MAX_BYTES`; `2·MAX_OUTPUT ≤ MAX_BYTES`; `MAX_ICC ≤ MAX_BYTES`; `MAX_INPUT ≤ 2^60`; `MAX_TOTAL_PIXELS ≤ 2^62`), so a rebuild with new values re-verifies without proof edits as long as `caps_ok` holds (owner decision on caps, PNG-Q5); gate CAPS-SYM checks this by one verification run per cap at a changed value (GIF's finding 6 showed that a lint alone does not). The values (owner decision 2026-11-17: `MAX_DIMENSION = 2^31 − 1`, `MAX_OUTPUT` = 256 MiB; coordinator decision 2026-11-17 pending owner objection: `MAX_INPUT = 2^30`) stay held out of the freeze until the corpus pass (M0-corpus) is re-run under them. They depend on the shared guard's `MAX_BYTES`, which alloc-delta erratum E16 raised to 2^30 with every core re-verified; with it, `Raw` (at most 640 MiB) and the RGBA16 output (512 MiB) each fit one reservation (SPEC P20), and A-PNG-3 states `R ≤ MAX_BYTES` and `8N ≤ MAX_BYTES` as consequences of `caps_ok`. The input cap was raised because a stored 8192 × 8192 RGBA8 PNG (about 268 MB) exceeded 256 MiB; the input is borrowed, so no reservation changes, and inflate and walk positions are 64-bit (`8·MAX_INPUT` does not fit `u32`; GIF erratum E3).

**M0-corpus — the real-corpus pass (PNG-Q7; not yet run).** On a pinned corpus (`BRIEF.md` "Corpus plan") record, per Strict error, how many real files hit it and, per RecommendedBeta field, its final outcome; report incidental assets (icons, screenshots, web images) separately from test and fuzz files; include large screenshots (multi-monitor), long thin images and stored (uncompressed) PNGs near the output cap to test the raised caps (2^31 − 1 per side, 256 MiB output, 2^30 input) and `MAX_BYTES`; the 2026-11-16 pass ran under the old caps and is to be re-run; keep a hold-out; reconcile the input counts (748 records in `results.json`, 737 distinct inputs in the Strict bridge, 740 after the three vectors of 2026-11-16, 767 after the 198 profile vectors, 773 after the six cap-boundary vector inputs of 2026-11-17, 784 after the 11 vector inputs added by the review and the council the same day). Gate for Stage 2; compatibility profiles are re-measured on held-out files afterwards (PNG-Q14).

**M1a — inflate, plain implementation (first; after Stage 1).** Ordinary Rust outside `verus!` for `inflate_verus`, `no_std` without `alloc`, both entry points. Done when the Rust inflate agrees with `png_oracle.py`'s inflate on every zlib stream of the 810 records (status, output and, on error, the written prefix, D5 decided), with zlib on 10,000 random streams and single-bit corruptions (only `EXPECTED_ZLIB_DIFFERENCES`), and the measuring variant returns the same counts as the writing one.

**M2 — inflate proofs (`inflate_verus`, T-HUFF, T-INFL, T-SEG).** (a) Huffman construction: from lengths `ℓ[0..n)`, the executable counts, first codes and symbol table represent RFC 1951's canonical codewords (L-CANON, L-PREFIX-FREE); the oversubscription and completeness checks equal the Kraft conditions of P10.3, stated as exact sums `Σ 2^(15−ℓ)` in `u32`; decoding reads the same bits and returns the same symbol, or the same error at the same position, as the model's prefix-match definition, with D4's rule (council decision: `InvalidSymbol` as soon as the bits read are a prefix of no codeword, `TruncatedZlib` only while they are a proper prefix of one). (b) Blocks and symbols: for all `Z`, `L` and option tuples, the executable returns `Inflate(Z, L, o)` exactly (status, written prefix, untouched suffix), including `Full` before byte `L + 1` and the stream-order position of each error; the Strict tuple first, RecommendedBeta's two values (`window = Ignore`, `zlib_tail = IgnoreTail`) at P1, the rest at P2. (c) Bit reader over segments: reading `k` bits at state `s` equals reading the ghost concatenation at `pos(s)` (L-BITS; the GIF sub-block obstacle in another form). (d) LZ77: an overlapping copy `out[i] = out[i − d]` for `d < len` writes the model's sequence (L-WINDOW; L-RING for the measuring variant); distances checked against both the output length and the declared window. (e) Adler-32 equals the model's mod-65,521 sums with the 5,552-byte deferral (L-ADLER). Termination: every iteration consumes at least one bit or returns. Work, in two disjoint ghost counters (`THEOREMS.md` Step accounting): `core_steps ≤ C_IN·|Z| + C_OUT·k + C_INFL_FIXED` for every loop body except the bit reader's segment-advance iterations, and `seg_steps ≤ C_SEG·(seg_count() + 1)` for those iterations (the `+ 1` is the advance past the final segment that reports end of input); the call's total work is `core_steps + seg_steps`, and the PNG readers discharge `seg_steps` from the container (12 bytes per chunk, L-SEG-PNG); a dynamic header that reaches table construction has read at least 45 bits (L-HDR-BITS), and its at most 316 code-length entries and three table builds are charged to them. Witnesses: the 54 M2 gates of `THEOREMS.md` (each P10 error, stored length boundary, single-code tables, empty distance code, distance = output length, 258-length runs, window boundary, the limit cases) plus the T-SEG records.

**M1b — PNG, plain implementation (may run in parallel with M2).** Ordinary Rust outside `verus!` for `png_verus` with the guard in place, calling `inflate_verus`. Done when all 810 records pass, every probe input matches `png_oracle.py` on accept/reject and pixels, the source lint passes (cap numerals, allocation outside the guard), and the leniency harness gains a `verified` PNG runner agreeing with Strict.

**M3 — chunk walk (T2, T6, prefix of T10, A-PNG-2, A-PNG-7).** `MW` equality with the exact first error for every input: CRC table and CRC-32 (L-CRC-TABLE: table construction as a lemma over 256 entries against a bitwise definition), type letters, lengths, the ordering automaton (a fixed record: IDAT phase, PLTE seen, singleton set as a bit mask, APNG counters), per-chunk value rules, keywords. The data streams are ghost: `MW` returns, per image, the sequence of payload ranges; the executable keeps only the offset of the first data chunk and re-walks (L-REWALK; `Segments` implementations proved against the ghost ranges, T-SEG). Allocation: `Raw` and `Output` reserved exactly when `MW` (for the constructor `MWF_p`) succeeds (G, Prog, the `PreAlloc` corollary).

**M4 — scanlines (T-FILT, T-A7).** (a) In-place unfiltering in `Raw`: row `r` of a pass is reconstructed from the reconstructed row `r − 1` that precedes it in the same buffer; the five filters equal the model byte by byte (Average's `⌊(a + b)/2⌋` in `u16`; Paeth's three absolute differences in `i16`, with the tie order as a lemma). (b) Adam7: pass sizes `⌊(w + dx − 1 − x0)/dx⌋` with no case split; the exact pass sum `Σ pw·ph = w·h` from the halving identities `⌈x/2d⌉ + ⌈(x − d)/2d⌉ = ⌈x/d⌉`; the pass map a bijection onto `[0, w) × [0, h)` for all `1 ≤ w, h ≤ 2^31 − 1`; `R(w, h)` computed without overflow, with `R ≤ 8·w·h + S(w, h)`, `S(w, h) ≤ 2h + 2` (the bound `h·(1 + 8w)` is false for interlaced images, SPEC P11), and monotone in `w, h` (needed for reusing `Raw` across frames). (c) Every pixel write lands in `[0, 4·W·H)`.

**M5 — conversion and compositor (T4, T8, A-PNG-4 in part).** (a) Fifteen sample formats to RGBA8 and RGBA16: sub-byte unpacking, the exact scaling identities (`v·255/(2^d − 1)` integral for `d ∈ {1, 2, 4, 8}`, `v·65535/(2^d − 1)` for all five depths, `s16 = 257·s8` for `d ≤ 8`), the 16-bit rounding identity `⌊(v·510 + 65535)/131070⌋ = ⌊(v + 128)/257⌋`, tRNS key masking and exact comparison, palette lookup with the index check. (b) APNG: disposal on rectangles, `Saved` (reserved at the start of call `SavedAt`, D9), OVER with the exact rounding of P14.4 (division by `A ∈ [255, 65025]`; the result bounded by 255 as a lemma), and the canvas equality `canvas_k = MK(canvas_{k−1}, …)` stated per position; `Saved` stated only through restore (GIF erratum E1's form).

**M6 — integration (T9–T13, T-ITER, T-PLAYS, A-PNG-1, -4, -5).** `try_decode_still(b)` agrees with `MS(b)` in the alloc-delta form: an `Ok` result implies model success unconditionally, and equality of every RGBA byte and of the first error holds for every result that is not `OutOfMemory`; likewise `try_decode_still16`, `try_icc_profile` (two inflate passes: the measuring pass's count equals the model's output length, and the second pass at `L = m` cannot fail, L-LIMIT-MONO); T-ITER: for every input and every `k`, the `k`-th `try_next` returns the `k`-th element of `MFr(b)`, then `Ok(None)` or the error, then `Ok(None)` on every later call without allocating or resuming decoding (D3, council decision 2026-11-17), over all reachable decoder states and call sequences (as DIB's T7 and GIF's T-ITER). Work bound: `steps = core_steps + seg_steps ≤ C_WORK·(|b| + R + N + P) + C_FIXED`, summed over iterator calls. Witnesses (`model_vectors.rs`, the M3–M6 gates of `THEOREMS.md`), runtime conformance, mutation campaign (40 mutations and the alloc-delta set), CAPS-SYM.

**P1 — Strict/RecommendedBeta.** Typed `#[non_exhaustive]` `Profile`; the 30-field record internal and `#[cfg(test)]`-constructible; the spec-level Strict bridge `M*(Strict) = M*`; RecommendedBeta's fifteen non-Strict fields (fourteen full relaxations and the narrowed `zlib_tail = IgnoreTail`, PNG-Q1, Q2 and Q11) with obligations E (R1, R3 and R4 are the events reachable in RecommendedBeta) and R (P-R: a simulation with four synchronisation points, not lockstep; `apng_in_still = Ignore` needs the APNG walk state left out of the still entry's relation, `THEOREMS.md` D22); T1/T3/T11/T12 universal over every record (P-UNIV). `IgnoreTail` keeps the inflate limit at `R` (surplus output stays `ExcessImageData`); no profile raises it above `R` (D12, council decision 2026-11-17: an attempt to emit byte `R + 1` is the surplus detection; reaching `R` does not end inflate, which continues to the stream end and the Adler-32); `zlib_tail = Ignore` and `stream_end = AtRaster` are the only candidates for a later exception, which needs a bounded surplus rule, its checksum behaviour and an R2 detector first. The constructor's upfront walk implements the R4 fallback of `apng_errors = Static` for structural errors only (PNG-Q11). ## Hardest verification obstacles

1. **Huffman construction and decoding.** The canonical-code arithmetic (counts → first codes → symbol offsets), the Kraft-sum completeness test, and the decoder's bit-by-bit search must be tied to a model that defines a code by its canonical codewords and the prefix property; an incomplete code (single code, empty distance code) must decode exactly the bit strings the model assigns and report `InvalidSymbol` for the others, at the position D4 fixes (the first bit after which no codeword can follow). This is new to these cores; the LZW table of GIF is the closest precedent.
2. **The bit reader over segmented input.** DEFLATE codes straddle IDAT/fdAT boundaries (including zero-length chunks); the reader's local state (current chunk offset, remaining length, bit buffer) must be related to one ghost position in the concatenation built by the walk. The re-walk instead of a stored chunk list keeps memory constant but adds a lemma that the re-walk sees the same chunks the structural walk validated.
3. **In-place unfiltering with Paeth.** Reconstructing a row in the same buffer that holds the previous reconstructed row, with `bpp` look-behind, signed intermediate arithmetic and the Paeth tie order, for fifteen `(colour type, depth)` byte layouts and seven pass widths.
4. **Overlapping LZ77 copies into the output slice, and the ring.** `d < len` copies read bytes written earlier in the same copy; the model is a sequence defined by appending, the executable a loop over a mutable slice that is also the window, or over a 32 KiB ring in the measuring variant.
5. **The chunk ordering automaton.** Twenty-five chunk types, each with its own position rule, duplicate rule and value rules, against a fixed-size state; the first-error ordering of P18 must be preserved exactly. Large but shallow: many small obligations rather than hard ones.
6. **The APNG iterator invariant.** Decoder state (re-walk cursor, frame index, previous disposal and rectangle, `Saved`, canvas) equal to the model's after `k` frames for every `k`, with the fused state; frames reuse `Raw` sized for the full image.
7. **Linear work with expanding output.** One 258-byte match costs constant input; the bound charges output bytes to `C_OUT·k` and Huffman rebuilds to the at least 45 header bits that trigger them.

## Mutation candidates (implementation-side, for M6)

The 40 of `THEOREMS.md`, each tied to a vector and a theorem: swap BTYPE 1 and 2; read Huffman codes LSB-first; accept an incomplete literal/length code with two codes; skip the NLEN check; off-by-one in the 258 length base; accept distance code 30; allow a distance equal to output + 1; skip the window check; compute Adler-32 without the modulo deferral boundary; drop the Adler-32 check; report the limit one byte early; read a bit position into a `u32`; ignore the CRC of ancillary chunks; accept PLTE after IDAT; allow a second gAMA; skip the first chunk's CRC; compute `4·W·H` in `u32`; test `|b| ≥ MAX_INPUT`; Paeth with `pb < pc` instead of `≤`; Average without the floor; Sub with `bpp = 1` for RGB8; count a filter byte for empty Adam7 passes; swap passes 4 and 5; compare the 16-bit tRNS key on the high byte only; strip instead of round 16-bit samples; treat PREVIOUS on frame 0 as NONE; save only the rectangle but restore the whole canvas for PREVIOUS (restoring the whole canvas from a whole-canvas save is not a mutation, D10); OVER with truncation; reserve `Saved` per frame (A-PNG-3 must kill it); reserve `Saved` on the still path; reserve before the walk ends; return `OutOfMemory` after a successful call; swallow a guard error; re-walk the chunk list per scanline (T12 must kill it); reserve `Icc` at `MAX_ICC` before measuring; let `IgnoreTail` discard surplus output; keep reading after a dead Huffman prefix (D4); test fdAT payload length instead of presence; drop a truncated stored block's present bytes (D5); repeat the terminal error on the next call (D3).

## Compositor in the same crate?

Yes (owner preference; no strong reason against). Frames decode into `Raw` and are converted straight onto the canvas, so the compositor and the conversion share the pixel-address lemmas; the policy fields `blend`, `dispose_previous` and `apng_errors` act inside the frame loop; a split would need a per-frame RGBA buffer of up to `MAX_OUTPUT` and a cross-crate allocation log. Keep it a separate module with its own model function (`MK`) so its proofs run after M4–M5 without reopening them.

bytes (1 GiB), not 67,108,864 bytes (64 MiB). This supersedes the earlier plan
