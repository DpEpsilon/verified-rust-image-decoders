# PNG proof phase: work breakdown

Conclusion first: two crates (`inflate_verus`, then `png_verus`), both `no_std` and `try_*`-only from the first line, proved in seven core milestones (M0–M6) and two policy milestones (P1–P2). Estimated size, calibrated on the earlier cores: 2,300–3,400 verified obligations for both crates with Strict and RecommendedBeta (inflate 700–1,000 of them), and 40–60% more for the two compatibility profiles; 1,900–3,200 `verify.sh` runs; 18–24 dispatches. The obstacles most likely to cost runs are canonical Huffman table construction and its completeness check, the bit reader over segmented input, in-place filter reconstruction with Paeth, and the APNG iterator invariant.

Calibration: DIB reached 1,557 obligations over 1,560 logged runs (core 1.0, the 1.1 mode, policy P1–P2, allocation work); TGA 947 obligations over 720 runs; ICNS 315 over 258; ICO 303 over 174; the GIF plan estimates 1,600–2,400 obligations and 1,200–2,000 runs for a comparable feature set without a separate decompressor. PNG's chunk walk has about three times TGA's header rules (25 chunk types, an ordering table, per-chunk value rules); its inflate is harder than GIF's LZW (two code tables rebuilt per block, a completeness check, overlapping copies); filters, Adam7 and fifteen sample formats have no precedent in these cores; the APNG compositor is GIF's with blending added. Runs per obligation have been 0.6–1.0; the estimate uses 0.8–0.95 because inflate's bit-level proofs resemble GIF's LZW, the costliest part of that plan.

## Structure

- `inflate_verus/src/model.rs`: the frozen model `Inflate(Z, L)` (P9–P10: header, blocks, codes, Adler-32, tail) as total spec functions over `Seq<u8>`, transcribed from SPEC.md independently of the executable. `huffman.rs` (canonical codes: counts, offsets, symbol table; decode), `bits.rs` (LSB-first reader over `Segments`), `inflate.rs` (blocks, LZ77 copy into the caller's slice), `adler.rs`. No allocation; no guard.
- `png_verus/src/model.rs`: `MW(b)` (the walk P2–P8, P14.1: a document record and ghost data sequences per image), `MR(doc, w, h)` (`R`), `MF(raw, …)` (unfiltering, P11), `MA7(w, h)` (the pass map, P12), `MC8`/`MC16` (conversion, P13), `MK(canvas, frame, …)` (P14.3–P14.4), `MS(b)`/`MS16(b)`/`MFr(b)`/`MI(b)` (P15–P17). Policy-indexed versions take the record (P1). `walk.rs`, `filter.rs`, `adam7.rs`, `convert.rs`, `compose.rs`, `png.rs` (entry points, iterator), `alloc_guard/{mod.rs,sites.rs}` (the hash-pinned guard of `../alloc-delta/SPEC.md` §3; sites `Raw`, `Output`, `Saved`, `IccWindow`, `Icc`).
- Tests: `tests/conformance.rs` over `spec-draft/VECTORS.json` (all 592, the 256 MiB `pad_to` record and the 2^30 pixel-budget record as runtime tests), the policy vectors once generated, the probe inputs, and the zlib cross-check of `check_vectors.py` re-run against the Rust inflate.

Every limit from SPEC P1 is a `pub const` in one module, and every theorem mentions the constants by name (`R ≤ 2·MAX_OUTPUT + MAX_DIMENSION`, `4·W·H ≤ MAX_OUTPUT`, `P ≤ MAX_TOTAL_PIXELS`), never their values; arithmetic-overflow lemmas take the constants' ranges as preconditions (for example `MAX_DIMENSION ≤ 2^20`, `MAX_OUTPUT ≤ 2^31`), so a rebuild with new values re-verifies without proof edits as long as those ranges hold (owner decision on caps, PNG-Q5).

## Milestones

**M0 — freeze.** Owner answers PNG-Q1–Q13. Write `THEOREMS.md` for both crates in the shape of `../dib/THEOREMS.md` (T1–T13 restated, plus T-HUFF, T-INFL, T-FILT, T-A7, T-ITER below), independent review (`REVIEW-SOL-*.md`), freeze `spec-draft/` → `spec-frozen/` with `FREEZE.txt`. Run the corpus pass (PNG-Q7) before the freeze of RecommendedBeta.

**M1 — plain implementation.** Ordinary Rust outside `verus!` for both crates, with the guard in place. Done when all 592 vectors pass, the Rust inflate agrees with zlib on the cross-check streams and on 10,000 random streams and corruptions, every probe input matches `png_oracle.py` on accept/reject and pixels, and the leniency harness gains a `verified` PNG runner agreeing with Strict.

**M2 — inflate core (`inflate_verus`, T-HUFF, T-INFL).** (a) Huffman construction: from lengths `ℓ[0..n)`, the executable counts, offsets and symbol table equal the canonical code of [1951 §3.2.2]; the over-subscription and completeness checks equal the Kraft sum conditions of P10.3, stated as exact rational sums `Σ 2^(15−ℓ)` in `u32`; decoding a code reads the same bits and returns the same symbol as the model's prefix-match definition. (b) Blocks and symbols: for all `Z`, `L`: the executable returns `Inflate(Z, L)` exactly, output prefix and first error, including `OutputFull` at byte `L+1` and the stream-order position of each error. (c) Bit reader over segments: reading `k` bits at state `s` equals reading the ghost concatenation at position `pos(s)` (the GIF sub-block obstacle in another form). (d) LZ77: an overlapping copy `out[i] = out[i−d]` for `d < len` writes the model's sequence; distances checked against both the output length and the CINFO window. (e) Adler-32 equals the model's mod-65521 sums with the 5,552-byte deferral. Termination: every iteration consumes at least one bit or returns. Work: `steps ≤ c·(|Z| + L)` (a dynamic header costs at most 320 code-length symbols per at least 26 bits read). Witnesses: about 25 streams (each P10 error, stored length boundary, single-code tables, empty distance code, distance = output length, 258-length runs, window boundary).

**M3 — chunk walk (T1–T3, prefix of T10).** `MW` equality with the exact first error for every input: CRC table and CRC-32 (table construction as a lemma over 256 entries, computed by `compute` or by a recursive spec function), type letters, lengths, the ordering automaton (a fixed record: IDAT phase, PLTE seen, singleton set as a bit mask, APNG counters), per-chunk value rules, keywords. The data streams are ghost: `MW` returns, per image, the sequence of payload ranges; the executable keeps only the offset of the first data chunk and re-walks (`Segments` implementation proved against the ghost ranges). Allocation: `Raw` and `Output` reserved exactly when `MW` succeeds (G, Prog, the `PreAlloc` corollary).

**M4 — scanlines (T-FILT, T-A7).** (a) In-place unfiltering in `Raw`: row `r` of a pass is reconstructed from the reconstructed row `r−1` that precedes it in the same buffer; the five filters equal the model byte by byte (Average's `⌊(a+b)/2⌋` in `u16`; Paeth's three absolute differences in `i16`, with the tie order as a lemma). (b) Adam7: the pass map is a bijection from the non-empty passes onto `[0,w) × [0,h)` for all `1 ≤ w, h ≤ MAX_DIMENSION`, pass sizes `⌈(w−x0)/dx⌉` with empty passes; `R(w,h)` computed without overflow and monotone in `w, h` (needed for reusing `Raw` across frames). (c) Every pixel write lands in `[0, 4·W·H)`.

**M5 — conversion and compositor.** (a) Fifteen sample formats to RGBA8 and RGBA16: sub-byte unpacking, the exact scaling identities (`v·255/(2^d−1)` integral for `d ∈ {1,2,4,8}`, `v·65535/(2^d−1)` for all five depths), the 16-bit rounding identity `⌊(v·510 + 65535)/131070⌋ = ⌊(v+128)/257⌋`, tRNS key masking and exact comparison, palette lookup with the index check. (b) APNG: disposal on rectangles, `Saved` (reserved at the first PREVIOUS frame), OVER with the exact rounding of P14.4 (division by `A ∈ [1, 65025]`; the result bounded by 255 as a lemma), and the canvas equality `canvas_k = MK(canvas_{k−1}, …)` stated per position.

**M6 — integration (T9–T13, T-ITER).** `try_decode_still(b) = MS(b)` exactly, every RGBA byte and the first error; likewise `try_decode_still16`, `try_icc_profile` (two inflate passes: the measuring pass's length equals the model's output length); T-ITER: for every input and every `k`, the `k`-th `try_next` returns the `k`-th element of `MFr(b)` then `None` or the error, then the same again, over all reachable decoder states and call sequences (as DIB's T7 and GIF's T-ITER). Work bound: `steps ≤ c·(|b| + R + N + P)`, summed over iterator calls. Witnesses (`model_vectors.rs`, about 30 gates), runtime conformance, mutation campaign.

**P1 — Strict/RecommendedBeta.** Typed `#[non_exhaustive]` `Profile`; the 29-field record internal and `#[cfg(test)]`-constructible; the spec-level Strict bridge `M*(Strict) = M*`; RecommendedBeta's fourteen fields with obligations E (R1, R2, R3 are the events reachable in RecommendedBeta) and R; T1/T3/T11/T12 universal over every record, including the bounded tail of `zlib_tail=Ignore` (the inflate limit becomes `R+1`, never unbounded). Policy vectors generated in `policy-draft` style (expectations from intent, checked by `policy_oracle.py`).

**P2 — compatibility profiles.** GdkCompat-2.42.12 (`HighByte`, `RejectBeforeIdat`, `StopAtRaster`, `GdkGrey`/`GdkPartial` with the grey fill, `apng=Off`) and ImageCrateCompat-0.25.10 (`ImageRs` after-IDAT, ordering, value and tRNS rules, `Ignore` Adler-32, `AtRaster`, `Prefix`, `dispose_previous=ImageRs`, `apng16=Reject`). `blend=ImageF32` is not verified: Verus's floating-point support does not reach an exact model of f32 rounding, so either an exact integer characterisation of image's results is found and proved, or the field is dropped and recorded as a residual (PNG-Q8). Gate each field separately, as the GIF plan does.

## Hardest verification obstacles

1. **Huffman construction and decoding.** The canonical-code arithmetic (counts → first codes → symbol offsets), the Kraft-sum completeness test, and the decoder's bit-by-bit search must be tied to a model that defines a code by its prefix property; an incomplete code (single code, empty distance code) must decode exactly the bit strings the model assigns and report `InvalidSymbol` for the others. This is new to these cores; the LZW table of GIF is the closest precedent.
2. **The bit reader over segmented input.** DEFLATE codes straddle IDAT/fdAT boundaries (including zero-length chunks); the reader's local state (current chunk offset, remaining length, bit buffer) must be related to one ghost position in the concatenation built by the walk. The re-walk instead of a stored chunk list keeps memory constant but adds a lemma that the re-walk sees the same chunks the structural walk validated.
3. **In-place unfiltering with Paeth.** Reconstructing a row in the same buffer that holds the previous reconstructed row, with `bpp` look-behind, signed intermediate arithmetic and the Paeth tie order, for fifteen `(colour type, depth)` byte layouts and seven pass widths.
4. **Overlapping LZ77 copies into the output slice.** `d < len` copies read bytes written earlier in the same copy; the model is a sequence defined by recursion on position, the executable a loop over a mutable slice that is also the window.
5. **The chunk ordering automaton.** Twenty-five chunk types, each with its own position rule, duplicate rule and value rules, against a fixed-size state; the first-error ordering of P18 must be preserved exactly. Large but shallow: many small obligations rather than hard ones.
6. **The APNG iterator invariant.** Decoder state (walk cursor, sequence counter, current frame's data offset, previous disposal and rectangle, `Saved`, canvas) equal to the model's after `k` frames for every `k`, with the fused error state; frames reuse `Raw` sized for the full image.
7. **Linear work with expanding output.** One 258-byte match costs constant input; the bound charges output bytes to `R` and Huffman rebuilds to the header bits that trigger them.

## Mutation candidates (implementation-side, for M6)

Swap BTYPE 1 and 2; read Huffman codes LSB-first; accept an incomplete literal/length code with two codes; skip the NLEN check; off-by-one in the 258 length base; accept distance code 30; allow a distance equal to output + 1; skip the window check; compute Adler-32 without the modulo deferral boundary; drop the Adler-32 check; ignore the CRC of ancillary chunks; accept PLTE after IDAT; allow a second gAMA; Paeth with `pb < pc` instead of `≤`; Average without the floor; Sub with `bpp = 1` for RGB8; count a filter byte for empty Adam7 passes; swap passes 4 and 5; compare the 16-bit tRNS key on the high byte only; strip instead of round 16-bit samples; treat PREVIOUS on frame 0 as NONE; restore the whole canvas for PREVIOUS; OVER with truncation; reserve `Saved` per frame (T3 must kill it); re-walk the chunk list per scanline (T12 must kill it).

## Compositor in the same crate?

Yes (owner preference; no strong reason against). Frames decode into `Raw` and are converted straight onto the canvas, so the compositor and the conversion share the pixel-address lemmas; the policy fields `blend`, `dispose_previous` and `apng_errors` act inside the frame loop; a split would need a per-frame RGBA buffer of up to 64 MiB and a cross-crate allocation log. Keep it a separate module with its own model function (`MK`) so its proofs run after M4–M5 without reopening them.
