# PNG core theorem manifest (M0 draft, not frozen)

This manifest states what the PNG proof phase must prove against PNG-CORE-SPEC draft 0.3 (`spec-draft/SPEC.md`, P1–P21), which the Stage-1 freeze copies to `spec-frozen/` (`REVIEW-BRIEF.md`), and, for the P rows, against policy draft 0.2 (`policy-draft/OPTIONS.md`). It has the shape of `../gif/THEOREMS.md` and `../dib/THEOREMS.md`, with the fallible-allocation shape of `../alloc-delta/THEOREMS-ALLOC-DELTA.md` built in from the first line: there is no infallible entry point, no retired theorem and no wrapper. Two crates (`PLAN.md`, Structure): `inflate_verus` (`#![no_std]`, no `alloc`, modules `model`, `bits`, `huffman`, `inflate`, `adler`) and `png_verus` (`#![no_std]` with `alloc`, modules `model`, `limits`, `walk`, `filter`, `adam7`, `convert`, `compose`, `policy`, `png`, `alloc_guard`). Section "Discrepancies found" lists the conflicts found between the drafts, each Resolved (with how), Stage 2 (a working proposal held out of Stage 1) or Open; the rows that depend on one name it. The independent review `REVIEW-SOL-THEOREMS.md` (findings 1–9) and the council decisions on D3, D4, D5, D9 and D12 (2026-11-17, 4–0 each) are applied; section "Review findings applied" maps each finding to the rows it changed.

The manifest applies the seven lessons of `../gif/ERRATA.md` from the start: (1) executable success implies model success unconditionally, and the reverse direction and every error equivalence are stated under the antecedent that the result is not `OutOfMemory`; (2) obligation R binds RecommendedBeta and declared-conservative records only; (3) every model is an independently evolving mathematical object (the inflate model appends to a byte sequence and decodes codes by prefix match over canonical codewords; it never shares the executable's tables or buffers), tied to the executable by named representation lemmas; (4) caps appear only by name, never as numerals, and every bit position in the inflate and the walk is 64-bit or a `nat`, with no `u32` bit counter; (5) statements about buffers and layouts say what is observable and leave the rest unspecified; (6) every domain restriction is explicit (byte-valued operands, sample ranges, symbol ranges); (7) every theorem is stated over the actual public entry points, and `png_verus` calls the same public `inflate_verus` functions that T-INFL covers, so no standalone/integrated split of the kind `../gif/ERRATA.md` E2 records can arise.

No executable code, Python oracle or incumbent library may be imported into the models. The proofs hold for 32-bit and 64-bit Rust slice domains (`|b| ≤ isize::MAX` on each target). No `assume`, `admit`, `external_body`, trusted FFI, `unsafe`, false precondition, new `assume_specification` or ghost claim disconnected from a concrete call establishes any obligation. Each proof report states the verifier, vstd, rustc and Verus versions. Allocation failure is **inside** the guarantee: it is the result `Err(OutOfMemory(o))`, related to the sealed log by `G` (below); only allocator behaviour itself, the trusted items of "Not proved, and trusted", and compiler or verifier unsoundness are outside it.

## Constants

Every resource cap is written by its P1 name and by no numeral: `MAX_INPUT`, `MAX_DIMENSION`, `MAX_OUTPUT`, `MAX_FRAMES`, `MAX_TOTAL_PIXELS`, `MAX_ICC`. Their values live only in `limits-draft/LIMITS.md` and `limits-draft/limits.py` (split out of SPEC P1 on 2026-11-17; `limits-frozen/` from Stage 2) and, in the crate, only in `png_verus/src/limits.rs`; a source lint (M1b) fails on any of the six values written elsewhere in `src/` of either crate, in comments included. The shared guard's per-reservation limit is `MAX_BYTES` (`../alloc-delta/SPEC.md` §3, raised by `../alloc-delta/ERRATA.md` E16), also by name only. A cap change is one edit to `limits.py`/`LIMITS.md` and one to `limits.rs`, and every statement below is unchanged by it, provided the new values satisfy `caps_ok` (lemma, proved once from the constants and used by every arithmetic proof; no proof may use a cap's value except through it) and lie in the Stage-1 fixture envelope of `LIMITS.md` (which keeps every frozen vector's outcome; `REVIEW-BRIEF.md`):

- (a) `1 ≤ MAX_DIMENSION ≤ PNG_WIRE_MAX`;
- (b) `4 ≤ MAX_OUTPUT`, `5·MAX_OUTPUT/2 + 2 ≤ MAX_BYTES` (largest `Raw`) and `2·MAX_OUTPUT ≤ MAX_BYTES` (RGBA16 `Output`);
- (c) `1 ≤ MAX_ICC ≤ MAX_BYTES`;
- (d) `MAX_INPUT ≤ 2^60`, so `8·MAX_INPUT + 64 < 2^64`;
- (e) `1 ≤ MAX_FRAMES ≤ 2^32 − 1`;
- (f) `MAX_TOTAL_PIXELS ≤ 2^62`, so `T + w·h < 2^64` for `T ≤ MAX_TOTAL_PIXELS` and `w, h ≤ PNG_WIRE_MAX`;
- (g) `MAX_BYTES ≤ 2^31 − 1` (alloc-delta's own fact: one reservation fits a 32-bit `isize`);
- (h) `WINDOW_MAX ≤ MAX_BYTES` (the constant `IccWindow` request; a fact about the format constant and the guard, listed here so that a lowered `MAX_BYTES` is caught by the same lemma).

Assurance gate CAPS-SYM (M6): one verification run per cap with that cap alone changed to another value inside `caps_ok` (halved, and doubled where `caps_ok` allows), each with zero proof edits, recorded in `RUNLOG.tsv`. GIF's finding 6 (`../gif/ERRATA.md` E3 (c)) shows why a lint alone is not evidence that the proofs are symbolic.

Format constants of RFC 1950/1951 and the PNG text, not caps, named here and used by name: `PNG_WIRE_MAX = 2^31 − 1` (chunk lengths, IHDR and fcTL wire limit), `MAX_CODE_BITS = 15`, `WINDOW_MAX = 32,768` (the largest DEFLATE window and the `IccWindow` request), `LEN_MAX = 258`, `NLIT_MAX = 286`, `NDIST_MAX = 30`, `NCL = 19`, `ADLER_MOD = 65,521`, `ADLER_NMAX = 5,552`, `BLEND_MAX = 255`.

Work constants, fixed by this manifest because SPEC P20 leaves `c` open (the reviewer checks that a plain implementation meets them, `REVIEW-BRIEF.md` item 6): `C_IN = 512` steps per input byte and `C_OUT = 8` steps per output byte inside inflate, `C_INFL_FIXED = 4,096` once per inflate call (fixed-code tables, state reset); `C_CALL = 1,024`, `C_WORK = 2·C_CALL = 2,048`, and `C_FIXED = 65,536` once per public call (CRC table if built at run time: 2,048 iterations; the `IccWindow` zero fill: `WINDOW_MAX` elements; constant-size state initialisation). `C_IN` covers a dynamic-block header: by L-HDR-BITS a header that reaches table construction has read at least 45 bits, and the implementation budget for one header (at most `NLIT_MAX + NDIST_MAX` = 316 code-length entries written plus the three canonical tables built) is below 2,048 iterations, at most `C_IN/8 = 64` steps per bit (D11). `C_SEG = 1` step per segment the bit reader advances past, empty segments included (T-SEG, T12): charged separately, not to `C_IN`, because a reader can skip arbitrarily many empty segments without consuming a byte of `Z`.

Notation: `MH(b)` is the header prefix (P2, the first chunk by P3, P4), the same for every record (L-MHP); when it succeeds it gives `W`, `H` and the IHDR record. For a record `p`, `N_p = W·H` and `R_p = R(W, H)` (P11) when `MW_p(b)` succeeds (for the constructor: `MWF_p(b)`), and 0 otherwise; `W` and `H` are `MH(b)`'s, so `N_p` and `R_p` are either 0 or the one record-independent shape. `N = N_STRICT` and `R = R_STRICT`. (Finding 5: defining `N` from `MW(b)` alone made the request of a profile that recovers an input Strict rejects evaluate to zero.) for frame `k` (zero-based, in stream order) `A_k = w_k·h_k` from its fcTL, and `A_0 = N` for the single frame of a stream without acTL; `R_k = R(w_k, h_k)`; `P` is the sum of `A_k` over the frames whose data is inflated by `MFr`. `STRICT` is the record whose 30 fields take the bold values of `OPTIONS.md`; `RB` is RecommendedBeta's record; `INFL(p)` is the five-field projection `(adler, stream_end, zlib_tail, window, single_code)` of record `p`, and `INFL_STRICT = (Check, Require, Reject, Enforce, Accept)`.

## Total mathematical models

Each model is the named spec section transcribed in a `model.rs` independently of the executable; this manifest does not restate the sections. Every model is total over finite byte sequences and natural numbers; on arguments outside a reachable domain it returns the internal marker `OutsideDomain`, which is not a 63rd error. Model errors are exactly P18's 62 names. Arithmetic is on mathematical integers; every guarded read checks availability first (SPEC Conventions).

`Accepted_still(b) ⇔ MS(b) is Ok`; `Accepted_stream(b) ⇔ MFr(b) = Frames{_, _, _, Iend}`. `SavedAt_p(b)` is the least `k ≥ 1` such that frame `k` of `MWF_p(b)` has `dispose_op = 2` and `k ≤ |MFr_p(b).frames|` (frames `0..k−1` were returned, so call `k` is reached), or none: SPEC P20's step S (D9, council decision 2026-11-17).

**Step accounting** (P20, Work). Every concrete loop body increments a ghost `steps: nat` by one per iteration, and each library or guard call that fills or copies `k` elements adds `k`; straight-line code adds nothing, so a call that runs no loop adds 0. `inflate_verus`'s entry points return their own `steps` as a ghost value that the caller adds. For iterator call number `n` (`n = 0` is the first `try_next`), `Δ_n` is the length of frame `n`'s span: the bytes from the start of its fcTL chunk to the start of the next fcTL chunk or of IEND, and 0 for an IDAT-based frame 0 and for the single frame of a stream without acTL (the constructor inflated those). The spans are disjoint, so `Σ_n Δ_n ≤ |b|`. `seg_steps` is the bit reader's own counter (T-SEG): one per segment it advances past; it is returned beside `steps` and charged to the container (T12).

## Allocation shape (alloc-delta §0, unchanged definitions)

`fmt_part`, `L`, `req(L)`, `G(f, Eq_f, Req)` (clauses 1–3), `log_tied`, `Prog` and `PreAlloc` are exactly as in `THEOREMS-ALLOC-DELTA.md` §0. `inflate_verus` has no `alloc` dependency and no guard; it writes only into the caller's slice. In `png_verus` every reservation is a byte-counted `try_zeroed(site, n)` (or, for D8's empty profile, `try_with_room::<u8>(Icc, 0)`) of the hash-pinned guard, so no guard text or admitted audit type changes.

## Quantified obligations

Each row holds for every `b` representable as a slice on either target. "Every record" means every value of the policy record type implemented at that milestone, including `#[cfg(test)]` records; "every finite call sequence" means `Frames::try_new` followed by any finite interleaving of `info()` and `try_next()`. Milestones are `PLAN.md`'s: M1a/M2 `inflate_verus`, M1b and M3–M6 `png_verus`, P1–P2 policy.

### T-HUFF and T-INFL sub-obligations (M2)

- L-PREFIX-FREE: for non-oversubscribed `ℓ`, no `cw(ℓ, s)` is a proper prefix of another, and distinct symbols have distinct codewords. L-CANON (representation lemma): the executable's `count[n]`, first code of length `n` and symbol order (by length, then symbol value) decode bit string `x` of length `n` to `s` iff `x = cw(ℓ, s)`; stated over the code-level function `cw`, never over raw table slots, so an unused slot's contents are unspecified (the R11 lesson of `../gif/THEOREMS.md`).
- L-WINDOW (representation lemma): at every reachable inflate state, `out[0..written) = model out` for the model state at the same bit position; a match `(n, d)` with `d ≤ written` and `d ≤ win` writes `out[written + j] = out[written + j − d]` for `j = 0..n−1` in increasing `j`, which equals the model's sequence definition, including `d < n` (overlap) and `d = written` (`deflate/distance-equals-output`). The distance is checked against `written` (bytes output so far in this stream) and against `win` before the first byte of the match is written.
- L-RING: in `inflate_zlib_measure`, at every reachable state with `k` bytes produced, `ring[(k − 1 − j) mod WINDOW_MAX] = model out[k − 1 − j]` for every `j < min(k, WINDOW_MAX)`; every admissible distance is at most `WINDOW_MAX`, so every byte a match reads is present.
- L-LIMIT: `Full` is returned exactly when the model would append byte `L + 1`; a match crossing the limit writes the bytes that fit, then returns `Full` (the oracle's behaviour, P10.6); a stored block that reaches `L` exactly is not `Full` (D5). Reaching `L` is not termination: decoding continues to the stream end and the Adler-32 with no further output permitted (D12). L-LIMIT-MONO: if `Inflate(Z, L, o) = {Done, out, _}` and `|out| ≤ L' ≤ L` then `Inflate(Z, L', o) = {Done, out, _}`.
- L-ADLER: the executable's running sums with the modulo taken at least once every `ADLER_NMAX` bytes (`u32` without overflow: `ADLER_NMAX` is the largest `n` with `255·n·(n + 1)/2 + (n + 1)·(ADLER_MOD − 1) < 2^32`) equal `Adler(out)`.
- L-HDR-BITS: a dynamic-block header that reaches the construction of the literal/length table has read at least 45 bits: 3 block-header bits, 14 count bits, at least 12 code-length-code bits (`HCLEN + 4 ≥ 4` lengths of 3 bits), and at least 16 bits of code-length symbols. The last part is an aggregate coding-cost argument, not a per-symbol one: the code-length code is complete, so every codeword has at least 1 bit, and a symbol costs at least 1 bit (a literal length, 1 entry), 3 bits (16: 1 + 2 extra, at most 6 entries), 4 bits (17: 1 + 3 extra, at most 10 entries) or 8 bits (18: 1 + 7 extra, at most 138 entries); at least `257 + 1 = 258` entries are needed. With two or more 18s the cost is at least 16 bits; with at most one, the other at least 120 entries cost at least 0.4 bits each (17's rate), at least 48 bits. (The former supporting claim, "at least two code-length symbols of at least 8 bits each", is false: a valid header can use one-bit code-length symbols throughout and reads 329 bits; finding 8, reproduced.) The header's work (at most 316 entries and three table builds, below 2,048 iterations) is charged to these bits (T12, D11).
- L-HDR: the dynamic header equals P10.5 step by step: `HLIT + 257 > NLIT_MAX` or `HDIST + 1 > NDIST_MAX` before any code-length bit; the code-length lengths in the order of P10.5; symbol 16 with no previous length and a repeat past `HLIT + HDIST` entries are `InvalidCodeLengths`; symbol 256's length is checked before admissibility; admissibility of the literal/length code before the distance code.
- Bit positions: the reader keeps a byte offset (`usize`) and at most 63 buffered bits; the ghost position is a `nat`; no `u32` holds a bit count or bit position (lesson 4).
- Termination variant and work: T11, T12.
- Policy forms (P1): `window = Ignore` (only `written` bounds the distance); `zlib_tail = IgnoreTail` (bytes after an Adler-32 that matched an output of exactly `L` bytes are not examined; `Full` unchanged). Values of P2 (`adler = Ignore`, `stream_end = AtRaster`, `zlib_tail ∈ {Ignore, StopAtRaster}`, `single_code = Reject`) are stated at P2 against `OPTIONS.md`; all of them keep the limit `L` (D12): under `StopAtRaster`, `Ignore` and `AtRaster` the attempt to produce byte `L + 1` ends inflating with R2, its Adler-32 unexamined, until P2 specifies a bounded surplus rule.

### T-ITER (M6; P1 for every record)

Fix `b`, a record `p`, and `F = MFr_p(b)` with `n_F = |F.frames|`, assuming `Frames::try_new(b, p)` returned a decoder. `wf_p(b, n)` is the decoder invariant relating the concrete state (frame index, re-walk cursor, sequence position, previous frame's effective disposal and rectangle, `Saved` and whether it is reserved, `Raw`, canvas, fused flag, log) to the model state after `n + 1` calls (`n = −1` after the constructor). `try_next` requires only `wf_p(b, n)` for some `n` and ensures `wf_p(b, n + 1)` and the result below; `info()` is pure. Therefore, for every reachable decoder state and every finite call sequence, with no earlier call having returned `OutOfMemory`, call `n` returns:

1. for `n < n_F`, `Ok(Some(v))` with `v.rgba@ = F.frames[n].rgba` and `v.rect`, `v.delay`, `v.dispose`, `v.blend`, `v.recovered` equal to `F.frames[n]`'s;
2. for `n = n_F`, `Err(Format(e))` if `F.end = Err(e)`, and `Ok(None)` if `F.end = Iend`;
3. for `n > n_F`, `Ok(None)`, and the call neither allocates (A-PNG-7: it appends nothing to the log) nor resumes decoding (it runs no loop and inflates nothing); so each terminal error is returned exactly once (D3, council decision 2026-11-17: SPEC P1 now says this);
