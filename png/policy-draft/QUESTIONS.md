# PNG core and policy: owner decisions and places the spec guessed

Each item names the decision, the options and a recommendation, and can be read on its own. PNG-Q1–Q13 block a freeze of PNG-CORE-SPEC 0.1 and its policy record; PNG-Q14–Q16 can be settled later without changing RecommendedBeta. Nothing here is decided. "Strict" is the core spec (`../spec-draft/SPEC.md`); "RecommendedBeta" is the provisional recommended profile, which may only turn Strict errors into successes and must decode every Strict-accepted image identically (obligation R). "image" is the `image` crate 0.25.10 with the `png` crate 0.18.1 behind it (glycin uses the same code with a newer png revision); "gdk-pixbuf" is version 2.42.12 with libpng 1.6.48. Evidence names (`probe:…`, `vec:…`, `wit:…`) refer to `OPTIONS.md` and `probes/results.json`.

## Decisions that block a freeze

**PNG-Q1. RecommendedBeta's field set.** RecommendedBeta = Strict plus fourteen relaxations, each replacing an error Strict returns: skip an ancillary chunk whose CRC is wrong; ignore IEND's CRC and length; treat end of file after the image data as IEND; ignore bytes after IEND; drop misplaced, duplicate (keeping the first) and invalid ancillary chunks, including an invalid tRNS; ignore a PLTE in a greyscale image or after the image data of a truecolour image; allow more palette entries than the bit depth can index; draw out-of-range palette indices black (PNG-Q6); ignore bytes after the zlib stream and surplus decompressed data; ignore the zlib window size declared in the header; let the still decoder ignore animation chunks. gdk-pixbuf and image agree on each of these (identical pixels), except the missing IEND, which image rejects when the file ends right after the image data. Only a dropped tRNS, surplus data and a black palette substitution set `recovered`. *Recommendation: accept.* On the 289 synthetic inputs that Strict rejects and image or the gdk-pixbuf loader accepts, this set accepts 231; most of the rest are damaged image data (PNG-Q10) and animation errors (PNG-Q11).

**PNG-Q2. CRC checking.** Strict checks the CRC of every chunk and rejects any mismatch. The PNG specification lets decoders skip CRCs, and recommends ignoring damaged ancillary chunks. libpng (so gdk-pixbuf) and image reject a bad CRC on a critical chunk (IHDR, PLTE, IDAT) and silently drop an ancillary chunk with a bad CRC; stb_image checks nothing. Options: (a) Strict checks all, RecommendedBeta drops bad ancillary chunks (current draft); (b) Strict also drops bad ancillary chunks; (c) no CRC checks at all (faster by one table lookup per byte; a damaged chunk length then misaligns the parser silently). *Recommendation: (a).* Note that dropping a damaged tRNS changes transparency (`probe:crc-trns`); RecommendedBeta reports that through `recovered`.

**PNG-Q3. 16-bit samples reduced to 8 bits.** Strict rounds: `(v + 128) / 257`, the PNG specification's "most accurate" rule, which image also uses. gdk-pixbuf keeps the high byte (`v >> 8`, libpng's `png_set_strip_16`). They differ by one level on about half of all values (`probe:depth16-rgba`). Options: (a) round (current draft); (b) high byte. Both are equally easy to verify. *Recommendation: (a)*, with `depth16=HighByte` in GdkCompat-2.42.12 only. A caller that needs exact samples uses the 16-bit entry point (PNG-Q13).

**PNG-Q4. Gamma and colour management.** No measured decoder applies gAMA, cHRM, sRGB, iCCP or cICP to pixels (`probe:gamma-*`: identical output everywhere); image does not even report gAMA (the png crate never fills the field it reads). Options: (a) the core returns raw samples and exposes the colour chunks' raw values plus the ICC profile through a separate call (current draft); (b) the core applies gAMA (a floating-point or table-based transform, a large new proof obligation with no incumbent to match). *Recommendation: (a)*; glycin already performs colour management outside the loader.

**PNG-Q5. Resource caps.** All caps are constants in one section of the spec (P1) and the theorems are stated over their names, so each changes with one edit and a rebuild. Proposed: input at most 256 MiB; width and height at most 16,384; RGBA8 output at most 64 MiB (16.7 megapixels, the same as BMP, TGA and GIF); at most 65,536 animation frames and 2^30 frame pixels in total; a decompressed ICC profile at most 16 MiB. For scale: a 16.7-megapixel 16-bit RGBA PNG stored without compression is about 134 MB, so the input cap must exceed the output cap; a 4,000 × 4,000 photo is within the output cap, an 8,000 × 6,000 one is not. gdk-pixbuf has no cap below libpng's 1,000,000 × 1,000,000; image applies 512 MiB of allocation by default, but its PNG decoder disables limits when constructed directly (DESIGN-NOTES N16). Options: (a) these numbers; (b) a larger output cap for PNG only (for example 256 MiB, 67 megapixels), at the cost of proportionally more peak memory: output plus filtered data is twice the output size for an 8-bit RGBA image and three times for a 16-bit one, and an animation using PREVIOUS disposal adds one more output-sized buffer. *Recommendation: (a)*, revisiting (b) only if the real corpus (PNG-Q7) contains common images above 16.7 megapixels.

**PNG-Q6. Palette indices beyond the palette in RecommendedBeta.** The PNG specification gives no rule. libpng, gdk-pixbuf and image all draw such pixels opaque black, with identical results (`probe:index-oob-*`). For GIF the incumbents disagreed and the GIF draft recommended rejecting. Options: (a) RecommendedBeta draws black and sets `recovered` (current draft); (b) RecommendedBeta rejects like Strict. *Recommendation: (a)*, because the three incumbents agree bit for bit.

**PNG-Q7. Real-world corpus before freeze.** All measurements use 737 synthetic inputs (vectors, 177 targeted probes and 55 distinct witnesses from the earlier leniency run), plus, since GAPS-CLOSED.md gap 6, 800 synthetic held-out mutations of them; none is a real-world file. TGA's recommended profile was justified on 300 real files. *Recommendation: block the freeze of RecommendedBeta (not of Strict) on a pass over a pinned real PNG corpus* (PngSuite, the libpng, image-png and gdk-pixbuf test images, and a web or desktop-theme sample; see BRIEF.md "Corpus plan"), recording which Strict errors real files hit. Likely candidates: ancillary chunks after IDAT, iCCP profiles with non-conforming names, surplus zlib data, and APNG files with frame-count mismatches.

**PNG-Q8. Alpha blending arithmetic for APNG.** The specification asks for a "simple OVER operation" without a rounding rule. Strict uses exact integer arithmetic on 8-bit values with round-half-up (P14.4). image computes in 32-bit floating point and truncates, so its frames differ by one level on some semi-transparent pixels (`probe:apng-blend-over`). Options: (a) exact integer rounding in every profile except ImageCrateCompat (current draft); (b) match image's floating-point result everywhere (verifying 32-bit float arithmetic in Verus is impractical; it would remain a trusted surrogate). *Recommendation: (a)*; ImageCrateCompat's `blend=ImageF32` is modelled in Python only and should be dropped from that profile if no exact integer characterisation of image's results is found during P2.

**PNG-Q9. What `decode_still` validates.** Options: (a) the whole chunk stream up to IEND, including chunks after the image data, but inflating only the image data (current draft); (b) stop after the image data, as image does, so damage after the pixels (a bad CRC in a trailing text chunk, a missing IEND) never matters. For GIF the draft recommended the prefix reading, because the full alternative cost a decode of every frame; here (a) costs only a CRC pass over the rest of the file. *Recommendation: (a)* for Strict, with RecommendedBeta's relaxations covering the common post-image damage (missing IEND, trailing bytes, damaged ancillary chunks).

**PNG-Q10. Damaged image data in RecommendedBeta.** When the zlib stream is truncated or corrupt, gdk-pixbuf's loader returns the image anyway, with the missing rows filled with a fixed grey `#979899` (and the last good row lost when zlib detects the error in the same `inflate()` call that completed it, GAPS-CLOSED.md gap 2); `gdk_pixbuf_new_from_file`, libpng, image and libspng reject. image also ignores a wrong Adler-32 checksum. Options: (a) RecommendedBeta rejects all of these (current draft; GdkCompat-2.42.12 offers the grey-fill behaviour); (b) RecommendedBeta returns the decoded rows with transparent padding and `recovered=true`; (c) RecommendedBeta ignores only the Adler-32 checksum. *Recommendation: (a)*, as DIB, TGA and GIF did for truncated pixel data; revisit with the corpus.

**PNG-Q11. Animation errors.** Strict rejects an APNG with any structural error (sequence numbers, frame rectangles, frame count, missing frame data), and also rejects fcTL or fdAT chunks without acTL. Static decoders (gdk-pixbuf, libpng) show the default image of such files; image shows the frames before the error, then stops. Options for RecommendedBeta's frame iterator: (a) reject (current draft); (b) fall back to the default image as a single frame (`apng_errors=Static`, sets `recovered`); (c) return the frames before the error (`Prefix`, image's behaviour). For RecommendedBeta's still decoder the draft already ignores animation chunks entirely (PNG-Q1), so a broken animation never prevents showing the default image. *Recommendation: (b)*, because it never shows a partial animation and matches what every static viewer shows; it needs one more event (R4, already in the list).

**PNG-Q12. Crate decomposition.** Options: (a) one crate holding inflate, the chunk parser, filters, interlacing, conversion, the APNG compositor and the policy layer; (b) a separately verified `inflate_verus` crate (zlib + DEFLATE) plus `png_verus` (everything else, compositor included). Splitting costs nothing in speed (generic, inlined calls), memory (inflate writes straight into the caller's buffer and uses it as its own window, so it allocates nothing and needs no cross-crate allocation log) or simplicity of the PNG proofs (they consume one frozen model function, `Inflate(Z, L)`). It buys reuse: ICO and ICNS embed PNG, and TIFF (Deflate compression), PDF streams, zTXt, iTXt and iCCP all use zlib. The compositor stays inside `png_verus` (the owner's preference; it shares the canvas with frame decoding and three policy fields act inside it). *Recommendation: (b)*; this is the case the GIF Q10 verdict left open, because none of the three costs it named applies.

**PNG-Q13. API and output model.** Proposed: `try_decode_still` (RGBA8), `try_decode_still16` (RGBA16 for any source; 8-bit sources scaled by 257), a frame iterator yielding a borrowed whole-canvas RGBA8 view per frame with the raw `delay_num/delay_den`, dispose and blend values and `recovered`, `try_icc_profile` (decompressed ICC profile), and an `Info` record with the IHDR fields and the raw values of gAMA, cHRM, sRGB, cICP, mDCV, cLLI, sBIT, bKGD, pHYs, tIME plus borrowed byte ranges for eXIf. Text chunks are not decoded; a borrowed iterator over chunk byte ranges lets glue code read them. gdk-pixbuf needs RGBA8, the ICC profile, pHYs and text (it exposes `tEXt::` options); glycin needs RGBA8 or 16-bit output, the ICC profile, cICP, Exif and XMP (an iTXt chunk). Options: (a) as proposed; (b) also decode text chunks in the verified crate (a new allocation site and a bounded inflate per chunk); (c) drop the 16-bit entry point. *Recommendation: (a).*

## Decisions that can wait

**PNG-Q14. Compatibility profiles.** GdkCompat-2.42.12 matches the gdk-pixbuf loader (whole-buffer writes) on 721 of 721 compared inputs and `gdk_pixbuf_new_from_file` on 616; ImageCrateCompat-0.25.10 matches image on 718–720 of 721. Both were fitted on the same inputs they are measured on, and both include surrogate rules for undocumented library internals (the grey rows, image's frame-control and disposal quirks). *Gap closed (GAPS-CLOSED.md gaps 2, 5, 6): the grey-row rule is now derived from libpng and zlib source; image's two fcTL quirks and png 0.18.1's interlaced-subframe bug are modelled (fitted set: ImageCrateCompat 721/721 still and frames, glycin 720/721); on 395 held-out mutations frozen after these changes GdkCompat agrees on 389 and ImageCrateCompat on 395 (still) and 394 (frames); a one-field necessity check finds seven fields that break no measured input, each subsumed by another field (OPTIONS.md).* Options: (a) freeze both as opt-in, versioned names; (b) target `gdk_pixbuf_new_from_file` instead of the loader; (c) defer both until after Strict and RecommendedBeta are proved. *Recommendation: (c)*, then (a) with a held-out re-measurement on the corpus.

**PNG-Q15. Two places where Strict is stricter than zlib.** Strict rejects a back-reference farther than the window size the zlib header declares, and accepts a Huffman code with a single one-bit code (zlib's rule; fdeflate rejects it). Every measured decoder accepts the first (`probe:zlib-window-too-small`); RecommendedBeta already ignores the window. Options: keep both (current draft) or make Strict ignore the declared window. *Recommendation: keep.*

**PNG-Q16. The image crash.** png 0.18.1, used by image 0.25.10, panics on a palette chunk whose length is not a multiple of 3 (a 60-byte file; `probe:plte-len-13`), and image's PNG decoder disables allocation limits, so a 69-byte file declaring 65,535 × 65,535 pixels makes the process abort on a failed 17 GB allocation (`image::load_from_memory`, with its default 512 MiB limit, rejects it instead; glycin's loader code disables the limits and aborts too). glycin's newer png revision fixes the first. *Gap closed (GAPS-CLOSED.md gap 4): the file is 69 bytes, not 100; the `load_from_memory` and glycin outcomes were measured.* *Recommendation: route through the coordinator for a disclosure decision; the verified decoder is unaffected (both are caught by P6 and P4).*

## Places the spec had to guess

- **Palette index beyond PLTE**: an error in Strict; the specification gives no rule (N8).
- **bKGD values with high bits set**: range-checked in Strict, by reading the stated range as the rule (N10).
- **Huffman completeness**: zlib's rule (N5).
- **The declared CINFO window**: enforced in Strict; no incumbent does (N5, PNG-Q15).
- **fcTL or fdAT without acTL**: an error in Strict; every measured decoder ignores them.
- **OVER rounding**: exact integer round-half-up (PNG-Q8).
- **`GdkGrey` row loss**: no longer a guess. Derived from libpng 1.6.48's progressive reader and zlib 1.3.1's `inflate()` (GAPS-CLOSED.md gap 2; OPTIONS.md `image_data_error`); it gives the surrogate's result on all 748 fitted inputs and matches the loader on 10 held-out inputs the surrogate missed.
- **Error names on new paths**: compatibility profiles reuse core names (for example `InvalidBackground` for image's fatal bKGD-before-PLTE, `InvalidChunkType` for libpng's reserved-bit rejection). Native error strings are never compared.
