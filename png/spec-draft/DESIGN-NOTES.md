# Design notes for PNG-CORE-SPEC draft 0.1

Each note records where the strict core chose one reading of the PNG third edition or RFC 1950/1951, and what the incumbents do. "Measured" means the probe harness (`../policy-draft/probes/`, results in `probes/results.json`) ran image 0.25.10 with png 0.18.1, libpng 1.6.48, gdk-pixbuf 2.42.12 (Debian build; loader whole-buffer and byte-wise, `gdk_pixbuf_new_from_file`, animation), libspng and stb_image on the input named.

- **N1. Every CRC is checked.** [3e #13Error-checking] lets a decoder skip CRC checks and ignore ancillary chunks; Strict checks every chunk, because an unchecked CRC lets a damaged length desynchronise the walk. libpng, the gdk-pixbuf loader and the png crate drop an ancillary chunk with a bad CRC and reject a critical one (`probe:crc-trns`: the tRNS is dropped, so the pixels lose their transparency); stb ignores all CRCs, libspng ignores the IDAT CRC (`probe:crc-idat`). Option `crc_ancillary`.
- **N2. The structural walk precedes all pixel work.** P5 visits every chunk to IEND before inflating anything, so a CRC error in a tEXt after IDAT precedes an Adler-32 error in the image data. Every incumbent streams instead. The difference is visible only in which error is reported, except that streaming decoders can return pixels before discovering a later structural error (libpng's `png_read_end` "tail errors", image-rs never looking past IDAT, N11).
- **N3. Inflate, then filters, then indices.** P11 inflates the whole image stream before unfiltering, so any zlib error precedes `InvalidFilterType` and `PaletteIndexOutOfRange`. This matches the implementation plan (inflate into `Raw`, P20) and keeps the model a composition of three pure functions.
- **N4. No decompression-ratio cap.** Every inflate has a hard output limit known before it starts: `R(W,H)` from IHDR (or the fcTL size), `MAX_ICC` for iCCP. A stream that would produce more is `ExcessImageData` at the first surplus byte, so a DEFLATE bomb costs at most `R ≤ 2·MAX_OUTPUT + MAX_DIMENSION` bytes of output and linear work. Text chunks are never inflated by the core (P21), so zTXt/iTXt bombs cost nothing (`probe:ztxt-bomb-64m`, `probe:itxt-bomb-64m`: every decoder except libspng accepts; libspng hits its cache limit).
- **N5. Huffman acceptance follows zlib.** RFC 1951 does not say whether incomplete codes are allowed except for the one-distance-code case. P10.3 takes zlib's rule: complete codes, or exactly one code of length 1 (literal/length or distance), or no distance codes; reading an unassigned bit string is `InvalidSymbol`. fdeflate (the png crate) rejects a literal/length code with a single code (`probe:deflate-single-literal-code`: image rejects, libpng and gdk-pixbuf accept). Strict additionally enforces the CINFO window (`DistanceTooFar` for a distance beyond `2^(CINFO+8)`), which zlib does not: every measured decoder accepts `probe:zlib-window-too-small`, and the gdk-pixbuf loader with one-byte writes produces different pixels from the whole-buffer loader on it. Option `window`.
- **N6. No colour management.** No measured decoder changes a pixel for gAMA, cHRM, sRGB, iCCP or cICP (`probe:gamma-none`, `-045455`, `-1`, `-srgb`, `-chrm`, `-cicp-pq`, `iccp-valid`: identical hashes across all runners). The core exposes the raw values (P8.3) and the ICC profile through `icc_profile` (P17); colour management belongs to the caller (glycin applies the ICC profile itself; gdk-pixbuf exposes it as the `icc-profile` option). The png crate never sets `Info::source_gamma` (it parses gAMA into `gama_chunk` only), so `image`'s `gamma_value()` is always `None` (source reading, `stream.rs:1504`; PNG-Q4).
- **N7. 16-bit to 8-bit: rounding.** P13.2 uses `round(255·v/65535) = ⌊(v+128)/257⌋`, the "most accurate" scaling of [3e #13Sample-depth-rescaling]; image's `into_rgba8` uses the same formula (`color.rs:549`). libpng's `png_set_strip_16`, which gdk-pixbuf uses (`io-png.c:108–110`), keeps the high byte (`probe:depth16-rgba`: image = Strict, libpng = gdk-pixbuf = libspng = stb ≠ Strict). Option `depth16`, PNG-Q3.
- **N8. Palette indices beyond PLTE are errors.** The third edition gives no rule for an index `≥ E`. libpng, the gdk-pixbuf loader and the png crate all draw opaque black (`probe:index-oob-8bit`, `-1bit`, `-with-trns`, `-2bit-trns`: identical hashes; image's RGBA dump shows `000000ff`); stb differs. Strict rejects; RecommendedBeta draws black and sets R3 (PNG-Q6).
- **N9. Rules the core does not check.** sPLT name uniqueness (needs a set of names: unbounded state), the character set of tEXt/zTXt text and the UTF-8 validity of iTXt text (no incumbent checks them; content is not exposed), BCP 47 syntax of iTXt language tags, the "should not" pairing of sRGB and iCCP (`vec:anc-ok/srgb-and-iccp-both` is accepted), and the content of compressed text and of the ICC profile.
- **N10. bKGD values are range-checked, tRNS values are masked.** The tRNS text says decoders "must mask the other bits to 0 before the value is used" (`vec:trns/grey-d*-masked` accepted); the bKGD text first states the range 0 to `2^bitdepth − 1` and then gives the same masking advice. Strict reads the range as the rule (`InvalidBackground`); bKGD never changes a pixel, so RecommendedBeta drops such a chunk. libspng does not mask the tRNS key (`probe:trns-grey-high-bits`: libspng shows no transparency).
- **N11. `decode_still` validates the whole stream.** P15 walks to IEND (CRCs, order, APNG structure) but inflates only the IDAT data. image's static path stops at the first chunk header after the IDAT run and examines nothing later (`png 0.18.1 read_decoder.rs:128–134`; `probe:crc-iend`, `unknown-critical-after-idat`, `idat-then-iend-no-crc` accepted), and rejects a file that ends exactly after the last IDAT (`probe:truncated-after-idat`). libpng and the gdk-pixbuf loader accept a missing IEND; `gdk_pixbuf_new_from_file` rejects it (`png_read_end`). PNG-Q9.
- **N12. APNG.** The default image is frame 0 exactly when an fcTL precedes the first IDAT; otherwise it is decoded (and validated) for `decode_still` but not shown as a frame (`vec:apng/default-not-in-animation`). A first-frame `dispose_op = 2` acts as 1 ([3e #fcTL-chunk]). fcTL/fdAT without acTL are errors (`MissingAnimationControl`); image ignores them, as do the decoders without APNG support. OVER uses exact integer rounding (P14.4); image uses f32 arithmetic with truncating casts (`color.rs:868–925`), which differs on semi-transparent pixels (`probe:apng-blend-over`). image's `previous` buffer also differs from the spec after a frame whose disposal is PREVIOUS (`vec:apng/dispose-previous-first-frame-and-later`, modelled as `dispose_previous=ImageRs`). gdk-pixbuf has no APNG support: the loader shows the default image, `gdk_pixbuf_new_from_file` and the animation API reject the file (content sniffing yields `image/apng`, which no loader claims).
- **N13. Empty Adam7 passes have no filter bytes.** [3e #8InterlaceMethods]: a pass with no pixels contributes no scanlines. `probe:interlace-1x1-empty-pass-bytes` writes a filter byte for each empty pass; every decoder accepts it as excess data (Strict: `ExcessImageData`). The png crate computes its buffer size with one filter byte per row of an empty pass (source reading), which is harmless for valid streams.
- **N14. IDAT boundaries are meaningless; zero-length IDAT is valid.** `vec:idat/split-1-byte`, `vec:idat/zero-length-idats`, `probe:zero-length-idat-*`: all decoders agree. A stream consisting only of an empty IDAT is `TruncatedZlib` everywhere.
- **N15. Chunk-type letters and the reserved bit.** Non-letter type bytes are `InvalidChunkType` (libpng and gdk-pixbuf reject; image, libspng, stb accept: `probe:type-nonletter`). A set reserved bit makes the chunk unknown, not invalid ([3e #13Chunking]); libpng rejects such a chunk before IDAT ("bad header"), and the gdk-pixbuf loader inherits that (`probe:reserved-bit-ancillary`), but accepts one after IDAT (`vec:container/unknown-ancillary-everywhere`).
- **N16. Panics and aborts in an incumbent.** png 0.18.1 panics on a PLTE whose length is not a multiple of 3 (`vec:plte/length-8`, `probe:plte-len-13`, `-14`: index out of bounds in `transform/palette.rs:72–74`, reached through `image::codecs::png::PngDecoder`, so any `image` 0.25.10 user decoding untrusted PNGs without `catch_unwind` can be crashed by a 60-byte file). glycin's png revision rejects such a PLTE instead. `PngDecoder::new` also disables image's allocation limits (`codecs/png.rs:42–51`), so a 65535×65535 IHDR with 100 bytes of data makes the process abort on a failed 17 GB allocation (`probe:dims-65535-square-tiny-data`, under a 768 MiB address-space limit; `image::load_from_memory` with its default 512 MiB limit is UNVERIFIED). Reported here only; disclosure is the coordinator's decision (PNG-Q16).
