The canonical hosts `www.w3.org` and `www.rfc-editor.org` refuse connections from this sandbox, as `w3.org` did for the GIF phase. **Status of `png-3e-index.html` against the published REC `https://www.w3.org/TR/2025/REC-png-3-20250624/` (checked 2026-11-14): UNVERIFIED at the text level.** The published text could not be fetched. The one independent record of it that could be fetched shows the published page is not the tag's file unchanged: it lacks one link and one reference that the tag has. Failed with `curl: (35) Recv failure: Connection reset by peer`: `www.w3.org` (the REC, the PR/CR/CRD snapshot URLs, `/TR/png-3/`, the errata page, `api.w3.org`), `www.rfc-editor.org`, `web.archive.org`, `archive.org/wayback`, `archive.ph`, `archive.softwareheritage.org`, `w3c.github.io`, `cdn.jsdelivr.net`, `data.jsdelivr.com`, `unpkg.com`, `cdnjs.cloudflare.com`, `api.cdnjs.com`. WebFetch gives `ECONNRESET` for `www.w3.org` and refuses `web.archive.org`; WebSearch works but returns model-written summaries, none used as evidence. Reachable: `api.github.com`, `github.com`, `raw.githubusercontent.com` (and the npm and PyPI registries, which hold nothing relevant).

What GitHub says. `Third-Edition` is a lightweight tag on `037f3c3` (authored 2025-06-17, committed 2025-06-24 17:09 UTC, three hours after the README commit "published today"); branch `third-edition` is the same commit; the release "Third Edition" only links the REC URL; there is no `gh-pages` branch (GitHub Pages serves `main`). The git blob SHA-1 of the local file (`866f0691c039629f0b192760af0f6162d7e6cd00`) equals the blob at the tag, and a fresh `raw.githubusercontent.com/w3c/png/Third-Edition/index.html` has the SHA-256 in the first row. Against its parent the tag commit changes only the ReSpec config (`specStatus`, `publishDate`, `errata`, `previousMaturity`) and adds two "Changes since … none" subsections. Before that `index.html` last changed on 2025-03-06, a week before the CR snapshot, so git holds one body text for CR, PR and REC; the transition requests (`w3c/transitions` #716, #725) also say "no changes". No commit between 2025-03-06 and the tag touches `index.html` (the parent still has `specStatus: "CR"`), so the PR of 2025-05-15 was rendered from a copy that is not in the repository's history.

What the independent record says. `w3c/webref` crawls the published page `https://www.w3.org/TR/png-3/` (`tr/`, reffy 19.0.1, 2025-06-25 01:36 UTC, page date "24 June 2025", generator ReSpec) and records its ids, headings, definitions, links and references, not its body text. I compared that crawl with the local source (HTML parser over `id`, `h2`–`h6`, `dfn`, `a href`) and with webref's `ed/` crawl of `w3c.github.io/png` from 2025-06-24 18:46 UTC, a ReSpec rendering of the tag content. Matches: all 335 `id` attributes of the local source exist in the published page; the 16 anchors SPEC.md cites exist there, each on a numbered heading (`fcTL-chunk` is 11.3.6.2, `13Chunking` is 13.5; the 17th grep hit, `anchor`, is the placeholder in SPEC.md's header); the two crawls have identical headings (183: number, title, id) and identical definitions (69); the published page has the anchors `changes-20250515` and `changes-20250313`, which only the tag commit adds. Differences: the published page lacks the link `https://colorusage.arc.nasa.gov/lum_and_chrom.php` (in the `luminance` definition) and the informative reference `Luminance-Chromaticity` (cited at the end of "Gamma and chromaticity"), both present in the tag source and in the CR crawl of 2025-03-14, both absent from the PR crawl of 2025-05-16 and the REC crawl; and one generated id differs (`f-9-` in the `ed/` crawl, `f-8-changes-between-first-and-second-editions` in the REC). webref records the page's `Last-Modified` as 2025-06-12, 12 days before the tag commit's author date (the PR's: 2025-05-05). One body-text check agrees: the REC's second `mDCV` white-point example has the wrong hexadecimal `{ 3C 05, 40 42 }` (W3C erratum, `w3c/png` issue 539), and the local source has the same text at line 4000.

Not compared: the body text of the 16 cited sections against the published page. No difference is known there, because the differences found are in the `luminance` definition and in the "Gamma and chromaticity" annex, but none can be excluded. To close this, compare those 16 sections (`../tools/spec_section.py ID`) with the published page once `www.w3.org` is reachable.

`main` is not the REC. 35 commits after the tag touch `index.html` (+297/−281 lines at `e200ab5`, 2026-10-08), and 4 of the 16 cited sections differ in `main`: `11keywords`, `5ChunkOrdering`, `9Filter-types` ("Filters may use the original values" becomes "must use", and "pixel" becomes "byte") and `fcTL-chunk`. SPEC.md therefore cites the tag, never `w3c.github.io/png/`. The ReSpec source has no section numbers, so SPEC.md cites anchors (`[3e #fcTL-chunk]`); all 16 exist in the tag, in `main` and in the published page.
