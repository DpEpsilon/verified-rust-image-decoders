# PNG decoder core

PNG-CORE-SPEC draft 0.1 (not frozen; open decisions are in `../policy-draft/QUESTIONS.md`, marked PNG-Q*n*). Source texts: Portable Network Graphics (PNG) Specification (Third Edition), W3C Recommendation 24 June 2025, and RFC 1950/1951; local copies and provenance in `SOURCES.md` (cited as `[3e #anchor]`, `[1950 §n]`, `[1951 §n]`; this spec's own sections are P*n*). Reference model: `png_oracle.py`; every function there names the P section it implements. Vectors: `VECTORS.json` (P19), generated by `gen_vectors.py`, checked by `check_vectors.py`. Design choices and incumbent comparisons: `DESIGN-NOTES.md` (N*n*).

Conventions. Offsets are zero-based; ranges half-open. BE32/BE16 are unsigned big-endian integers. All arithmetic is on mathematical integers before any checked narrowing. "Require *n* bytes at *p*, else E" means: if `p+n > |b|`, return E without reading. RGBA8 output is tightly packed, non-premultiplied, left to right, top row first. `round(n/d)` for `n ≥ 0, d > 0` is `⌊(2n + d) / (2d)⌋` (half up).

## P1. Entry points and limits

**Limits.** Every resource cap is one named constant in this section and nowhere else; the theorems (`../PLAN.md`) are stated over these names, so a cap changes by editing one line and rebuilding (PNG-Q5). Proposed values:

| Constant | Value | Bounds |
|---|---|---|
| `MAX_INPUT` | 268,435,456 (256 MiB) | input bytes |
| `MAX_DIMENSION` | 16,384 | IHDR width and height |
| `MAX_OUTPUT` | 67,108,864 (64 MiB) | `4·W·H`, one RGBA8 image or canvas; the RGBA16 output is `2·MAX_OUTPUT` |
| `MAX_FRAMES` | 65,536 | acTL `num_frames` |
| `MAX_TOTAL_PIXELS` | 2^30 | sum of `w·h` over all fcTL frames of one stream |
| `MAX_ICC` | 16,777,216 (16 MiB) | decompressed iCCP profile (P17 only) |

Derived bounds used by the proofs: the filtered image data `R(W,H) ≤ H·(1 + 8W) ≤ 2·MAX_OUTPUT + MAX_DIMENSION` (P11); no zlib stream inflated by P15/P16 may produce more than `R` bytes, so no separate decompression-ratio cap exists (N4).

**Entry points** (all share the structural pass P2–P8 and P14.1):

- `decode_still(b)` → `Ok(Still{width, height, rgba, info})` or `Err(e)`: the default image (the IDAT image) as RGBA8 (P15).
- `decode_still16(b)` → as `decode_still` with `rgba16`: four 16-bit samples per pixel (P13.3).
- `decode_frames(b)` → `Err(e)`, or `Frames{width, height, num_plays, frames, end}`: the animation (P16). The executable form is an iterator: the *k*-th call returns `frames[k]`, then `None` (on `end = Iend`) or `Err(e)` once, then the same result again.
- `icc_profile(b)` → `Ok(None)`, `Ok(Some(bytes))` or `Err(e)` (P17).

`Info` (P8.3) carries the IHDR fields and the raw values of the colour and metadata chunks; no ancillary value except tRNS changes a pixel.

## P2. Signature

Test `|b| > MAX_INPUT` first: `FileTooLarge`. Require 8 bytes at 0 equal to `89 50 4E 47 0D 0A 1A 0A`, else `BadSignature` (a shorter input is also `BadSignature`). [3e #5PNG-file-signature]

## P3. Chunk layer

A chunk at offset `p` [3e #5Chunk-layout]: require 8 bytes at `p`, else `TruncatedChunk`; `n = BE32(p)`, type `t = b[p+4..p+8]`. Then, in order:

1. `n > 2^31 − 1`: `ChunkTooLong`.
2. any byte of `t` outside `41–5A`, `61–7A`: `InvalidChunkType` [3e #13Error-checking].
3. require `n + 4` bytes at `p+8`, else `TruncatedChunk`.
4. CRC-32 (ISO 3309, reflected polynomial `EDB88320`, register preset to all ones, result complemented [3e #5CRC-algorithm]) over `t` and the `n` data bytes must equal `BE32(p+8+n)`, else `CrcMismatch`. Every chunk is checked, critical, ancillary or unknown (N1, PNG-Q2).

The next chunk starts at `p + 12 + n`. Types are compared as four literal bytes; bit 5 of byte 0 set means ancillary [3e #5Chunk-naming-conventions]. The reserved bit (byte 2) and the private bit (byte 1) are not tested: a chunk with the reserved bit set is an unknown chunk like any other [3e #13Chunking].

## P4. IHDR

The first chunk after the signature must have type `IHDR`, else `MissingIhdr`; its length must be 13, else `InvalidChunkLength`. `W = BE32(0)`, `H = BE32(4)`, depth `d`, colour type `ct`, compression `cm`, filter `fm`, interlace `im` [3e #11IHDR]. In order:

- `1 ≤ W ≤ MAX_DIMENSION` and `1 ≤ H ≤ MAX_DIMENSION`, else `InvalidDimensions` (this also rejects the format's own limit `2^31 − 1`).
- `4·W·H ≤ MAX_OUTPUT`, else `OutputTooLarge`.
- `(ct, d)` in `{0: 1,2,4,8,16; 2: 8,16; 3: 1,2,4,8; 4: 8,16; 6: 8,16}`, else `InvalidColorTypeDepth`.
- `cm = 0`, else `UnsupportedCompressionMethod`; `fm = 0`, else `UnsupportedFilterMethod`; `im ≤ 1`, else `UnsupportedInterlaceMethod`.

Channels `C(ct)` = 1, 3, 1, 2, 4 for `ct` = 0, 2, 3, 4, 6; bits per pixel `B = C·d`; filter byte distance `bpp = max(1, B/8)`.

## P5. Chunk sequence and ordering

After IHDR the walk reads chunks (P3) until IEND. State: the set of singleton types seen; whether PLTE has been seen; the IDAT phase (`before`, `in` = the previous chunk was IDAT, `after`); the APNG state of P14.1. At each chunk boundary `p = |b|` is `MissingIend`. For a chunk of type `t`, the checks below apply in this order, then the chunk's own section:

1. **Duplicates.** `t` ∈ {IHDR, PLTE, tRNS, cHRM, gAMA, iCCP, sBIT, sRGB, cICP, mDCV, cLLI, bKGD, hIST, pHYs, eXIf, tIME, acTL} seen before: `DuplicateChunk`. sPLT, tEXt, zTXt, iTXt, IDAT, fcTL, fdAT and unknown chunks may repeat. (sPLT name uniqueness is not checked, N9.)
2. **Ordering** [3e #5ChunkOrdering]. `ChunkOutOfOrder` when:
   - cHRM, gAMA, iCCP, sBIT, sRGB, cICP, mDCV or cLLI appears after PLTE or after the first IDAT;
   - bKGD, hIST or tRNS appears after the first IDAT, or (colour type 3, or hIST in any type) before PLTE;
   - eXIf, pHYs, sPLT or acTL appears after the first IDAT;
   - PLTE appears after the first IDAT, or after a bKGD, hIST or tRNS;
   - the APNG rules of P14.1 (a second fcTL before IDAT; fdAT before IDAT).
3. **Fixed lengths.** gAMA 4, cHRM 32, sRGB 1, cICP 4, mDCV 24, cLLI 8, pHYs 9, tIME 7, acTL 8, IEND 0; otherwise `InvalidChunkLength`. fcTL (26) and fdAT (≥ 4) are checked in P14.1 after the acTL check.
4. **Critical chunks.** A second IHDR is `DuplicateChunk` (step 1). PLTE: P6. IDAT: if the phase is `after`, `NonConsecutiveIdat`; for colour type 3 without PLTE, `MissingPalette`; the payload is appended to the image data. IEND: if no IDAT was seen, `MissingImageData`; then the end-of-stream checks of P14.1; then if `p + 12 < |b|`, `TrailingBytes`; otherwise the walk ends.
5. **Unknown chunks.** An unknown type with bit 5 of byte 0 clear is `UnknownCriticalChunk`; an unknown ancillary chunk is skipped wherever it appears between IHDR and IEND.

Zero-length IDAT chunks are valid and contribute nothing. IDAT boundaries carry no meaning: the image data is the concatenation of all IDAT payloads [3e #13Decompression]. The walk visits every chunk before any pixel is decoded (N2); its only state is a fixed-size record, independent of the number of chunks (P20).

## P6. PLTE [3e #11PLTE]

Colour types 0 and 4: `UnexpectedPalette`. Otherwise the length must be a positive multiple of 3, at most 768, and for colour type 3 at most `3·2^d`, else `InvalidPalette`. Entries `E = n/3`. For colour types 2 and 6 the palette is a suggested palette: validated, recorded in `Info`, never applied.

## P7. tRNS [3e #11tRNS]

Colour types 4 and 6: `InvalidTransparency`. Required length: 2 for type 0, 6 for type 2, `1 ≤ n ≤ E` for type 3; else `InvalidTransparency`. For types 0 and 2 each 16-bit value is masked to its low `d` bits before use (the text says decoders "must mask"), so high bits are not an error. The key is compared with the unscaled samples, exactly, before any depth conversion (P13).

## P8. Other ancillary chunks

**P8.1 Values** (after P5's checks). Any violation is the named error:

| Chunk | Rule | Error |
|---|---|---|
| gAMA | value ≠ 0 | `InvalidGamma` |
| cHRM | none beyond length | — |
| sRGB | intent ≤ 3 | `InvalidSrgb` |
| iCCP | keyword (P8.2), null, method byte present and 0; the compressed profile is not inflated here | `InvalidIccp` |
| sBIT | length 1, 3, 3, 2, 4 for ct 0, 2, 3, 4, 6 (`InvalidChunkLength`); each value in `1..s` with `s = 8` for ct 3, else `d` | `InvalidSbit` |
| cICP | matrix coefficients 0, full-range flag ≤ 1 | `InvalidCicp` |
| mDCV, cLLI | none beyond length | — |
| bKGD | length 2, 6, 1 for ct {0,4}, {2,6}, 3 (`InvalidChunkLength`); ct 3: index `< E`; otherwise each value `< 2^d` | `InvalidBackground` |
| hIST | length `2·E` | `InvalidHistogram` |
| pHYs | unit ≤ 1 | `InvalidPhys` |
| sPLT | keyword, null, depth 8 or 16, entry bytes a multiple of 6 or 10 | `InvalidSplt` |
| eXIf | length ≥ 4 and starts `49 49 2A 00` or `4D 4D 00 2A` | `InvalidExif` |
| tIME | month 1–12, day 1–31, hour ≤ 23, minute ≤ 59, second ≤ 60 | `InvalidTime` |
| tEXt | keyword, null | `InvalidText` |
| zTXt | keyword, null, method byte present and 0; not inflated | `InvalidText` |
| iTXt | keyword, null, flag ≤ 1, method byte (must be 0 when flag = 1, ignored when 0), language tag and translated keyword each null-terminated; not inflated | `InvalidText` |

bKGD's grey and RGB values are range-checked rather than masked: unlike tRNS, the text states the range ("in the range 0 to 2^bitdepth − 1") and only then the masking advice (N10). Text content character sets and UTF-8 validity are not checked (N9).

**P8.2 Keywords** [3e #11keywords]: 1–79 bytes, each in `20–7E` or `A1–FF`, no leading, trailing or consecutive spaces.

**P8.3 Info.** IHDR fields, palette entry count, whether tRNS is present, and the raw values of gAMA, cHRM, sRGB, cICP, mDCV, cLLI, sBIT, bKGD, pHYs, tIME, the iCCP profile name, and the byte range of eXIf in the input. The implementation exposes byte ranges (borrowed from the input), never copies (P20). Text chunks are reachable through a borrowed chunk iterator outside this core's model (BRIEF.md, PNG-Q13).

## P9. zlib datastream (RFC 1950)

Input: the concatenated payload `Z` of one image's data chunks (IDAT, or one frame's fdAT payloads after their sequence numbers, or the iCCP profile field), and an output limit `L`. Require 2 bytes, else `TruncatedZlib`. `CMF = Z[0]`, `FLG = Z[1]`:

1. `(256·CMF + FLG) mod 31 ≠ 0`: `InvalidZlibHeader` [1950 §2.2].
2. `CMF & 15 ≠ 8` or `CMF >> 4 > 7`: `UnsupportedZlibMethod`.
3. `FLG & 0x20` (FDICT): `ZlibPresetDictionary` (PNG defines no dictionary [3e #10CompressionCM0]).
4. Inflate (P10) from byte 2 with window `2^(CINFO+8)` and limit `L`.
5. Skip to a byte boundary; require 4 bytes, else `TruncatedZlib`; `BE32` must equal Adler-32 of the output [1950 §8.2], else `AdlerMismatch`.
6. Any byte of `Z` after the Adler-32: `TrailingZlibData`.

## P10. DEFLATE (RFC 1951)

**P10.1 Bits.** Read least significant bit first; Huffman codes most significant bit first [1951 §3.1.1]. Reading past the end of `Z` is `TruncatedZlib`.

**P10.2 Blocks.** Repeat: `BFINAL` (1 bit), `BTYPE` (2 bits). `BTYPE = 3`: `InvalidBlockType`. Stored (0): skip to a byte boundary, require 4 bytes (`TruncatedZlib`), `LEN`, `NLEN` little-endian, `NLEN = ¬LEN`, else `StoredLengthMismatch`; then the `LEN` bytes are output, one at a time in stream order (so the output limit is reached before a truncation in the same block). Fixed (1): P10.4. Dynamic (2): P10.5. Stop after a block with `BFINAL = 1`.

**P10.3 Codes.** A code is given by lengths `0..15` per symbol and assigned canonically [1951 §3.2.2]. A set of lengths is *oversubscribed* if `Σ 2^-len > 1` and *complete* if it equals 1. Admissible: the code-length code must be complete; the literal/length code must be complete or consist of exactly one code of length 1; the distance code must be complete, consist of exactly one code of length 1, or be empty (all lengths 0). Otherwise `InvalidCodeLengths`. Reading a bit string that matches no code of an incomplete code is `InvalidSymbol`. (These are zlib's acceptance rules; N5.)

**P10.4 Fixed codes.** Literal/length lengths 8 (0–143), 9 (144–255), 7 (256–279), 8 (280–287); 30 distance codes of length 5 plus codes 30, 31 of the same length. Symbols 286, 287 and distances 30, 31 decode but are `InvalidSymbol`.

**P10.5 Dynamic header.** `HLIT` (5 bits) + 257, `HDIST` (5) + 1, `HCLEN` (4) + 4; `HLIT + 257 > 286` or `HDIST + 1 > 30`: `InvalidCodeLengths`. Read `HCLEN+4` 3-bit lengths in the order 16, 17, 18, 0, 8, 7, 9, 6, 10, 5, 11, 4, 12, 3, 13, 2, 14, 1, 15 (the rest 0); the code-length code must be admissible (P10.3). Then read `HLIT + HDIST` lengths as one sequence: 0–15 literal; 16 repeats the previous length `3 + 2 bits` times (no previous length: `InvalidCodeLengths`); 17 writes `3 + 3 bits` zeros; 18 writes `11 + 7 bits` zeros; a repeat that runs past `HLIT + HDIST` is `InvalidCodeLengths`. The literal/length code must give symbol 256 a nonzero length, else `InvalidCodeLengths`; both codes must be admissible.

**P10.6 Symbols.** Literal `< 256`: output it. 256: end of block. 257–285: length `base + extra` [1951 §3.2.5], then a distance symbol (`≥ 30`: `InvalidSymbol`) and its extra bits; if the distance exceeds the bytes output so far in this stream or the window `2^(CINFO+8)`, `DistanceTooFar`; then copy byte by byte (overlap allowed). Every output byte counts against `L`: the first byte beyond `L` is the caller's limit error (`ExcessImageData` for P11, `IccProfileTooLarge` for P17), raised before the byte would be written and before any later check of the stream.

## P11. Image data layout and filters

For an image of `w × h` (the IHDR size, or an fcTL frame size) the passes are one full pass without interlace, or the seven Adam7 passes (P12). A pass of `pw × ph` pixels with `pw > 0` and `ph > 0` contributes `ph` scanlines of `1 + ⌈pw·B/8⌉` bytes; an empty pass contributes nothing (no filter bytes) [3e #8InterlaceMethods]. `R(w,h)` is the sum.

The data is inflated with `L = R` (P9). If the stream completes (step 6 passes) with fewer than `R` bytes: `TruncatedImageData`. Then the scanlines are processed pass by pass, top to bottom: filter byte `f > 4` is `InvalidFilterType`; otherwise reconstruct [3e #9Filter-types] with `a` the byte `bpp` to the left (0 at the start), `b` the byte above in the same pass (0 in the pass's first scanline), `c` above-left: None `x`, Sub `x + a`, Up `x + b`, Average `x + ⌊(a+b)/2⌋`, Paeth `x + PaethPredictor(a,b,c)` (ties prefer `a`, then `b`), all mod 256; then convert the scanline (P13) and place its pixels (P12). Errors therefore come in this order: every P9/P10 error of the whole stream, `TruncatedImageData`, then per scanline in stream order `InvalidFilterType` and `PaletteIndexOutOfRange` (N3).

## P12. Adam7 [3e #8InterlaceMethods]

Pass `k` = 1..7 has origin `(x0, y0)` and step `(dx, dy)`: (0,0,8,8), (4,0,8,8), (0,4,4,8), (2,0,4,4), (0,2,2,4), (1,0,2,2), (0,1,1,2). `pw = ⌈(w − x0)/dx⌉` if `w > x0`, else 0; `ph` likewise. Pixel `(c, r)` of pass `k` is image pixel `(x0 + c·dx, y0 + r·dy)`. Over the non-empty passes this map is a bijection onto `[0,w) × [0,h)` for every `w, h ≥ 1`.

## P13. Samples and conversion

**P13.1 Unpacking.** Samples are packed most significant bit first within a byte for `d < 8`; 16-bit samples are big-endian. Padding bits at the end of a scanline are ignored.

**P13.2 RGBA8.** `s8(v) = v·255/(2^d − 1)` for `d ≤ 8` (exact for 1, 2, 4, 8); `s8(v) = round(255·v / 65535)` for `d = 16` (equivalently `⌊(v + 128)/257⌋`; PNG-Q3 for the alternative `v >> 8`). Per colour type:
- 0: `(s8(g), s8(g), s8(g), A)`, `A = 0` if tRNS is present and `g` equals the masked key, else 255.
- 2: `(s8(r), s8(g), s8(b), A)`, `A = 0` iff all three equal the masked key.
- 3: index `i`; `i ≥ E` is `PaletteIndexOutOfRange`; else `(R_i, G_i, B_i, α_i)` with `α_i` the tRNS entry if `i <` the tRNS length, else 255.
- 4: `(s8(g), s8(g), s8(g), s8(a))`; 6: `(s8(r), s8(g), s8(b), s8(a))`.

**P13.3 RGBA16.** `s16(v) = v·65535/(2^d − 1)` (exact for every PNG depth); palette entries and tRNS alpha are multiplied by 257; transparent pixels have alpha 0 and opaque ones 65535.

No gamma, chromaticity, ICC, cICP, sBIT or background transform is applied (N6, PNG-Q4).

## P14. APNG

**P14.1 Structure (part of the P5 walk).** Sequence counter `q = 0`; frame list empty; current frame none.
- **acTL** (P5 already checked: before IDAT, single, length 8): `num_frames = 0` is `InvalidAnimationControl`; `> MAX_FRAMES` is `TooManyFrames`. `num_plays` is recorded raw.
- **fcTL**: without a preceding acTL, `MissingAnimationControl`; a second fcTL before the first IDAT, `ChunkOutOfOrder`; length ≠ 26, `InvalidChunkLength`; `sequence_number ≠ q`, `SequenceError`, then `q ← q+1`; if the current frame is fdAT-based and has no fdAT, `MissingFrameData`. Then `w = 0`, `h = 0`, `x + w > W`, `y + h > H` (computed without overflow), `dispose_op > 2` or `blend_op > 1`: `InvalidFrameControl`; before the first IDAT also `x ≠ 0`, `y ≠ 0`, `w ≠ W` or `h ≠ H`: `InvalidFrameControl`. Add `w·h` to the pixel total; above `MAX_TOTAL_PIXELS`, `PixelBudgetExceeded`. The fcTL starts a new current frame: IDAT-based if it precedes the first IDAT (the default image is then frame 0), else fdAT-based.
- **fdAT**: without acTL, `MissingAnimationControl`; before the first IDAT, `ChunkOutOfOrder`; length < 4, `InvalidChunkLength`; `sequence_number ≠ q`, `SequenceError`, then `q ← q+1`; if there is no current frame or it is IDAT-based, `UnexpectedFrameData`; the payload after the sequence number is appended to the frame's data. fdAT chunks of one frame need not be adjacent.
- **At IEND**: a current fdAT-based frame without fdAT is `MissingFrameData`; with acTL, a frame count ≠ `num_frames` is `FrameCountMismatch`.

**P14.2 Frame data.** Each frame's data is one zlib stream decoded by P9–P13 at the frame's `w × h` with the IHDR's depth, colour type, interlace method, PLTE and tRNS.

**P14.3 Canvas and disposal.** The canvas is `W × H` pixels of `(0,0,0,0)` at the start. Before frame `k > 0` is drawn, frame `k−1`'s disposal applies to its rectangle: 0 leaves the canvas; 1 sets the rectangle to `(0,0,0,0)`; 2 restores the canvas saved before frame `k−1` was drawn. Frame 0's `dispose_op = 2` acts as 1 [3e #fcTL-chunk]. The last frame's disposal is never applied.

**P14.4 Blending.** `blend_op = 0` (source) writes the frame's RGBA8 pixels into its rectangle. `blend_op = 1` (over) combines source `s` and canvas `d` per pixel: `s.a = 255` gives `s`; `s.a = 0` gives `d`; otherwise with `A = 255·s.a + d.a·(255 − s.a)`, each colour channel is `round((255·s.a·s.c + d.a·(255 − s.a)·d.c) / A)` and alpha is `round(A / 255)`. This is the exact straight-alpha OVER on 8-bit values with half-up rounding (PNG-Q8). Blending uses the RGBA8 conversion; 16-bit APNGs are composited after P13.2.

## P15. `decode_still` and `decode_still16`

Run the walk P2–P8, P14.1 to IEND; then decode the IDAT data at `W × H` (P11–P13). Return the image or the first error. fdAT data is never inflated, so frame-data errors do not affect the still (PNG-Q9).

## P16. `decode_frames`

Run the walk; decode the default image (its errors are returned as `Err`). Without acTL, return one frame: the default image, rectangle `(0,0,W,H)`, `delay = None`, dispose 0, blend 0, `num_plays = None`. With acTL, for each fcTL frame in order decode its data (frame 0 reuses the default image when IDAT-based), apply P14.3 and P14.4, and append `{rgba (the whole canvas), rect, delay (delay_num, delay_den raw), dispose, blend}`. The first error decoding frame `k` ends the sequence with `end = Err(e)` after the `k` frames already returned; otherwise `end = Iend`. A default image outside the animation is decoded (validated) but is not a frame.

## P17. `icc_profile`

Run the walk. Without iCCP return `None`; otherwise inflate its compressed profile field by P9–P10 with `L = MAX_ICC` (excess: `IccProfileTooLarge`) and return the bytes. The profile's own content is not interpreted.

## P18. Errors

The closed, case-sensitive error set (62 names), in check order: `FileTooLarge`, `BadSignature`, `TruncatedChunk`, `ChunkTooLong`, `InvalidChunkType`, `CrcMismatch`, `MissingIhdr`, `InvalidChunkLength`, `InvalidDimensions`, `OutputTooLarge`, `InvalidColorTypeDepth`, `UnsupportedCompressionMethod`, `UnsupportedFilterMethod`, `UnsupportedInterlaceMethod`, `UnknownCriticalChunk`, `DuplicateChunk`, `ChunkOutOfOrder`, `MissingPalette`, `UnexpectedPalette`, `InvalidPalette`, `NonConsecutiveIdat`, `MissingImageData`, `MissingIend`, `TrailingBytes`, `InvalidTransparency`, `InvalidGamma`, `InvalidSrgb`, `InvalidIccp`, `InvalidSbit`, `InvalidCicp`, `InvalidBackground`, `InvalidHistogram`, `InvalidPhys`, `InvalidSplt`, `InvalidExif`, `InvalidTime`, `InvalidText`, `MissingAnimationControl`, `InvalidAnimationControl`, `TooManyFrames`, `InvalidFrameControl`, `SequenceError`, `UnexpectedFrameData`, `MissingFrameData`, `FrameCountMismatch`, `PixelBudgetExceeded`, `InvalidZlibHeader`, `UnsupportedZlibMethod`, `ZlibPresetDictionary`, `InvalidBlockType`, `StoredLengthMismatch`, `InvalidCodeLengths`, `InvalidSymbol`, `DistanceTooFar`, `TruncatedZlib`, `AdlerMismatch`, `TrailingZlibData`, `TruncatedImageData`, `ExcessImageData`, `InvalidFilterType`, `PaletteIndexOutOfRange`, `IccProfileTooLarge`. `IccProfileTooLarge` is returned only by `icc_profile`. Allocation failure is not in this set (P20).

Precedence is operational: the first failing check in the order written, over one walk of the chunk sequence (P2–P8, P14.1, chunk by chunk, each chunk P3 then P5 then its section), then the default image's data (P9–P13), then (P16 only) each frame's data in frame order, then (P17 only) the iCCP profile. No partial image is ever returned by `decode_still`; `decode_frames` exposes the completed frames and one error.

The `recovered` events of the policy layer are a separate closed list (`../policy-draft/OPTIONS.md`, R1–R5); Strict never sets `recovered`.

## P19. Vectors

`VECTORS.json` is an array of `{name, entry, input_hex, expected}` with `entry ∈ {still, still16, frames, icc}`; optional `pad_to: n` appends zero bytes up to length `n`. Expectations: `{error}`; still `{width, height, rgba_runs}`; still16 `{width, height, rgba16_runs}`; frames `{width, height, num_plays, frames: [{rect, delay, dispose, blend, rgba_runs}], end}` with `end` `"iend"` or `{error}`; icc `{icc: null}` or `{icc_len, icc_sha256}`. `rgba_runs` are maximal runs `{count, hex}` of pixels (8 hex digits per RGBA8 pixel, 16 per RGBA16 pixel). Expectations are written from the generator's intent, never computed by the oracle. 592 records; all 62 errors are exercised (`PixelBudgetExceeded` by a 4 KB stream of 65 fcTL frames whose data is never inflated, `FileTooLarge` by `pad_to`). `check_vectors.py` also cross-checks the oracle's inflate, CRC-32 and Adler-32 against Python's zlib on every zlib stream in the vectors and on random streams and single-bit corruptions; the only accepted rule difference is `DistanceTooFar` beyond the declared CINFO window, which zlib does not enforce (N5).

## P20. Resource and safety contract (for the implementation)

Input is borrowed. Before any reservation, P2–P8 and P14.1 hold for the whole stream. Reservations, all through the `alloc_guard` of `../../alloc-delta/SPEC.md` (no aborting allocation in the crate):

| Site | Size | When |
|---|---|---|
| `Raw` | `R(W,H)` bytes (filtered data of the largest image; frames reuse it, `R(w,h) ≤ R(W,H)` for `w ≤ W, h ≤ H`) | `decode_still*`, `Frames::try_new`, after the walk |
| `Output` | `4·W·H` (`8·W·H` for `decode_still16`), zero-filled | same call, after `Raw` |
| `Saved` | `4·W·H` | the first frame with `dispose_op = 2` (k > 0), once per decoder |
| `IccWindow` | 32,768 bytes | `icc_profile` only: a first inflate pass measures the profile length `m ≤ MAX_ICC` |
| `Icc` | `m` bytes | `icc_profile` only, after the measuring pass; the second pass inflates into it |

So `Req(still) = [(Raw, R), (Output, 4N)]` iff the walk passes, and `Req(icc) = [(IccWindow, 32768), (Icc, m)]` iff the walk passes, the iCCP chunk exists and the measuring pass succeeds (zlib's stored length is not trusted: the profile has no declared size). No other input-dependent allocation: the walk keeps a fixed-size record (no chunk list: data chunks are re-walked by offset when inflating), inflate writes into `Raw` and uses `Raw` itself as its window, the Huffman tables are fixed-size arrays inside the decoder state. No reads beyond the slice, no unchecked overflow or narrowing, no panic, no recursion. Work: `steps ≤ c·(|b| + R + N + P)` with `N = W·H` and `P` the sum of frame pixels, for every input and every policy record (one dynamic-block header costs at most 320 code-length symbols and is charged to the at least 14 bits it consumes).

## P21. Not in this core

No gamma, ICC, cICP, chromaticity or sBIT transform; no background compositing; no premultiplication; no text decoding or decompression (zTXt/iTXt are validated structurally only); no sPLT use; no streaming input (the caller supplies the whole stream); no partially decoded images outside `../policy-draft` options; no loop playback or delay mapping (raw `delay_num/delay_den` and `num_plays` only). The `no_std + alloc` form and the fallible-allocation API follow `../../alloc-delta/SPEC.md` §1–§9 unchanged.
