## Point-by-point scrutiny

(a) Preconditions. No theorem carries a hypothesis stronger than the manifest's. Verus `rle_decode` adds `n ≤ 16384` (weaker than `n ∈ {…}`); Verus `decode_*`/`combine` require `parsed_inv`, Creusot require `parser_ok`, both implied by `P(b,E)` (`lemma_p_exec_inv` model.rs:1827; `p_parser_ok` lib.rs:676-687, proved from `mp`'s guards, not assumed). Creusot `decode_rgb`'s second `requires` (lib.rs:2632) is `parser_ok` restated through `entry_ok_iff_mentry` (610) and is discharged by `combine_pair` from `parser_ok` alone, so it is not an extra hypothesis. All indices are `u32`/`Option<u32>` in both; lengths are `nat`/`Int` in the models.

(b) T13 form. `MP` is a function, so `p_model(b,e)` holds for at most one `e`. When `parse` returns `Ok(es)`, T7 gives `mp(b)=Ok(entries_view(es))`, so Creusot's `∀e` collapses to the single actual `E` and asserts `combine(b,es,…) = MJ(b,E,…)`, the manifest's statement. When `parse` returns `Err`, no `e` satisfies the antecedent and the postcondition is vacuous, exactly as the manifest's `parse(b)=Ok(E) ⇒ …` is. The vacuity does not matter: `witness_t13_parse_succeeds` (lib.rs:3010-3021) proves the `Ok` path is taken on a concrete input, and the `Err(_) => proof_assert!(false)` there is a proved unreachability goal, not an assumption. Verus's tuple form states the same thing directly on the returned entries. Equal.

(c) T7/T8 postconditions are exact in both: same error variant (Verus via `exec_err`, model.rs:1020-1033; Creusot shares the `Error` enum) and all four entry fields in order (`entries_eq_models` model.rs:1160; `entries_view` lib.rs:268-278).

(d) Model independence and faithfulness. Neither model calls executable code: Verus `mp`/`scan`/`mr`/`mc`/`ma`/`mj` are `spec fn`s over `Seq<u8>`; Creusot `mp`/`mp_loop`/`mr_ch`/`mc_entry`/`ma_entry`/`mj_pair` are `#[logic]` over `Seq<u8>`. Executables carry `ensures` linking to them. Checked against the manifest: FileTooLarge `>67,108,864` (model.rs:433, lib.rs:342); header/magic/length/Truncated/Trailing order (model.rs:435-446, lib.rs:344-353); entry loop order TruncatedEntryHeader → `q<8` → `q>L−off` → count (model.rs:415-424, lib.rs:322-329); classification with the legacy guard (model.rs:151-159, lib.rs:176-182); RLE: cursor check before control, overrun before data availability, repeat needs one byte, trailing test after three channels (model.rs:2689-2707, 2740-2749; lib.rs:1930-1950, 2409-2425); `it32` strips exactly four bytes iff all zero (model.rs:3117-3132; lib.rs:2026-2035); mask length `= d²` (model.rs:3191; lib.rs:2119); MJ order MissingColor → MissingMask → MC → MA → TypeMismatch (model.rs:3691-3706; lib.rs:2150-2198). One definitional difference: Creusot's `mentry_type` reads the type from `b[start−8..start−4]` (lib.rs:2046-2048) rather than from `E[i].type_hex`; Verus recovers it from `type_hex` (`code_of`, model.rs:3164). Under `P(b,E)` the two coincide (`mentry_ok`, lib.rs:596-604), and every T10–T13 statement is under `P`, so this does not change strength.

(e) Vector agreement. Both generators read `expected` from `spec-frozen/VECTORS.json` (icns-verus/tools/gen_model_vectors.py:22,232; icns-creusot/tools/gen_model_vectors.py:32,293,685). Verus decoding vectors are stated as `match mp(b) { Ok(ms) => mc_ms(b,ms,i) == expected, Err(_) => false }` discharged `by (compute)` (e.g. model_vectors.rs:311-324). Creusot splits each into `p_<v>` proving `mp(b) == Ok(ms_<v>())` and `agree_<v>` proving `<model>(b, ms_<v>(), i) == expected` (e.g. lib.rs:52864-52870, 39513-39517); together these are the same obligation. 102 `agree_*` in each; the nine large vectors are covered by L1–L6 instantiations in both (Creusot additionally builds the five ≤ 33 KB witnesses executably, lib.rs:1667-1741).

(f) Mutation 8. Creusot mutates the executable helper `strip4_prog` body (`&p[4..]` → `&p[8..]`, mutation/m8 diff at lib.rs:2394) and `vc_strip4_prog` fails. `strip4_prog`'s contract is R11 verbatim and `decode_rgb_sel` (lib.rs:2618-2622) depends on it, so T10's chain is broken; the manifest's wording ("T10 must fail on `it32-eight-zero-prefix-then-literals`") is satisfied in the modular sense. It is weaker evidence than Verus's m8, which mutates the model (`it32_prefix`, model.rs:3117) and fails both the named vector obligation (model_vectors.rs:466) and `decode_rgb`'s T10 assertion (icns.rs:995). The same asymmetry holds for mutations 6, 7 and 9: Verus mutates `rle_count`/`rle_chan_from`/`mj` in model.rs, Creusot mutates `rle_channel`/`combine` in the executable (mutation/m6, m7, m9 diffs). Both readings are admissible; Verus's demonstrates model↔vector sensitivity for RLE/it32/MJ, Creusot's demonstrates only code↔model sensitivity there (its model↔vector sensitivity is shown for the parser by m1–m4).

(g) Nothing is proven only for the code. Both projects' models are total over their inputs; neither weakens a model to pass (the Creusot `mj_pair` interleaving of index tests, lib.rs:2152-2175, is equivalent to "MC first then MA" because `IndexOutOfRange` is MC's/MA's own first test).

(h) Trust. No `assume`, `admit`, `external_body`, `#[trusted]`, `unsafe`, or `requires(false)` in either crate (grep). Verus `#[cfg(verus_only)]` guards only `use` lines (model.rs:8-22). Creusot `#[cfg(creusot)]` guards only the `model_vectors` module (lib.rs:3023), which contains 7,474 `#[logic]` items and no executable code or contract; the shipped executable code is identical to the verified code. The sole `proof_assert!(false)` (lib.rs:3018) is a goal, not an axiom.

## Differences that matter, by severity

1. (Low) Creusot report inaccuracy. PROOF-REPORT-M4d.md:152-153 says mutation 5 fails "the T13 site too"; `mutation/m5/result.txt` and `direct.log:314-321` list only `vc_rgb_at_parse`, `vc_mask_at_parse`, `vc_combine_at_parse` (and `vc_map_push`). `t13_combine_at_parse` survives because it derives `parser_ok` from the untouched T7 postcondition via `p_parser_ok`. The manifest's fallback was arguably triggered for T13 and not run. Verus's m5 deletes the range conjunct of `entry_inv` itself, so every consumer fails (icns.rs:982, 1118). Not a proof deficiency; the T13 proof is sound either way.
2. (Low) Creusot `vc_map_push` fails in six of ten mutation runs (m1, m2, m3, m5, m6, m7) although `map_push` (lib.rs:691-698) is a structural lemma unrelated to any mutation and is proved in the live crate. This is prover flakiness in the disposable copies; every mutation also fails a relevant goal, so the protocol's conclusion stands, but the report tables (M4d:134-140) do not flag it.
3. (Low) Mutations 6–9 target the model in Verus and the executable in Creusot (point f). Creusot's protocol therefore never shows that `agree_rgb_is32`, `agree_repeat_overrun_before_missing_value`, `agree_it32_eight_zero_prefix_then_literals` or `agree_mask_without_colour` would reject a wrong RLE/it32/MJ model. Those agreement proofs do exist and pass, so the models are shown correct on the vectors; only the sensitivity demonstration is narrower.
4. (Informational) Creusot's `MC`/`MA` read the type from the header bytes, Verus's from `type_hex` (point d). Identical under `P(b,E)`.
5. (Informational) Creusot's T10/T11 wrappers re-implement the index test before calling the decoder (lib.rs:2907-2915); equality with `decode_rgb`'s result on that branch follows from `decode_rgb`'s own `ensures` (lib.rs:2638). Verus's wrappers call the decoder unconditionally.

## Verdict

Every T1–T13 and L1–L6 statement in both projects matches the manifest's quantification exactly or is stronger (weaker preconditions on `rle` and the decoders); none is weaker, none is vacuous, and both exclude the manifest's named vacuities with concrete witnesses. The two projects are of equal theorem strength, so their effort and cost can be compared like-for-like. Neither proof is deficient. The only items to correct are reporting: Creusot's mutation-5 claim about T13, and an unflagged flaky goal in its mutation runs.
