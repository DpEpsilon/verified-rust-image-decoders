# TGA decoder core

TGA-CORE-SPEC 1.0 (frozen). Offsets are zero-based and ranges half-open. `decode(bytes)` is a pure, total byte-slice-to-result function: `Ok({width: u32, height: u32, rgba: bytes})` or `Err(error)`. The output is tightly packed, non-premultiplied RGBA8, left-to-right and **top row first**, with no row padding. The caller owns an immutable input slice. All arithmetic in this document is mathematical until checked against the target integer width; the implementation checks before narrowing to `usize`, including on 32-bit targets. No I/O, callbacks, external codecs or implicit image selection occur.

R1. The input is at most `MAX_INPUT=67,108,864` bytes (64 MiB). Test length first and return `FileTooLarge` for a larger slice, without reading it; then return `TruncatedHeader` if fewer than 18 bytes remain. Byte fields of the 18-byte header are: ID length `[0]`; colour-map flag `[1]`; image type `[2]`; colour-map first index `LE16(3)`; colour-map length `LE16(5)`; colour-map entry depth `[7]`; x/y origin `LE16(8)`/`LE16(10)`; width/height `LE16(12)`/`LE16(14)`; image pixel depth `[16]`; descriptor `[17]`. `LE16(p)=b[p]+256*b[p+1]`. Coordinates are metadata, not an extra crop or offset. Require image type in `{1,2,3,9,10,11}` or return `UnsupportedImageType`; 1/9 are indexed, 2/10 true-colour, 3/11 greyscale; 1/2/3 are raw and 9/10/11 are RLE. No type-zero image is returned.

R2. After type validation, flag `[1]` must be 0 or 1 or return `InvalidColorMapFlag`. Width and height must each be between 1 and `MAX_DIMENSION=8,192` inclusive or return `InvalidDimensions`. Require `(descriptor & 0xc0)==0` (no two-/four-way interleaving) or return `UnsupportedInterleave`. Descriptor bits 4 and 5 specify horizontal (right when set) and vertical (top when set) input origin; bits 0..3 are attribute count. Check dimension and interleave even when later pixel-depth and payload fields are malformed.

R3. Supported image depths: indexed 8- or 16-bit unsigned **little-endian indices**; true-colour 15, 16, 24 or 32; greyscale 8 or 16. All other image depths return `UnsupportedPixelDepth` before checking map metadata or attribute count. `sample_bytes=ceil(depth/8)`; 15-bit true-colour uses two bytes. Colour-map entry depths are 15, 16, 24 or 32 only, checked in R4. Image and map entry depth are independent.

R4. With flag zero, require `first=length=entry_depth=0`; indexed images additionally require flag one. With flag one, whether indexed, true-colour or greyscale, require nonzero length and map entry depth in `{15,16,24,32}`. Any failure of these coherence/depth checks returns `InvalidColorMap`. Only after they pass, if `first+length>65,536`, return `ColorMapRange` for **any** flag-one image, including a non-indexed one. Thus flag zero with `first=65,535,length=2,entry_depth=24` returns `InvalidColorMap`, not `ColorMapRange`. A valid map can start at 65,535 and contain one entry. Indexed sample values are absolute indices: map entry `j` has index `first+j`, for `0<=j<length`. A map attached to a non-indexed image is consumed under R7 but never used to convert its pixels. Never allocate or index a 65,536-entry lookup table merely because `first` is large.

R5. Check descriptor attribute count after map validity. For true-colour 15/24 and greyscale 8 require zero. For true-colour 16 allow zero or one; for true-colour 32 and greyscale 16 allow zero or eight. For indexed images, the map's entry depth determines the **map-entry** attribute policy: 15/24 require zero, 16 allows zero or one, 32 allows zero or eight. The indexed image descriptor is the map-entry attribute count: for indexed images the allowed counts depend only on the map entry depth; the index depth is irrelevant. For non-indexed images, the count is governed by the image depth; an attached map's entry depth is irrelevant. All other combinations return `InvalidAttributeBits`. The count controls alpha for both raw and RLE pixels; there is no separate alpha heuristic based on version or an unused sample byte.

R6. Compute `N=width*height` and `4*N` with checked `u64` arithmetic before allocating pixels. If `4*N>MAX_OUTPUT=67,108,864` bytes return `OutputTooLarge`. An image at 4,096×4,096 is exactly at the output cap; 8,192×2,048 is also exactly at it. Successful output allocation requests exactly `4*N` bytes; an implementation may allocate lazily or after a cheap minimum-length check, provided that it still returns the R14-priority error (in particular `OutputTooLarge` before `TruncatedImageId`, map or pixels). Any bounded temporary allocation must be included in an implementation's resource accounting, and a streaming implementation needs no pixel-sized scratch buffer. Allocation failure is outside the byte-format error set (see R17).

R7. Following the 18-byte header, skip exactly the ID length (0..255); if unavailable return `TruncatedImageId`. Then consume exactly `length*ceil(map_entry_depth/8)` map bytes when flag is one (including non-indexed images), or return `TruncatedColorMap`; their positions are `[18+ID_length, 18+ID_length+map_bytes)`. Because the header length is a 16-bit integer (`length<=65,535`) and supported entry depths use at most four bytes, `map_bytes<=262,140`. The ID is opaque and never interpreted as text. These checks precede pixel decoding; do not read a map entry or pixel speculatively while verifying availability.

R8. Convert a 15/16-bit little-endian colour word `v` using blue `v&31`, green `(v>>5)&31`, red `(v>>10)&31`; expand a five-bit channel `c` to `(c<<3)|(c>>2)`. For 15-bit entries alpha is 255 and bit 15 is ignored. For true-colour 16-bit samples alpha is 255 both when attribute count is zero and when it is one, regardless of bit 15. For 16-bit **map entries**, alpha is 255 when attribute count is zero; when count is one alpha is 255 if bit 15 is set and 0 otherwise. For 24-bit entries bytes are B,G,R and alpha 255. For 32-bit entries bytes are B,G,R,A and alpha is A only when attribute count is eight; otherwise alpha 255. For greyscale depth 8, return `[Y,Y,Y,255]`; for depth 16, return `[Y,Y,Y,A]` when attribute count is eight, otherwise `[Y,Y,Y,255]`. An indexed sample reads an 8- or 16-bit index; require `first<=index<first+length` or return `ColorIndexOutOfRange` at that pixel, and convert the corresponding map entry using the same colour and alpha rules. No premultiplication, colour-profile transform, gamma correction, rescale or use of TGA 2.0 alpha metadata occurs. In particular pre-2.0 alpha is **not** automatically discarded: the attribute count is authoritative even without a footer.

R9. Input sample number `k` has logical coordinates `x=k%width`, `y=k/width`. Write it at output `(X,Y)`, where `X=width-1-x` if descriptor bit 4 is set, else `x`, and `Y=y` if descriptor bit 5 is set, else `height-1-y`. Write four bytes at `4*(Y*width+X)`. This flips each axis independently; x/y-origin numeric fields do not affect the flip. Each pixel is written once; no orientation rewrite after decoding.

R10. For raw types, read exactly `N` samples of `sample_bytes` bytes, checking availability **before** reading each sample and returning `TruncatedPixels` if any are missing. For an available indexed sample, check its index and return `ColorIndexOutOfRange` immediately, before inspecting later pixels or trailing bytes. `N` cannot be zero after R2.

R11. For RLE types, set `produced=0` and use one continuous packet stream across scanlines. While `produced<N`, require one control byte or return `RleTruncated`. Let `count=(control&0x7f)+1` (1..128). If `count>N-produced`, return `RleOverrun` **before reading packet samples**. If control bit 7 is set, require one complete sample or return `RleTruncated`, then decode and write that sample `count` times; otherwise require `count*sample_bytes` bytes or return `RleTruncated`, then decode and write those samples in order. For indexed packets, detect the first out-of-range index in output order and return `ColorIndexOutOfRange`; all packet bytes are checked for availability before decoding its first sample. Advance the input cursor by the packet's full encoded length. A packet can cross a scanline, but cannot cross the end of the image. On the Nth output pixel, stop parsing packets.

R12. After exactly `N` pixels, require the input cursor to equal the input end, **or** permit a suffix of at least 26 bytes whose final 18 bytes equal the exact ASCII signature `TRUEVISION-XFILE.\0` (bytes `54525545564953494f4e2d5846494c452e00`); otherwise return `TrailingBytes`. In the permitted case the last 26 bytes are the TGA 2.0 footer and all bytes before it in the suffix are opaque extension/developer/padding data. Ignore both four-byte footer offsets, extension fields, developer directory, metadata alpha type, and all opaque bytes, without dereferencing offsets or requiring them to be consistent. A complete footer is recognised only **after** pixel data, never used to recover a truncated sample. A lone signature without its preceding eight bytes and arbitrary padding without a footer are rejected. This recognition is structural rather than authentication of the extension area.

R13. The total reference model `M(b)` follows the R1–R12 checks in order, returns immediately on the first failure, and returns exactly one `Ok(width,height,rgba)` only after the suffix test. Its state is `(cursor,produced,rgba)`; header/map checks do not allocate the output until R6 succeeds, and each pixel write uses R8–R9. Its loop variant `N-produced` strictly decreases after each raw sample or each RLE packet. Every read is guarded by a preceding available-length check. For indexed RLE, packet completeness and packet overrun precede index validity, even if the first sample is available and invalid. The input cursor never exceeds `|b|`.

R14. The error precedence is **total operational precedence**, not a sorting of discovered defects: `FileTooLarge`, `TruncatedHeader`, `UnsupportedImageType`, `InvalidColorMapFlag`, `InvalidDimensions`, `UnsupportedInterleave`, `UnsupportedPixelDepth`, `InvalidColorMap`, `ColorMapRange`, `InvalidAttributeBits`, `OutputTooLarge`, `TruncatedImageId`, `TruncatedColorMap`, then the first pixel/packet failure in stream order (`TruncatedPixels` for raw; `RleTruncated` or `RleOverrun` for RLE; `ColorIndexOutOfRange` at the first invalid indexed sample), then `TrailingBytes`. Within an RLE packet, the exact checks are control presence, overrun, whole-packet data presence, then samples' index bounds in sequence. Never inspect a later packet after an earlier error. On error no partial output is returned.

R15. The closed, case-sensitive error set is exactly `FileTooLarge`, `TruncatedHeader`, `UnsupportedImageType`, `InvalidColorMapFlag`, `InvalidDimensions`, `UnsupportedInterleave`, `UnsupportedPixelDepth`, `InvalidColorMap`, `ColorMapRange`, `InvalidAttributeBits`, `OutputTooLarge`, `TruncatedImageId`, `TruncatedColorMap`, `TruncatedPixels`, `RleTruncated`, `RleOverrun`, `ColorIndexOutOfRange`, `TrailingBytes`. There is no `BadMagic`: TGA has no mandatory leading magic. Neither absent alpha nor out-of-range footer offsets create an error.

R16. `VECTORS.json` is a JSON array of exactly `{name,input_hex,expected}`, optionally adding `input_repeat`. `input_hex` is contiguous lowercase hexadecimal; `input_repeat` is a positive integer (default one) that repeats the **entire** decoded hex sequence before invoking `decode`. A success is `{width: integer,height: integer,rgba_runs: [{count: positive integer,hex: eight lowercase hex digits},...]}` where runs are maximal, in top-first row-major pixel order, and counts sum to `width*height`. An error is exactly `{error: name}`. No operation field is needed: every fixture invokes `decode`. Large compact vectors use the repeat field; an oracle need not expand them when an R1 length lemma settles the result. Fixture syntax is not input syntax.

R17. Safety is conditional only on successful allocation and an ordinary operating-system stack: the core never panics, indexes out of bounds, overflows a target integer, or performs unchecked narrowing for any representable input length. Allocator exhaustion is not a TGA error and no core operation performs I/O. Check the `MAX_INPUT` limit before any input-dependent allocation. Provenance means only the caller-owned immutable byte slice; there are no separately passed entry records.
