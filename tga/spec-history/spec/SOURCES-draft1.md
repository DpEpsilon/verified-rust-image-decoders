# Evidence and deliberate boundaries

`READ` means the named local file and lines were inspected for this draft; `RECALLED` means background knowledge not verified against a primary source. The baseline is `/home/ws/projects/spec/gdk-pixbuf/gdk-pixbuf/io-tga.c` (769 lines). Its behavior is evidence of a loader, not normative format authority. The ICNS reference documents were also read: `/home/ws/projects/spec/SPEC.md` (R1–R18), `check_vectors.py`, `FREEZE.txt`, `REVIEW.md`, `REVIEW2.md`, and `/home/ws/projects/THEOREMS.md`, `/home/ws/projects/BRIEF.md`. No external TGA specification or CVE advisory was fetched; unknown producer compatibility is not asserted.

| Draft requirement | Evidence and chosen deviation |
| --- | --- |
| R1 header field positions, little-endian 16-bit dimensions/fields, six image types | **READ** `io-tga.c:53–63,73–90,257–281,564–624`. The 18-byte layout and type values follow that baseline. 64 MiB input bound, exact names and precedence are **DECISION**. |
| R2 descriptor origin and interleave | **READ** `io-tga.c:44–51,192–205,605–617`. The baseline rejects nonzero high two bits. Dimension cap 8,192 and ordered error checks are **DECISION**. |
| R3 image depths | **READ** `io-tga.c:257–281`: indexed 8, true-colour 16/24/32, grey 8/16. True-colour **15** and indexed **16** are **DECISION** extensions; the baseline rejects these image depths. |
| R4 map presence and entries | **READ** `io-tga.c:341–343,477–538`. The baseline requires a map for indexed images but allocates a map for all types, sets entries by their zero-based enumeration, and retrieves an index from that zero-based table (`:154–175,497–524`); it does not apply `cmap_start` to lookup. This spec requires exact coherence for non-indexed images, honors `first`, checks the 65,536-entry index range, and rejects out-of-range indices instead of returning transparent black (`:154–164`): **DECISION**. |
| R5/R8 alpha and 5:5:5 conversion | **READ** `io-tga.c:283–327,350–352,495–514`. True-colour 16 in the baseline always sets alpha 255 and its 16-bit extraction (`:299–306`) does not inspect descriptor attribute count. Its 32-bit true-colour and 16-bit grey paths copy their alpha bytes regardless of descriptor (`:310–326`). Its map 15/16 branch (`:499–506`) neither expands five-bit channels to full 0..255 nor checks bit 15; its map 32 path copies alpha (`:507–514`). This draft defines bit-exact 5-bit expansion, descriptor-governed alpha, and byte-order/channel-order consistently: **DECISION**. TGA 2.0 attribute type is deliberately not authoritative. |
| R6 input/output allocation bounds | **READ** `io-tga.c:334–375` allocates a pixbuf after header checks without this spec's explicit 64 MiB cap. **DECISION**: dimension and 64 MiB output caps; motivation is bounded allocation, not a claim that a particular CVE occurs in this file revision. |
| R7 ID and map consumption | **READ** `io-tga.c:550–561` skips ID; `:477–526` loads map. Rejecting a partial ID/map with a distinct named error is **DECISION**, consistent with baseline stop-load incomplete-image error (`:700–714`). |
| R9 orientation | **READ** `io-tga.c:192–205`: bits 4/5 independently reverse x/y. Output always top-left row-major is **DECISION** for the pure API. |
| R10/R11 RLE packets, scanline crossing | **READ** `io-tga.c:378–410,412–475`: control high bit selects repeat; low seven bits plus one gives count; `tga_write_pixel` wraps x across rows (`:206–211`). This spec rejects overshoot before inspecting packet data, requires the full packet before decoding its first sample, and returns exact truncation/overshoot errors. Baseline clamps runs to pixels remaining (`:439,453`): **DECISION**. |
| R12 suffix and 2.0 footer | **READ** `io-tga.c:21–27,92–104` describes optional footer and its signature; `:183–190,407–409,470–474` skips remaining bytes after image completion. This draft rejects arbitrary trailing bytes yet accepts a 26-byte footer with any intervening opaque extension/developer bytes; ignores offset validity: **DECISION**. This checks the signature, not whether a suffix is a semantically correct 2.0 extension. |
| R13–R17 reference model, exact error order, fixture schema, ownership and conditional safety | **DECISION**, patterned on **READ** `/home/ws/projects/spec/SPEC.md:5–9,57–63` and `/home/ws/projects/THEOREMS.md:5–17,19–39`. The ICNS freeze includes two SHA-256 hashes (`/home/ws/projects/spec/FREEZE.txt:1–4`); this TGA draft has no freeze, versioned digest or implied immutability. |

**RECALLED, not verified here:** CVE-2015-7673 is reported as part of gdk-pixbuf TGA's vulnerability history. We did not read its advisory, determine affected revisions, or attribute a specific vulnerability to a line in this checkout. It motivates explicit size and packet bounds only. No claim about what TGA producers write or the normative TGA 2.0 alpha-type semantics rests on that recollection.

The fixtures were built from hand-selected headers, samples, packets and expected RGBA runs in a separate generator; `check_vectors.py` independently parses the fixture bytes and computes outcomes. Neither runs nor imports gdk-pixbuf. The two 64 MiB input-boundary fixtures use `input_repeat` and one is settled by an input-length lemma without expansion; two 64 MiB **output** fixtures have ordinary compressed inputs and require actual complete decode by the oracle. The generator is a scratchpad construction aid, not a frozen specification file.
